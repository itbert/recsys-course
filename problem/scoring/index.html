Скоринг, ранжирование и политика

Мы описали вход рекомендательного запроса и природу обратной связи. Теперь нужно превратить доступную информацию в решение. Для этого полезно различать три уровня: численную оценку объекта, построение выдачи и правило, по которому система выбирает действие.

Численная оценка объекта​

Пусть sθ(x,i)s_\theta(x,i)sθ​(x,i) — скоринг, то есть вещественная оценка объекта iii в ситуации xxx. Через θ\thetaθ обозначим параметры, если они есть. Более высокая оценка означает более высокий приоритет по выбранному правилу.

Скорингом могут служить число прошлых дочитываний, сходство представлений, прогноз рейтинга, логит классификатора или ожидаемая величина результата. Само слово «оценка» не делает число вероятностью.

Например, для прогноза клика можно определить

p^θ(x,i)∈[0,1].\widehat p_\theta(x,i)\in[0,1].p​θ​(x,i)∈[0,1].

Если использовать sθ=p^θs_\theta=\widehat p_\thetasθ​=p​θ​, задача скоринга связана с вероятностью клика. Но оценка 12 в счётчике прошлых дочитываний означает двенадцать событий, а не вероятность 12. Значения из разных моделей нельзя складывать или сравнивать без понимания их смысла и масштаба.

В обычном supervised learning параметры подбирают через эмпирическую функцию потерь:

L(θ)=1n∑j=1nℓ(sθ(xj,ij),yj).\mathcal{L}(\theta)=\frac{1}{n}\sum_{j=1}^{n} \ell\bigl(s_\theta(x_j,i_j),y_j\bigr).L(θ)=n1​j=1∑n​ℓ(sθ​(xj​,ij​),yj​).

Здесь nnn — число обучающих наблюдений, yjy_jyj​ — их метки, ℓ\ellℓ — выбранная потеря. Это знакомая ML-постановка. Она ещё не определяет, какие объекты допустимы, каким будет список и какую пользовательскую цель оптимизирует вся система.

От оценок к top-K​

Простейшее решение — оценить все допустимые объекты и выбрать первые KKK по убыванию оценки:

L=TopK⁡i∈A(x)sθ(x,i).L=\operatorname{TopK}_{i\in A(x)} s_\theta(x,i).L=TopKi∈A(x)​sθ​(x,i).

Будем понимать этот оператор как упорядоченный список без повторов. Если объектов меньше KKK, возвращаем все доступные. Для равных оценок нужен воспроизводимый способ разрешения ничьей: например, порядок идентификаторов.

В полной сортировке nnn объектов требуется обычно O(nlog⁡n)O(n\log n)O(nlogn) сравнений. Специальные алгоритмы выбора top-K могут обойтись без сортировки всего набора; к ним вернёмся при обсуждении эффективного retrieval. Пока важнее понять, какую цель решает выбор по отдельным оценкам.

Когда выбор top-K действительно оптимален​

Предположим, каждому допустимому объекту сопоставлена фиксированная ценность viv_ivi​. Ценность набора складывается из ценностей его элементов:

V(S)=∑i∈Svi.V(S)=\sum_{i\in S}v_i.V(S)=i∈S∑​vi​.

Объекты не меняют ценности друг друга, позиция в списке не влияет на результат, дополнительных ограничений нет. Требуется выбрать ровно KKK разных объектов, причём доступных объектов не меньше KKK.

Теорема · Оптимальность top-K для аддитивной цели#

При указанных условиях набор из KKK наибольших значений viv_ivi​ максимизирует V(S)V(S)V(S) среди всех наборов размера KKK.

Доказательство

Рассмотрим набор SSS, в котором есть объект bbb, но нет объекта aaa с va>vbv_a>v_bva​>vb​. Заменим bbb на aaa. Число объектов не изменится, допустимость сохранится, а сумма возрастёт на va−vb>0v_a-v_b>0va​−vb​>0. Значит, набор с такой парой не может быть оптимальным. Повторяя обмены, получим набор наибольших значений. При равных значениях может существовать несколько оптимальных наборов.

□

Обратите внимание на границы утверждения. Оно доказывает оптимальность состава набора для указанной суммы. При отсутствии позиционных эффектов порядок внутри набора сам по себе не меняет значение суммы. Также доказательство использует заданные viv_ivi​: если модель ошиблась в оценках, оптимальность по её прогнозам не гарантирует оптимальности по неизвестным истинным значениям.

Если разрешено выбрать до KKK объектов и некоторые viv_ivi​ отрицательны, заполнять все позиции уже не обязательно. Это другая формулировка ограничения.

Почему объекты нельзя всегда оценивать независимо​

Возьмём четыре статьи с условными ценностями:

СтатьяABCD
viv_ivi​0,080,400,300,18

По отдельным значениям top-2 — B и C, сумма равна 0,70. Допустим, B и C — почти одинаковые разборы одной темы. Введём явное предпочтение разнообразию: вычитаем 0,25, если пара состоит из двух материалов одной темы.

Тогда для B и C получим 0,40+0,30−0,25=0,450{,}40+0{,}30-0{,}25=0{,}450,40+0,30−0,25=0,45, а для разных по теме B и D — 0,40+0,18=0,580{,}40+0{,}18=0{,}580,40+0,18=0,58. Выбор по отдельным оценкам перестал давать лучшее значение новой цели.

Здесь коэффициент 0,25 назначен нами как часть учебной целевой функции. Он не является измеренным эффектом повторения темы. Пример показывает, как изменение определения ценности меняет задачу выбора.

Определение · Выдача как совместное действие#

Упорядоченный список рекомендованных объектов называют выдачей, или slate. Если результат зависит от сочетания, порядка или взаимодействия объектов, естественно задавать ценность как V(x,L)V(x,L)V(x,L) для всего списка.

Сложность slate-постановок существенна и для последовательного принятия решений; пример такого исследования — работа о SlateQ. Её методы будем разбирать после основ RL.

Что такое политика​

Политика задаёт правило выбора выдачи по доступной ситуации. Детерминированная политика всегда возвращает один и тот же результат при одинаковом входе. В частности, это может быть сортировка по скорингу с фиксированными фильтрами и разрешением ничьих.

Случайная политика задаёт распределение

π(L∣x)≥0,∑L∈S(x)π(L∣x)=1,\pi(L\mid x)\ge0,\qquad \sum_{L\in\mathcal{S}(x)}\pi(L\mid x)=1,π(L∣x)≥0,L∈S(x)∑​π(L∣x)=1,

где S(x)\mathcal{S}(x)S(x) — множество допустимых списков. Значение π(L∣x)\pi(L\mid x)π(L∣x) — вероятность выбрать конкретный список в ситуации xxx.

Например, политика может с вероятностью 0,7 выдать список (A, B), а с вероятностью 0,3 — (B, C), если оба допустимы. Это распределение решений системы, а не вероятности пользовательского клика. Случайность пригодится для исследования предпочтений и экспериментов; её смысл рассмотрим в частях о бандитах и оценке политик.

Проверьте понимание​

Упражнение · Преобразование скоринга#

Оценки трёх статей равны 2, 1 и −1. Изменится ли их порядок после применения строго возрастающей сигмоиды? Станут ли преобразованные числа автоматически корректными вероятностями клика?

Разбор

Порядок сохранится, потому что сигмоида строго возрастает. Но диапазона от 0 до 1 недостаточно, чтобы объявить числа корректными вероятностями. Нужны соответствующая модель события, обучение и проверка калибровки.

Упражнение · Граница доказательства#

Есть три допустимых объекта с ценностями 0,5, 0,3 и −0,2. Что выбрать при требовании ровно три объекта и что — при разрешении до трёх? Считайте цель аддитивной и допускайте пустую выдачу.

Разбор

При требовании ровно три придётся выбрать все: значение 0,6. При ограничении «до трёх» лучше взять только первые два: значение 0,8. Формулировка ограничения меняет оптимальное решение.

Что запомнить​

Скоринг выдаёт числа, ранжирование строит порядок, политика выбирает действие. Связь между ними задают цель и ограничения. Оптимальность простого top-K требует конкретных условий; в следующей главе посмотрим, как выбор целевого события меняет даже такой простой список.
