Контракт офлайн-оценки

Запрос задаёт область допустимых решений​

Пусть q=(u,t,x)q=(u,t,x)q=(u,t,x) содержит пользователя, время и контекст. Каталог с учётом истории даёт множество допустимых объектов Aq\mathcal A_qAq​. Модель получает информацию, доступную в ttt, и возвращает вероятность, числовой рейтинг, порядок кандидатов или список Sq=(i1,…,ik)S_q=(i_1,\ldots,i_k)Sq​=(i1​,…,ik​). До расчёта качества фиксируются все входы определения.

Определение · Контракт оценки#

Контракт задаёт входную когорту запросов, единицу усреднения, Aq\mathcal A_qAq​, способ формирования оцениваемой области Uq⊆Aq\mathcal U_q\subseteq\mathcal A_qUq​⊆Aq​, вид метки и её наблюдаемость, глубину выдачи, правила совпадений и пропусков, момент обучения, режим обновления истории и время снимка для меток.

Единица оценки рейтинга — наблюдаемая пара запроса и объекта. В оценке ranking метрика сначала вычисляется для списка одного запроса. При оценке slate совместный исход целого списка может измеряться непосредственно на запросе. Одно и то же событие нельзя без определения цели копировать на каждую позицию и затем интерпретировать как сумму индивидуальных вкладов.

Три варианта разметки​

Полностью размеченная конечная область даёт gq(i)g_q(i)gq​(i) для каждого i∈Uqi\in\mathcal U_qi∈Uq​. Нулевой балл тогда означает отрицательную метку в этой области. В синтетике так можно задать весь доступный каталог. Ручная разметка обычно покрывает более узкую область, поэтому её границы нужно указать.

В журнале показов исход наблюдается для показанного iii, при условии созревания и покрытия из части 6. Метрика на таких парах описывает эти показы. Если сравниваются два скоровых алгоритма на одинаковых показанных объектов, получаем условное сравнение внутри старого распределения экспозиций.

В benchmark по отложенным взаимодействиям часто известен только набор положительных примеров PqP_qPq​. Если все остальные объекты получают нулевой балл, результат измеряет способность вернуть известные отложенные взаимодействия при данной конвенции. Например, Recall с PqP_qPq​ в знаменателе измеряет возвращённую долю PqP_qPq​. Реальную суммарную долю релевантных объектов из этого числа восстановить без дополнительных предпосылок нельзя. Сравнение с другими работами требует одинакового горизонта и способа отбора этих позитивов.

Теорема · Неидентифицируемость качества нового показа#

Пусть для контекста qqq историческая политика всегда показывает A и никогда B. Только из наблюдаемого исхода A невозможно определить средний исход политики, которая всегда показывает B, если связь между исходами A и B не задана.

Доказательство

Рассмотрим два мира. В обоих исход A всегда равен 1. В первом исход B равен 0, во втором равен 1. Распределение наблюдаемых журналов совпадает, а ожидаемый исход новой политики различается. Функция одного и того же журнала не может идентифицировать обе величины.

□

Это частный пример отсутствия поддержки. Проблема сохраняется после корректной дедупликации, хорошего временного разбиения и долгого наблюдения той же детерминированной политики. Оценка контрфактических исходов будет введена в части 20.

Проверяемая таблица​

Минимальная запись содержит ID запроса, момент решения, версию модели, список допустимых кандидатов или его восстанавливаемую ссылку, выданный порядок, метки и маски наблюдения, временное окно исхода и срезы. Две модели сравниваются на парных запросах. Если модель пропустила запрос, контракт задаёт, считается ли это пустой выдачей, отказом или отдельной категорией. Удаление всех отказов одной модели меняет её целевую популяцию.

Холодный объект, доступный в момент решения, остаётся в области. Fallback оценивается как часть системы. При равных score нужен устойчивый ключ, если продакшен выдаёт детерминированный список. Для модели со случайным порядком воспроизводится её распределение, а не один удачный seed.

Упражнение · Неполная разметка

Из 20 допустимых объектов показаны два. У первого известен исход 1, у второго 0. Модель ставит первым один из остальных 18. Известен ли её Hit@1?

Разбор

Для полной скрытой релевантности ответ неизвестен. Для контракта «найти единственный известный отложенный позитив» Hit@1 равен 0. Сравнение на двух показанных объектах отвечает на третий вопрос, поскольку ранжируется другая область.

Упражнение · Сколько запросов считать

Из 100 запросов одна модель выдала 90 списков, другая 100. Какие две характеристики надо публиковать при использовании условной NDCG на успешных запросах?

Разбор

Отдельно публикуются частота обслуживания и условная NDCG со знаменателем. Для парного сравнения на всех 100 запросах нужно заранее определить полезность отказа или явно оценивать иной объект. Сравнивать 90 и 100 условных значений как одну популяцию нельзя.
