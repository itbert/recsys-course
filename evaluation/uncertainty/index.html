Парное сравнение и неопределённость

Вариация запроса и вариация модели​

Если тест задан полностью и заморожен, среднее на нём вычисляется точно. Интервал нужен для вопроса о повторении эксперимента, например о новых пользователях в той же среде. Другие источники вариации — обучение при разных seed, повторная выборка кандидатов и смена календарного периода. Для каждого нужна соответствующая схема повторения. Повторная выборка тестовых пользователей при фиксированных моделях не включает неопределённость обучения.

Для моделей A и B на одних запросах обозначим dj=mBj−mAjd_j=m_{Bj}-m_{Aj}dj​=mBj​−mAj​. После выбора весов работаем с разностями. При оценке потерь решение о направлении принимается отдельно.

Лемма · Ковариация в парном сравнении#

Для случайных результатов на одном запросе Var⁡(B−A)=Var⁡(A)+Var⁡(B)−2Cov⁡(A,B)\operatorname{Var}(B-A)=\operatorname{Var}(A)+\operatorname{Var}(B)-2\operatorname{Cov}(A,B)Var(B−A)=Var(A)+Var(B)−2Cov(A,B), если вторые моменты конечны.

Доказательство

Раскрываем квадрат центрированной разности и берём ожидание. Если обе модели, например, обычно хорошо решают одни и те же запросы, ковариация может быть положительной. Два независимых пересэмплирования уничтожили бы эту зависимость и изменили оценку дисперсии.

□

Наблюдения одного аккаунта обычно имеют общую историю и скрытые признаки. Если каждую строку считать независимой, перекрытие контекстов может привести к слишком узким интервалам. В предельном примере каждый из 100 пользователей порождает десять одинаковых по разности запросов. При равных размерах и независимых пользователях эффективное число независимых значений равно 100, хотя строк 1000.

Кластерный bootstrap​

Пусть независимы и одинаково распределены пользовательские кластеры, каждый содержит все оценённые запросы аккаунта. Считаем суммы разностей sus_usu​ и объёмы nun_unu​. Пользователи с нулём оцениваемых запросов не входят в выбранную условную популяцию. Далее строим распределение повторных оценок.

  1. Присваиваем кластерам равные шансы быть отобранными.
  2. Выбираем с возвращением UUU кластеров целиком и переносим парные результаты обеих моделей вместе.
  3. Для веса запросов пересчитываем отношение ∑su/∑nu\sum s_u/\sum n_u∑su​/∑nu​, для веса пользователей — среднее su/nus_u/n_usu​/nu​.
  4. Повторяем и берём эмпирические квантили 0,025 и 0,975 для процентильного 95% интервала.

Если кластер попал дважды, в расчёт входят обе копии. При весе запросов и одинаково распределённых кластерах целевой параметр — E[su]/E[nu]\E[s_u]/\E[n_u]E[su​]/E[nu​], при весе пользователей — E[su/nu]\E[s_u/n_u]E[su​/nu​]. Две оценки используют одни данные, но отвечают на разные вопросы. При конечных вторых моментах и положительном среднем размере кластера средние числителя и знаменателя стабилизируются с ростом числа независимых кластеров. Bootstrap приближает их совместную вариацию. Теоретические условия зависят от схемы зависимости и статистики. Efron, 1979, Field и Welsh, 2007

comparison.py
"""Парные разности и повторная выборка целых кластеров."""
from collections import defaultdict
import math
import random


def aggregates(records):
    """records — пары (cluster_id, delta) для одних и тех же запросов моделей A и B."""
    groups = defaultdict(list)
    for cluster, delta in records:
        if not math.isfinite(delta):
            raise ValueError("Сравнивайте конечные значения на общей области")
        groups[cluster].append(delta)
    if not groups:
        raise ValueError("Пустая когорта")
    return [(math.fsum(groups[c]), len(groups[c])) for c in sorted(groups)]


def summarize(groups, weighting):
    if weighting == "request":
        return math.fsum(s for s, _ in groups) / sum(n for _, n in groups)
    if weighting == "user":
        return math.fsum(s / n for s, n in groups) / len(groups)
    raise ValueError("weighting: request или user")


def quantile(sorted_values, q):
    if not sorted_values or not 0 <= q <= 1:
        raise ValueError("Нужен непустой отсортированный массив и 0 <= q <= 1")
    index = (len(sorted_values) - 1) * q
    lo, hi = math.floor(index), math.ceil(index)
    return sorted_values[lo] + (index - lo) * (sorted_values[hi] - sorted_values[lo])


def paired_bootstrap(records, weighting="request", draws=2000, seed=7, level=0.95):
    groups = aggregates(records)
    if len(groups) < 2 or draws < 2 or not 0 < level < 1:
        raise ValueError("Нужны несколько кластеров, повторов и уровень между 0 и 1")
    rng = random.Random(seed)
    repetitions = sorted(summarize(rng.choices(groups, k=len(groups)), weighting)
                         for _ in range(draws))
    tail = (1 - level) / 2
    return {
        "estimate": summarize(groups, weighting),
        "interval": [quantile(repetitions, tail), quantile(repetitions, 1 - tail)],
        "clusters": len(groups),
        "requests": sum(n for _, n in groups),
    }

Сводка (su,nu)(s_u,n_u)(su​,nu​) достаточна для выбранных аддитивных разностей. Для coverage нужно пересчитывать объединение списков внутри каждого повтора, для RMSE — считать разность двух корней из соответствующих средних. Bootstrap разности построчных абсолютных ошибок не оценивает разность RMSE.

Границы вывода​

Процентильный интервал — приближённая частотная процедура. Он не гарантирует заданное покрытие на малых или сильно неравных кластерах. Число повторов уменьшает ошибку вычисления квантилей, но не увеличивает число наблюдавшихся пользователей. Если один календарный шок затронул многих, независимость пользователей может нарушиться. Для стационарных зависимых рядов существуют схемы повторной выборки временных блоков. Выбор длины блока и вопрос обобщения требуют анализа зависимости. Künsch, 1989

При тестировании многих метрик, глубин и срезов вероятность увидеть случайный убедительный результат растёт. До финальной проверки фиксируют основную метрику и правило выбора, а остальные показатели называют диагностическими. Для семейства формальных подтверждений нужен совместный контроль ошибок. Для вывода о практической ценности сравнивайте интервал с заранее заданным минимальным эффектом. При наличии только одного временного отрезка интервал условен на этом режиме.
