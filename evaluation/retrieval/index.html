Оценка retrieval и ranking в каскаде

Три вычисления с разными знаменателями​

Зафиксируем допустимую область Uq\mathcal U_qUq​, релевантное множество PqP_qPq​, shortlist Cq⊆Uq\mathcal C_q\subseteq\mathcal U_qCq​⊆Uq​ размера не больше LLL и итоговый список из Cq\mathcal C_qCq​ длины не больше KKK. При Pq≠∅P_q\ne\varnothingPq​=∅ считаем candidate Recall@LLL.

Rqret=∣Pq∩Cq∣∣Pq∣.R^{\mathrm{ret}}_q=\frac{|P_q\cap\mathcal C_q|}{|P_q|}.Rqret​=∣Pq​∣∣Pq​∩Cq​∣​.

Ranking можно диагностировать условно на Cq\mathcal C_qCq​. Тогда Recall делит на число позитивов внутри shortlist, а NDCG нормирует на IDCG этого же shortlist. Так можно сравнить два ranker при одном upstream, но число запросов с определённой условной NDCG зависит от retrieval. При сравнении двух разных генераторов нужно отдельно показывать, для скольких запросов условная метрика определена.

End-to-end метрика использует исходную область и итоговый список. Она включает потери от обоих этапов. Если позитив выпал до ranker, он по-прежнему учитывается в полном знаменателе.

Теорема · Ограничение shortlist#

При неизменном shortlist итоговая Recall@K не выше candidate Recall@LLL. При положительном IDCG по полной области итоговая NDCG@K не выше отношения IDCGK(Cq)/IDCGK(Uq)\mathrm{IDCG}_K(\mathcal C_q)/\mathrm{IDCG}_K(\mathcal U_q)IDCGK​(Cq​)/IDCGK​(Uq​).

Доказательство

Релевантные объекты в итоге принадлежат Pq∩CqP_q\cap\mathcal C_qPq​∩Cq​, откуда следует первое неравенство. Во втором случае DCG любой перестановки и подвыборки shortlist не больше его идеальной DCG по доказанному ранее правилу обмена. Деление на общий положительный знаменатель сохраняет порядок.

□

Когда IDCGK(Cq)>0\mathrm{IDCG}_K(\mathcal C_q)>0IDCGK​(Cq​)>0, end-to-end NDCG раскладывается в произведение условной NDCG и oracle-отношения выше. При пустом по позитивам shortlist итоговая NDCG равна нулю для запроса с положительным полным IDCG, а условная не определена. Среднее произведений нельзя в общем случае заменять произведением средних.

Пример одного запроса​

Пусть положительные gains каталога равны 7, 3 и 1. Shortlist сохранил только объект с gain 1, остальные элементы имеют gain 0. При K=2K=2K=2 лучшая условная NDCG равна 1, а лучшая сквозная равна 1/(7+3/log⁡23)≈0,1121/(7+3/\log_2 3)\approx0{,}1121/(7+3/log2​3)≈0,112. Полнота retrieval равна 1/31/31/3. Пропуск самой ценной степени объясняет, почему отношение IDCG здесь заметно меньше полноты.

В эксперименте shortlist модели A содержит пять объектов. Ранжировщик B переупорядочивает только эту пятёрку. Oracle сортирует её по известным оценочным меткам исключительно для диагностики. Он недоступен системе в момент запроса. Triple «candidate Recall, сквозная NDCG, oracle NDCG» позволяет выяснить, где в этом каскаде находится резерв.

Оценка приближённого поиска​

Если этап использует ANN, полезно сравнить его с точным top-LLL того же скоринга на тех же допустимых ID. Для эталона из LLL уникальных объектов считаем ∣CANN∩Cexact∣/L|\mathcal C^{\mathrm{ANN}}\cap\mathcal C^{\mathrm{exact}}|/L∣CANN∩Cexact∣/L. Это техническая полнота приближённого поиска. Она может быть равна 1, даже если точная модель не вернула ни одного размеченного позитива. Измерения задержки и нагрузки относятся к этому же генератору и версии индекса, а не заменяют метрики релевантности. Сравнение индексов будет подробнее в части 14.

Упражнение · Смена виновника

Общий Recall@10 системы равен 0,2, полнота shortlist из 100 кандидатов равна 0,25. Может ли замена ranker при прежнем shortlist повысить Recall@10 до 0,4?

Разбор

Нет. Для каждого запроса с позитивами полнота результата ограничена полнотой его shortlist, поэтому то же выполняется для среднего на общей когорте. Верхняя оценка 0,25 сама может быть недостижима, если в shortlist больше десяти позитивов.

Упражнение · Идеальный ранг в неполной области

В полном каталоге четыре позитива. В shortlist попали два, оба помещены в top-5. Найдите условную и сквозную Recall.

Разбор

Условная Recall равна 2/2=12/2=12/2=1, сквозная равна 2/4=0,52/4=0{,}52/4=0,5. Область в знаменателе различается даже при одном и том же списке.
