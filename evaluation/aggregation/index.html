Усреднение, веса и диагностические срезы

Один результат, несколько популяций​

Пусть mujm_{uj}muj​ — метрика запроса jjj пользователя uuu и nun_unu​ — число его запросов, для которых метрика определена. Среднее по запросам и среднее по пользователям имеют вид

Mreq=∑u∑jmuj∑unu,Muser=1U∑u1nu∑jmuj.M_{\rm req}=\frac{\sum_u\sum_j m_{uj}}{\sum_u n_u},\qquad M_{\rm user}=\frac1U\sum_u\frac1{n_u}\sum_jm_{uj}.Mreq​=∑u​nu​∑u​∑j​muj​​,Muser​=U1​u∑​nu​1​j∑​muj​.

В первой цели активный аккаунт влияет пропорционально числу запросов. Во второй каждый аккаунт с nu>0n_u>0nu​>0 вносит одинаковый вес. При одном новом аккаунте как единице обобщения MuserM_{\rm user}Muser​ естественно оценивает среднее по случайному аккаунту, а MreqM_{\rm req}Mreq​ соответствует выбору случайного запроса из совокупности. Нужный критерий задаётся способом использования, например долей удачных запросов или средним качеством опыта на аккаунт.

Обозначим mˉu=nu−1∑jmuj\bar m_u=n_u^{-1}\sum_jm_{uj}mˉu​=nu−1​∑j​muj​, а ожидание и ковариацию возьмём по равномерной конечной совокупности аккаунтов. Тогда Mreq−Muser=Cov⁡(nu,mˉu)/E[nu]M_{\rm req}-M_{\rm user}=\operatorname{Cov}(n_u,\bar m_u)/\E[n_u]Mreq​−Muser​=Cov(nu​,mˉu​)/E[nu​].

Доказательство

Mreq=E[numˉu]/E[nu]M_{\rm req}=\E[n_u\bar m_u]/\E[n_u]Mreq​=E[nu​mˉu​]/E[nu​] и Muser=E[mˉu]M_{\rm user}=\E[\bar m_u]Muser​=E[mˉu​]. Раскрытие ковариации даёт разность. При равных объёмах nun_unu​ ковариация равна нулю.

Срезы и состав​

Группы задаются по доступной информации, например регион, объём прошлого, наличие объекта в обучении или период. Для каждой публикуют размер, долю неопределённых запросов, значение основной метрики и, для сравнения, парную разность. Срезы могут пересекаться. Чтобы восстановить полное среднее по группам, нужна непересекающаяся разбивка либо явные веса.

Предположим, у A в лёгком и трудном сегментах метрика 0,9 и 0,4, у B — 0,8 и 0,3. Если у A лёгкий трафик составляет 10%, суммарно получим 0,45. Если у B он составляет 90%, получим 0,75. B выигрывает по наблюдаемому агрегату при другом составе, хотя хуже внутри обоих сегментов. При весах 50/50 значения становятся 0,65 и 0,55. Этот пример применяет стандартизацию из части 4 к метрикам моделей.

При парном оценивании состав совпадает, если обе метрики вычислены для каждого запроса той же когорты. Если модель возвращает пустые списки или у компонента другой набор кандидатов, объявите область применимости среза. Например, «позитив есть в shortlist» зависит от конкретного retrieval. Такой срез удобен для диагностики ranker при одном фиксированном shortlist, но его значения по разным retrieval имеют разные знаменатели.

Перевести разность в понятную единицу​

Улучшение Recall с 0,20 до 0,24 составляет 0,04 абсолютных пункта шкалы, 4 процентных пункта и 20% относительно базы. При нулевой базе относительное изменение не определено. Для метрик, которые нужно минимизировать, направление разности указывают рядом с результатом. Удобно считать B − A и в случае Brier явно указать, что отрицательная разность соответствует меньшей потере.

Упражнение · Вес активного аккаунта

Один пользователь имеет 8 запросов со средним 0,25, второй — два запроса со средним 1. Найдите оба агрегата.

Разбор

По запросам (8⋅0,25+2⋅1)/10=0,4(8\cdot0{,}25+2\cdot1)/10=0{,}4(8⋅0,25+2⋅1)/10=0,4. По пользователям (0,25+1)/2=0,625(0{,}25+1)/2=0{,}625(0,25+1)/2=0,625. Активный пользователь ухудшает первую величину сильнее.

Упражнение · Восстановление общего результата

Два непересекающихся среза содержат 20 и 80 запросов с определённой NDCG. Средние 0,7 и 0,4. Как восстановить среднее по запросам?

Разбор

(20⋅0,7+80⋅0,4)/100=0,46(20\cdot0{,}7+80\cdot0{,}4)/100=0{,}46(20⋅0,7+80⋅0,4)/100=0,46. Среднее двух средних без весов равно 0,55 и присваивает срезам равные веса.
