Градуированная релевантность и NDCG

Балл и вес позиции​

У объекта может быть оценка g(i)∈{0,1,2,3}g(i)\in\{0,1,2,3\}g(i)∈{0,1,2,3}, где больший балл означает большую релевантность по правилам разметки. В этой книге используем неотрицательный gain G(g)=2g−1G(g)=2^g-1G(g)=2g−1 и дисконт wr=1/log⁡2(r+1)w_r=1/\log_2(r+1)wr​=1/log2​(r+1).

После конца списка вклад равен нулю. IDCG — DCG первых KKK объектов при идеальной сортировке всей оцениваемой области по grade. При IDCG =0=0=0 NDCG не определена, в отчёте публикуются число включённых запросов и доля исключений. Условие исключения одинаково для всех моделей.

Линейный gain дал бы отношение 3 к 1, а другой дисконт изменил бы компромисс между ранней и поздней позицией. Для метки «завершено» 0/1 экспоненциальный gain совпадает с исходной меткой. Исходная работа ввела семейство накопленных, дисконтированных и нормированных оценок. При сравнении указывайте выбранную формулу, поскольку функции gain и дисконта различаются по реализациям. Теорема · Идеальная сортировка#

Пусть w1≥⋯≥wK≥0w_1\ge\cdots\ge w_K\ge0w1​≥⋯≥wK​≥0 и все gains неотрицательны. При отсутствии дополнительных ограничений на порядок и состав идеальная DCG достигается сортировкой gains по убыванию.

Доказательство

Если на местах a<ba<ba<b стоят gains Ga<GbG_a<G_bGa​<Gb​, обмен увеличивает сумму на (wa−wb)(Gb−Ga)≥0(w_a-w_b)(G_b-G_a)\ge0(wa​−wb​)(Gb​−Ga​)≥0. Продлим веса нулями после KKK, чтобы включить обмен с объектами за пределами выдачи. Повторяя обмены инверсий, получаем отсортированную последовательность с не меньшей суммой. Поэтому при положительном IDCG значение NDCG лежит в [0,1][0,1][0,1].

□

Если правила запрещают два объекта одной категории, стандартный IDCG может оказаться недостижимым. Тогда можно публиковать отдельно верхнюю границу без ограничений и оптимум допустимой задачи. Выбор знаменателя меняет смысл единицы. В каскаде такое различие возникает между идеальным списком из каталога и идеальным списком из shortlist.

Ручной расчёт и совпавшие score​

В области четыре объекта со степенями (3,1,0,0)(3,1,0,0)(3,1,0,0). При K=3K=3K=3 порядок A с метками (0,1,0,3)(0,1,0,3)(0,1,0,3) даёт DCG 1/log⁡231/\log_2 31/log2​3. Порядок B с метками (3,0,1,0)(3,0,1,0)(3,0,1,0) даёт 7+1/27+1/27+1/2. Общий знаменатель 7+1/log⁡237+1/\log_2 37+1/log2​3. Меняя KKK, можно увидеть, на какой глубине модель возвращает самый ценный объект.

При одинаковом score и разной разметке выбор положения влияет на DCG. Для детерминированной системы сортируем по (−s,i)(-s,i)(−s,i), где iii — ID. Для случайного равномерного разрешения совпадений ожидаемый DCG блока равен среднему gain блока, умноженному на сумму весов его позиций в пределах KKK. Это следует из того, что каждая позиция внутри блока равновероятно получает любой объект. В AP вклад позиции зависит и от числа предыдущих единиц, поэтому для среднего нужна совместная модель порядка.

Код​

ranking.py
"""Оценка одной выдачи на явно заданной таблице релевантности."""
import math


def ranking_metrics(order, grades, k):
    if k < 1 or len(set(order)) != len(order) or any(i not in grades for i in order):
        raise ValueError("Нужны K >= 1, уникальные ID и известные метки всех выданных объектов")
    if any(not math.isfinite(g) or g < 0 for g in grades.values()):
        raise ValueError("Степени релевантности должны быть конечными и неотрицательными")

    observed = [grades[i] for i in order[:k]]
    relevant = sum(g > 0 for g in grades.values())
    positions = [r for r, g in enumerate(observed, start=1) if g > 0]
    hits = len(positions)
    dcg = discounted_gain(observed)
    ideal = discounted_gain(sorted(grades.values(), reverse=True)[:k])
    return {
        "precision": hits / k,
        "recall": hits / relevant if relevant else None,
        "hit": int(hits > 0),
        "rr": 1 / positions[0] if positions else 0.0,
        "ap": (math.fsum(j / r for j, r in enumerate(positions, start=1))
               / min(relevant, k)) if relevant else None,
        "ndcg": dcg / ideal if ideal else None,
    }


def discounted_gain(grades):
    return math.fsum((2**g - 1) / math.log2(r + 1)
                     for r, g in enumerate(grades, start=1))


def ranked_ids(scores):
    if any(not math.isfinite(s) for s in scores.values()):
        raise ValueError("Нужны конечные scores")
    return sorted(scores, key=lambda i: (-scores[i], i))


def catalog_coverage(lists, eligible):
    universe = set(eligible)
    exposed = {item for order in lists for item in order}
    if not universe or not exposed <= universe:
        raise ValueError("Проверьте область каталога")
    return len(exposed) / len(universe)


def diversity(order, distance):
    pairs = [distance(a, b) for j, a in enumerate(order) for b in order[j+1:]]
    return math.fsum(pairs) / len(pairs) if pairs else None


def novelty(order, counts, alpha=1):
    if not order:
        return None
    if alpha <= 0 or not set(order) <= counts.keys() or any(n < 0 for n in counts.values()):
        raise ValueError("Задайте исторические счётчики всех объектов и положительное сглаживание")
    total = sum(counts.values()) + alpha * len(counts)
    return math.fsum(-math.log2((counts[i] + alpha) / total) for i in order) / len(order)

ranking_metrics принимает порядок из уникальных ID и полную разметку заявленной области. Код использует маску положительности g>0g>0g>0 для бинарных метрик. Идеальные gains сортируются отдельно от scores. Время расчёта для NNN меток равно O(Nlog⁡N+K)O(N\log N+K)O(NlogN+K), не считая проверки уникальности входного списка. При больших областях IDCG можно считать по частотам конечной шкалы или через выбор KKK наибольших gains. Метрики покрытия и состава из этого модуля разбираются далее.
