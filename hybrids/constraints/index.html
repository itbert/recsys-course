Предметные знания и допустимые решения

Знания задают область допустимости​

Для курсов известно, какие уроки требуют пререквизитов, какие форматы можно открыть на устройстве и сколько длится эпизод. Такие сведения хранятся отдельно от статистических оценок. Если пользователь выбрал короткий эпизод, ограничение minutes(i)≤B\mathrm{minutes}(i)\le Bminutes(i)≤B можно проверять точно. Если длительность лишь пожелание, её можно использовать в полезности или расстоянии. Подходы с ограничениями и рекомендация по прецеденту используют явные знания о требованиях и свойствах объектов. Felfernig и Burke, 2008.

Определение · Допустимость и полезность#

Пусть Cℓ(i,q)∈{0,1}C_\ell(i,q)\in\{0,1\}Cℓ​(i,q)∈{0,1} — предикаты обязательных условий для запроса qqq. Тогда A(q)={i:∀ℓ, Cℓ(i,q)=1}A(q)=\{i:\forall\ell,\ C_\ell(i,q)=1\}A(q)={i:∀ℓ, Cℓ​(i,q)=1}. Внутри A(q)A(q)A(q) можно ранжировать по полезности U(i,q)=∑jwjuj(i,q)U(i,q)=\sum_j w_j u_j(i,q)U(i,q)=∑j​wj​uj​(i,q), где uju_juj​ сопоставляют допустимым кандидатам оценки по отдельным критериям.

Суммирование предполагает выбранные сопоставимые шкалы и компенсируемость. Плюс по одному критерию может компенсировать минус по другому. Обязательный предикат такой компенсации не допускает. Если неизвестно, выполняется ли обязательное требование, контракт системы должен отдельно определить статус неизвестного. Например, сертификат совместимости нужен для допуска, а пропуск данных о предпочтительном цвете может быть поводом для уточнения.

В case-based рекомендации запрос может иметь вид «похожее на этот курс, но короче». Для числовых атрибутов нормируем расстояния по диапазонам, для категориальных используем совпадение или явно заданное расстояние. Сначала проверяем обязательное условие длительности, затем выбираем наиболее близкое по признакам из допустимых. Если одна рекомендация — это комплект, то допустимость уже проверяется по сочетанию переменных. Например, суммарное время и порядок пререквизитов не сводятся к проверкам отдельных частей. Тогда подходит постановка CSP или целочисленная модель.

Когда результат пуст​

Обозначим через SSS множество обсуждаемых условий, а через D⊆SD\subseteq SD⊆S набор, который можно предложить снять. В коде ищутся минимальные по включению наборы DDD, при которых имеется объект, удовлетворяющий обязательным условиям и всем условиям S∖DS\setminus DS∖D. Такой набор не обязательно имеет наименьшую мощность среди всех вариантов. Снятие условия — предложение пользователю, а не автоматическая смена запроса.

Лемма · Монотонность допустимости#

Если после снятия DDD есть допустимый объект, он остаётся допустим при снятии любого D′⊇DD'\supseteq DD′⊇D.

Доказательство

S∖D′⊆S∖DS\setminus D'\subseteq S\setminus DS∖D′⊆S∖D, поэтому у объекта стало меньше проверяемых условий. Обязательные предикаты в обеих проверках одинаковы.

constraints.py
"""Версии каталога, точные ограничения и ограниченное ранговое слияние."""

from collections import defaultdict
from dataclasses import dataclass


@dataclass(frozen=True)
class Version:
    item: int
    effective: int
    available: int
    description: str
    topic: int
    format: str
    minutes: int
    active: bool = True


def catalog_as_of(versions, time):
    latest, seen_versions = {}, {}
    for entry in versions:
        if entry.effective > time or entry.available > time:
            continue
        key = (entry.effective, entry.available)
        version_key = (entry.item, *key)
        if seen_versions.setdefault(version_key, entry) != entry:
            raise ValueError("conflicting records for a catalog version")
        current = latest.get(entry.item)
        if current is None or key > (current.effective, current.available):
            latest[entry.item] = entry
    return {item: entry for item, entry in latest.items() if entry.active}


def eligible(catalog, time_budget, *, required_format=None, seen=()):
    seen = set(seen)
    return sorted(
        item for item, entry in catalog.items()
        if item not in seen and entry.minutes <= time_budget
        and (required_format is None or entry.format == required_format)
    )


def minimal_relaxations(catalog, required, negotiable):
    """Наборы ключей торгуемых условий, минимальные по включению."""
    violations = {
        frozenset(name for name, test in negotiable.items() if not test(entry))
        for entry in catalog.values() if all(check(entry) for check in required)
    }
    minimal = []
    for removed in sorted(violations, key=lambda names: (len(names), sorted(names))):
        if not any(previous <= removed for previous in minimal):
            minimal.append(removed)
    return minimal


def reciprocal_rank_fusion(rankings, offset=60):
    if offset <= 0:
        raise ValueError("expected a positive offset")
    scores = defaultdict(float)
    for order in rankings:
        for rank, item in enumerate(dict.fromkeys(order), start=1):
            scores[item] += 1 / (offset + rank)
    return dict(scores)

catalog_as_of выбирает доступную версию перед применением статуса активности. eligible проверяет лимит времени, формат и исключение истории для задачи открытия нового объекта. Для объекта, удовлетворяющего обязательным условиям, обозначим через ViV_iVi​ множество нарушенных пожеланий. Он допустим при снятии DDD ровно тогда, когда Vi⊆DV_i\subseteq DVi​⊆D. Следовательно, минимальные наборы DDD — минимальные по включению множества среди ViV_iVi​ объектов. minimal_relaxations строит эти множества, удаляет повторы и проверяет включения от меньших наборов к большим. Оценки предикатов требуют одного обхода каталога. В составной задаче, где полный каталог комплектов перечислить невозможно, вместо этого ищут ослабления вместе с решателем ограничений. Последняя функция модуля используется в главе о слиянии.

Упражнение · Два объяснения пустой области

Один доступный урок имеет аудио и длится 40 минут, второй текстовый и длится 20 минут. Требования — аудио и не более 30 минут. Оба требования обсуждаемые. Найдите минимальные наборы для ослабления.

Разбор

Снятие лимита открывает первый урок, снятие требования аудио — второй. Получаем два минимальных по включению одноэлементных набора. Если формат сделать обязательным, останется предложение изменить только лимит длительности.
