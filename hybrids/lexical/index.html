TF-IDF, BM25 и лексический поиск

Векторная модель​

Пусть NNN — число документов в зафиксированном корпусе, ftdf_{td}ftd​ — число вхождений термина ttt в документ ddd, а dft\mathrm{df}_tdft​ — число документов, в которых он встречается хотя бы раз. Один и тот же термин может дать ftd=20f_{td}=20ftd​=20, прибавив к dft\mathrm{df}_tdft​ ровно единицу. В коде взята сглаженная версия TF-IDF,

atd={(1+log⁡ftd)(1+log⁡N+1dft+1),ftd>0, dft>0,0,иначе.a_{td}= \begin{cases} (1+\log f_{td})\bigl(1+\log\tfrac{N+1}{\mathrm{df}_t+1}\bigr),& f_{td}>0,\ \mathrm{df}_t>0,\\ 0,&\text{иначе}. \end{cases}atd​={(1+logftd​)(1+logdft​+1N+1​),0,​ftd​>0, dft​>0,иначе.​

Отдельный множитель idf\mathrm{idf}idf зависит от корпуса. Вес элемента fff растёт логарифмически. Форму весов нужно фиксировать рядом с результатами, поскольку схемы TF-IDF различаются сглаживанием и нормировкой. Manning, Raghavan и Schütze, гл. 6.

Для ненулевых векторов нормируем vd=ad/∥ad∥2v_d=a_d/\|a_d\|_2vd​=ad​/∥ad​∥2​. Тогда vq⊤vdv_q^\top v_dvq⊤​vd​ — косинус между документом и запросом. У документа только с неизвестными терминами вектор нулевой, поэтому косинус с ним не определён. Интерфейс в коде трактует пустой словарь как отсутствие вклада, а резерв решает, где показывать такие объекты. Контент синонимов или разных языков может иметь нулевое пересечение.

BM25​

Длину документа обозначим через LdL_dLd​, среднюю длину обучающего корпуса — через Lˉ>0\bar L>0Lˉ>0. Для непустого документа и множества различных терминов запроса используем

idft=log⁡ ⁣(1+N−dft+1/2dft+1/2),Kd=k1(1−b+bLd/Lˉ),s(q,d)=∑t∈q∩Vidft(k1+1)ftdftd+Kd,k1>0, b∈[0,1].\begin{aligned} \mathrm{idf}_t&=\log\!\left(1+\frac{N-\mathrm{df}_t+1/2}{\mathrm{df}_t+1/2}\right),\\ K_d&=k_1(1-b+bL_d/\bar L),\\ s(q,d)&=\sum_{t\in q\cap V}\mathrm{idf}_t \frac{(k_1+1)f_{td}}{f_{td}+K_d}, \qquad k_1>0,\ b\in[0,1]. \end{aligned}idft​Kd​s(q,d)​=log(1+dft​+1/2N−dft​+1/2​),=k1​(1−b+bLd​/Lˉ),=t∈q∩V∑​idft​ftd​+Kd​(k1​+1)ftd​​,k1​>0, b∈[0,1].​

Множитель k1+1k_1+1k1​+1 выбран в этой записи явно. Положительная формула для IDF совпадает с вариантом Lucene. В данном коде неизвестные корпусу термины опускаются, запрос не получает вес за повторы, средняя длина считается по всем переданным документам. Robertson и Zaragoza, Lucene BM25Similarity.

Лемма · Насыщение частоты#

При фиксированном Kd>0K_d>0Kd​>0 множитель ψ(f)=(k1+1)f/(f+Kd)\psi(f)=(k_1+1)f/(f+K_d)ψ(f)=(k1​+1)f/(f+Kd​) строго растёт по f≥0f\ge0f≥0 и стремится к k1+1k_1+1k1​+1. При фиксированном f>0f>0f>0 и b>0b>0b>0 он убывает по LdL_dLd​.

Доказательство

ψ′(f)=(k1+1)Kd/(f+Kd)2>0\psi'(f)=(k_1+1)K_d/(f+K_d)^2>0ψ′(f)=(k1​+1)Kd​/(f+Kd​)2>0, а деление числителя и знаменателя на fff даёт предел. При фиксированном fff увеличение LdL_dLd​ увеличивает только знаменатель. В реальном редактировании документа могут измениться обе величины, поэтому частные зависимости следует различать.

Поля и индекс​

Для названия, описания и тегов можно считать отдельные признаки. В одной из записей BM25F для поля hhh с длиной LdhL_{dh}Ldh​, средней длиной Lˉh>0\bar L_h>0Lˉh​>0 и весом whw_hwh​ строится суммарная нормированная частота

Ftd=∑hwhftdh1−bh+bhLdh/Lˉh.F_{td}=\sum_h w_h \frac{f_{tdh}}{1-b_h+b_h L_{dh}/\bar L_h}.Ftd​=h∑​wh​1−bh​+bh​Ldh​/Lˉh​ftdh​​.

Пустое поле даёт нулевой вклад. К FtdF_{td}Ftd​ применяют насыщение с общим k1k_1k1​. Поскольку насыщение нелинейно, сумма отдельных BM25 даёт в общем случае другой результат. Robertson, Zaragoza и Taylor, 2004.

Инвертированный индекс хранит список документов для каждого термина. По запросу требуется обойти только совпавшие списки и применить ограничения каталога. Пример ниже считает score одного документа, что достаточно для проверочной задачи на малом каталоге.

text_models.py
"""TF-IDF, BM25 и профиль из доступных версий контента."""

from collections import Counter
from dataclasses import dataclass
import math
import re


def tokenize(text):
    return tuple(re.findall(r"[^\W_]+", text.casefold()))


@dataclass(frozen=True)
class TextIndex:
    size: int
    df: Counter
    average_length: float

    @classmethod
    def fit(cls, documents):
        df, size, length = Counter(), 0, 0
        for document in documents:
            df.update(set(document))
            size += 1
            length += len(document)
        if size == 0:
            raise ValueError("an index needs at least one document")
        return cls(size, df, length / size)

    def vector(self, document):
        weights = {
            term: (1 + math.log(count)) * (
                1 + math.log((self.size + 1) / (self.df[term] + 1))
            )
            for term, count in Counter(document).items() if term in self.df
        }
        return normalize(weights)

    def bm25(self, query, document, *, k1=1.2, b=.75):
        if not (math.isfinite(k1) and k1 > 0 and 0 <= b <= 1):
            raise ValueError("expected finite k1 > 0 and 0 <= b <= 1")
        if not document or not self.average_length:
            return 0.
        counts = Counter(document)
        normalizer = k1 * (1 - b + b * len(document) / self.average_length)
        return math.fsum(
            math.log1p((self.size - self.df[t] + .5) / (self.df[t] + .5))
            * (k1 + 1) * counts[t] / (counts[t] + normalizer)
            for t in set(query).intersection(counts, self.df)
        )


def normalize(weights):
    length = math.sqrt(math.fsum(value * value for value in weights.values()))
    return {key: value / length for key, value in weights.items() if value} if length else {}


def profile(weighted_documents):
    total = Counter()
    for weight, vector in weighted_documents:
        for term, value in vector.items():
            total[term] += weight * value
    return normalize(total)


def dot(left, right):
    return math.fsum(value * right.get(term, 0.) for term, value in left.items())

fit считает DF по множеству терминов документа, vector нормирует по L2L_2L2​, а bm25 перебирает пересечение запроса, документа и словаря. Токенизатор приводит регистр и выделяет группы букв и цифр. В нём нет морфологического анализа. Для русского это означает разные ключи для «клетка» и «клетки», если нормализацию не добавить до построения словаря.
