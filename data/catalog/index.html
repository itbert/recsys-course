Каталог и две временные оси

Почему текущего каталога недостаточно​

В момент показа статья имела заголовок «Введение в рекомендации». На следующий день редактор исправил ошибку в заголовке. Если соединить старые показы с сегодняшней таблицей статей, у всех появится новое описание. Для анализа текущего контента это может быть намеренным выбором. Для восстановления доступных тогда признаков это другое состояние информации.

История нужна не только текстам. Цена, наличие, категория, авторство, возрастное ограничение и признаки, рассчитанные отдельной моделью, могут изменяться. Для каждого источника требуется ответить на два вопроса: когда значение относилось к объекту и когда система узнала именно это значение.

Действие значения и знание о нём​

Определение · Двухвременная версия#

Для объекта iii версия vvv содержит значение xvx_vxv​ и два непустых полуоткрытых интервала:

Vv=[sv,ev),Kv=[bv,dv).V_v=[s_v,e_v),\qquad K_v=[b_v,d_v).Vv​=[sv​,ev​),Kv​=[bv​,dv​).

VvV_vVv​ задаёт время действия значения, KvK_vKv​ — время, в течение которого эта версия считалась известной системой. Правый конец может быть +∞+\infty+∞. Состояние «для момента TTT по знанию на момент CCC» выбирает версии с T∈VvT\in V_vT∈Vv​ и C∈KvC\in K_vC∈Kv​.

Это модель хранения для учебного примера. В ней интервалы знания отражают принятые системой версии, а не субъективное знание всех участников. Для воспроизведения реального serving необходимо, чтобы это время соответствовало доступности записи нужному сервису, а не только её появлению в последующей аналитической выгрузке.

При обычной смене цены меняется время действия. При позднем исправлении ошибки может измениться знание о прежнем времени действия. Эти изменения не обязаны совпадать. Две оси позволяют выразить оба случая.

Исправление прошлого​

В каталоге статьи A записаны две версии:

ВерсияДействует для времениИзвестна как версия для этого времени
v1, исходное описание[0,+∞)[0,+\infty)[0,+∞)[0,30)[0,30)[0,30)
v2, исправленное описание[0,+∞)[0,+\infty)[0,+∞)[30,+∞)[30,+\infty)[30,+∞)

В момент 30 мы узнали, что описание следовало исправить и для прошлого. Поэтому запрос (T=10,C=20)(T=10,C=20)(T=10,C=20) возвращает v1, а (T=10,C=40)(T=10,C=40)(T=10,C=40) — v2. В обоих случаях спрашивается о времени 10, но с разным состоянием знания.

Полуоткрытый интервал включает левую границу и исключает правую. Смежные интервалы [0,30)[0,30)[0,30) и [30,+∞)[30,+\infty)[30,+∞) не содержат общих точек. Явные границы и операции пересечения поддерживаются, например, типами диапазонов в PostgreSQL 18; вся двухвременная схема выше задана нами отдельно.

Условие однозначного выбора​

Теорема · Не более одной версии#

Пусть для одного объекта прямоугольники Vv×KvV_v\times K_vVv​×Kv​ различных версий попарно не пересекаются. Тогда для любых T,CT,CT,C условию T∈VvT\in V_vT∈Vv​, C∈KvC\in K_vC∈Kv​ удовлетворяет не более одной версии.

Доказательство

Предположим, что подходят две разные версии vvv и www. Тогда (T,C)(T,C)(T,C) принадлежит обоим прямоугольникам и, следовательно, их пересечению. Это противоречит предпосылке. Значит, две подходящие версии существовать не могут.

□

Утверждение не гарантирует существование версии. Между интервалами может быть пробел; объект может ещё не существовать или не быть известен системе. Поэтому проверка уникальности и проверка покрытия нужных показов — разные проверки.

В нашей схеме версия описывает запись целиком. Если цена и текст хранятся отдельными историями, однозначность должна выполняться для каждой присоединяемой сущности. Произвольное декартово произведение их версий снова способно размножить строки.

Реализация и применение​

catalog.py
"""Две временные оси каталога; конечные интервалы полуоткрыты."""
from dataclasses import dataclass
from itertools import combinations


@dataclass(frozen=True)
class CatalogVersion:
    item_id: str
    revision: str
    title: str
    valid_from: int
    valid_to: int | None
    known_from: int
    known_to: int | None


def contains(start, end, point):
    return start <= point and (end is None or point < end)


def overlaps(a_start, a_end, b_start, b_end):
    return (a_end is None or b_start < a_end) and (b_end is None or a_start < b_end)


def validate_catalog(versions):
    seen = set()
    for version in versions:
        if any(type(getattr(version, name)) is not str or not getattr(version, name)
               for name in ("item_id", "revision", "title")):
            raise ValueError("ID, ревизия и название должны быть непустыми строками")
        key = (version.item_id, version.revision)
        if key in seen:
            raise ValueError("Повторный ключ версии")
        seen.add(key)
        for start, end in [(version.valid_from, version.valid_to),
                           (version.known_from, version.known_to)]:
            if type(start) is not int or (end is not None and type(end) is not int):
                raise ValueError("Границы должны быть целыми или открытыми справа")
            if end is not None and start >= end:
                raise ValueError("Интервал должен быть непустым")
    for a, b in combinations(versions, 2):
        if a.item_id != b.item_id:
            continue
        valid_overlap = overlaps(a.valid_from, a.valid_to, b.valid_from, b.valid_to)
        known_overlap = overlaps(a.known_from, a.known_to, b.known_from, b.known_to)
        if valid_overlap and known_overlap:
            raise ValueError("Неоднозначное состояние каталога на двух осях")


def lookup(versions, item_id, valid_at, known_at):
    candidates = [version for version in versions
                  if version.item_id == item_id
                  and contains(version.valid_from, version.valid_to, valid_at)
                  and contains(version.known_from, version.known_to, known_at)]
    if len(candidates) > 1:
        raise ValueError("Найдено несколько версий")
    return candidates[0] if candidates else None


if __name__ == "__main__":
    versions = [
        CatalogVersion("A", "v1", "Исходное описание", 0, None, 0, 30),
        CatalogVersion("A", "v2", "Исправленное описание", 0, None, 30, None),
    ]
    validate_catalog(versions)
    print(lookup(versions, "A", valid_at=10, known_at=20).revision)
    print(lookup(versions, "A", valid_at=10, known_at=40).revision)

None в правой границе означает неограниченность, а не неизвестное значение атрибута. contains проверяет принадлежность полуоткрытому интервалу. overlaps устанавливает, имеют ли два непустых интервала общие точки.

validate_catalog проверяет ключ версии, типы, непустоту интервалов и отсутствие пересечения одновременно по обеим осям для одного объекта. Пересечение только по времени действия допустимо: именно так устроено исправление A. lookup возвращает единственную подходящую запись, None при отсутствии и ошибку при неоднозначности.

Для признаков, доступных при показе в t0t_0t0​, мы вызываем lookup(..., valid_at=t0, known_at=t0). Все показы A в журнале произошли до 30, поэтому получают v1 даже при экспорте в момент 40. Исправленное описание v2 существует в выгрузке, но не становится исторически доступным задним числом.

Пример предполагает, что показ и доступность каталога описаны совместимой временной шкалой. Для решения, принятого раньше клиентского показа, в реальной системе нужна именно отметка решения и доступные ему версии. Само имя known_from этого не гарантирует.

Проверка всех пар версий требует O(V2)O(V^2)O(V2) времени, один поиск — O(V)O(V)O(V). Для учебного каталога это прозрачно и достаточно. Индексация интервалов и поддержка истории при обновлениях нужны на масштабе; замена структуры хранения не должна менять определённую здесь семантику.

Упражнения​

Упражнение · Точка на границе#

Какая версия A выбирается при (T=10,C=30)(T=10,C=30)(T=10,C=30)? Что случилось бы при закрытых интервалах знания [0,30][0,30][0,30] и [30,+∞)[30,+\infty)[30,+∞)?

Разбор

Выбирается v2. При двух закрытых в точке 30 интервалах подошли бы обе версии. Для однозначности потребовалось бы другое согласованное правило границ или явное правило разрешения конфликта.

Упражнение · Уникальность без покрытия#

Для объекта есть только версии с интервалами действия [0,10)[0,10)[0,10) и [20,30)[20,30)[20,30), обе известны в момент 40. Противоречит ли отсутствие версии для T=15T=15T=15 доказанной теореме? Можно ли заменить его первой версией без изменения контракта?

Разбор

Не противоречит: теорема даёт «не более одной», а не «ровно одну». Подстановка первой версии расширит её действие на незаданный интервал. Это отдельное правило заполнения, которое должно быть обосновано и отражено в данных; молчаливое заполнение нарушает исходный контракт.
