Идентификаторы и словари

Что именно идентифицирует ключ​

Слово «пользователь» может означать человека, аккаунт, профиль внутри аккаунта, установку приложения или анонимный браузер. Их нельзя отождествить по названию столбца. Один человек способен иметь несколько аккаунтов; одним аккаунтом могут пользоваться несколько людей. Это разные возможные отношения, а не ошибка словаря ID.

Для нашей схемы user_id обозначает аккаунт. Для анонимного браузера понадобилось бы другое определение. Правило связывания двух идентичностей является отдельной процедурой с происхождением, временем доступности и возможными ошибками. Присоединение всех старых анонимных действий к аккаунту после входа не означает, что такая связь была известна при прежних решениях.

Аналогично статья, редакция статьи, автор и сайт — разные сущности. В торговле семейство товара, конкретный вариант и предложение продавца также могут иметь разные ключи. Укрупнение товара объединяет варианты и меняет задачу: рекомендация семейства не равна выбору доступного размера у конкретного продавца.

Определение · Область идентификатора#

Идентификатор определяет сущность только в установленной области: тип сущности, источник и при необходимости версия пространства ключей. Равенство строк из разных областей не устанавливает тождество сущностей. Таблица соответствий между областями должна иметь собственное правило построения.

Уровни ключей в журнале​

В этом договоре запрос выдачи не равен сессии. Если сессия определяется разрывом активности, нужно задать порог, временную ось и обработку нескольких устройств. Разные правила дают разные разбиения одной последовательности. До выбора правила session_id нельзя «восстановить» из одного user_id.

Также нельзя без договора источника обрезать пробелы, менять регистр, приводить строковые ID к числам или убирать ведущие нули. Строки "01" и "1" могут обозначать разные объекты. Если нормализация нужна, она становится частью версионируемого преобразования с проверкой коллизий.

Индексы для моделей​

Строковый внешний ID удобно преобразовать в индекс строки матрицы представлений. Это техническое кодирование, а не числовой признак с порядком: индекс 200 не означает, что объект вдвое «больше» объекта 100.

Зададим словарь v:Iknown→{1,…,m}v: \mathcal I_{\mathrm{known}}\to\{1,\ldots,m\}v:Iknown​→{1,…,m} как взаимно однозначное соответствие. Индекс 0 зарезервируем для неизвестного ID. Тогда кодировщик

encode⁡(i)={v(i),i∈Iknown,0,i∉Iknown\operatorname{encode}(i)= \begin{cases} v(i),&i\in\mathcal I_{\mathrm{known}},\\ 0,&i\notin\mathcal I_{\mathrm{known}} \end{cases}encode(i)={v(i),0,​i∈Iknown​,i∈/Iknown​​

сохраняет различия известных объектов, но объединяет неизвестные. Нулевой индекс не является внешним ID и не доказывает наличие обученного представления для нового объекта. Способ обработки новых объектов определяется моделью и serving-процедурой.

identifiers.py
"""Версионируемый словарь: 0 зарезервирован для неизвестного ID."""


def extend_vocabulary(previous, identifiers):
    if (any(type(value) is not int for value in previous.values())
            or set(previous.values()) != set(range(1, len(previous) + 1))):
        raise ValueError("Индексы должны быть уникальными и непрерывными от 1")
    if any(type(key) is not str or not key for key in previous):
        raise ValueError("ID должны быть непустыми строками")
    incoming = list(identifiers)
    if any(type(value) is not str or not value for value in incoming):
        raise ValueError("ID должны быть непустыми строками")
    result = dict(previous)
    for identifier in sorted(set(incoming) - result.keys()):
        result[identifier] = len(result) + 1
    return result


def encode(identifier, vocabulary):
    return vocabulary.get(identifier, 0)


if __name__ == "__main__":
    first = extend_vocabulary({}, ["B", "A", "B"])
    second = extend_vocabulary(first, ["C", "AA"])
    print("v1:", first)
    print("v2:", second)
    print("unknown:", encode("Z", second))

Сначала проверяется, что старые индексы являются точными целыми числами и составляют множество от 1 до размера словаря. Это исключает пропуски и повторное присвоение индекса. Затем код копирует словарь и добавляет новые ID в отсортированном порядке. Старые значения не меняются.

Для первой порции B, A, B получается A→1, B→2. Расширение порцией C, AA даёт A→1, B→2, AA→3, C→4. Если вместо расширения отсортировать весь объединённый каталог заново, индекс B станет 3. Веса модели, где строка 2 соответствовала B, перестанут совпадать с кодированием входов.

Сортировка делает результат независимым от порядка элементов внутри одной новой порции. Она не делает одинаковыми индексы при любых разбиениях потока на порции: сначала добавить C, а затем AA — другой порядок расширений. Поэтому сохраняется сам словарь, его версия и совместимость с моделью; одного описания алгоритма недостаточно.

Неизвестный объект и отсутствующая запись​

OOV, то есть ID вне словаря, отличается от ссылки на отсутствующий объект каталога. Новый объект может корректно существовать в каталоге и ещё не иметь обученного ID-представления. Напротив, известный индекс не гарантирует, что объект доступен для рекомендации сейчас. Эти условия проверяются разными компонентами.

Не следует также строить обучаемые агрегаты по всей будущей истории только потому, что внешний ID уже известен. Доступность идентичности не делает доступными будущие признаки и целевые действия. Временные правила построения словарей и признаков будут частью протокола выборок.

Упражнения​

Упражнение · Устойчивость к перестановке#

Старый словарь равен A→1, B→2. Дадут ли порции C, AA, C и AA, C одинаковое расширение? Дадут ли тот же результат два последовательных расширения сначала C, затем AA?

Разбор

Первые две порции дают AA→3, C→4: повторы убраны, новые ключи отсортированы. Два последовательных расширения дают C→3, AA→4. Устойчивость старых индексов и независимость от разбиения потока — разные свойства; код обеспечивает первое.

Упражнение · Объединение пространств#

В каталогах двух поставщиков есть товар 42. После конкатенации таблиц ключом оставили только строку 42. Почему это опасно и какое представление ключа сохраняет исходное различие?

Разбор

Строка уникальна лишь внутри каталога поставщика. Пара (supplier_id, external_item_id) сохраняет различие. Если товары действительно требуется объединить, нужна отдельная таблица соответствий и правило определения одной сущности; совпадение внешних ID для этого недостаточно.
