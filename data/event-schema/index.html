Схема события и время

Контракт вместо догадки​

Схема задаёт допустимые записи. Она включает имена полей, типы, обязательность, ограничения значений и семантику. Таблица с числовым timestamp без единицы измерения и определения момента события ещё не имеет достаточного временного контракта.

В нашем примере каждое событие имеет следующую схему версии 1.

ПолеТип и ограничениеЗначение
event_idНепустая строкаИдентичность события в единственном учебном источнике
actionimpression, click или finishТип зарегистрированного действия
event_timeНеотрицательное целоеМомент действия, минуты общей шкалы
received_atЦелое, не меньше event_timeМомент получения данной доставки
user_idНепустая строкаАккаунт в учебной системе
request_idНепустая строкаЗапрос рекомендательной выдачи
item_idНепустая строкаСтатья
impression_idНепустая строкаПоказ, к которому относится событие
positionЦелое от 1Позиция карточки в выдаче
schema_versionЦелое, равное 1Версия именно этой учебной схемы

Идентификатор события отличается от идентификатора показа: клик и дочитывание одного показа являются разными событиями. Каждая доставка события имеет свой received_at; остальные перечисленные поля при повторе должны совпадать.

Это компактная учебная схема, не реализация стандарта CloudEvents. В многопроизводительной системе область уникальности события задаётся явно; например, CloudEvents 1.0.2 использует пару source и id. Единственный источник позволяет нам оставить один event_id.

Тип и смысл пропуска​

Отсутствующее поле, JSON null, пустая строка и число 0 различаются. position=0 нарушает выбранную нумерацию. label=0 в будущей таблице будет известным отрицательным исходом. label=null будет неизвестной меткой. Замена всех пропусков нулями смешала бы эти случаи.

В Python bool является подклассом int. Поэтому проверка isinstance(value, int) приняла бы True в качестве времени или версии. Наш контракт требует точный тип int. Это намеренное ограничение формата: после JSON-разбора нормальное целое число имеет именно такой тип.

Новая версия схемы нужна и при изменении смысла поля. Например, переход от «сервер отправил карточку» к «клиент подтвердил отрисовку» меняет определение показа даже при сохранении всех типов. Старые и новые записи нельзя автоматически считать одним измерением. Для смешанной выгрузки требуется явное преобразование версий с документированными потерями информации.

Две отметки времени​

Определение · Время действия и время получения#

Для доставки jjj события eee обозначим через tet_ete​ время действия, через aeja_{ej}aej​ — время получения. В примере они выражены в целых минутах одной общей шкалы и удовлетворяют 0≤te≤aej0\le t_e\le a_{ej}0≤te​≤aej​. Первая доставка события имеет время ae=min⁡jaeja_e=\min_j a_{ej}ae​=minj​aej​.

Неравенство — допущение общей шкалы нашего примера. У реального клиента часы могут отличаться от часов сервера; преобразование в UTC само по себе рассинхронизацию не исправляет. Нельзя переносить эту проверку на произвольный клиентский лог без анализа устройства измерения.

Времена в календарном представлении нормализуются только при известном смещении или часовом поясе. 12:00+03:00 и 09:00Z обозначают один момент; строка 12:00 без дополнительного соглашения не определяет его однозначно. Различие между aware и naive объектами и операции преобразования описаны в документации Python 3.13.

Проверка с нуля​

schema.py
"""Строгая схема учебного события; время — целые минуты общей шкалы."""
from dataclasses import dataclass, fields
from datetime import datetime, timezone
import json


@dataclass(frozen=True)
class Event:
    event_id: str
    action: str
    event_time: int
    received_at: int
    user_id: str
    request_id: str
    item_id: str
    impression_id: str
    position: int
    schema_version: int


def validate(event):
    for name in ("event_id", "user_id", "request_id", "item_id", "impression_id"):
        value = getattr(event, name)
        if type(value) is not str or not value:
            raise ValueError(f"{name}: нужна непустая строка")
    if type(event.action) is not str or event.action not in {"impression", "click", "finish"}:
        raise ValueError("Неизвестный тип события")
    for name in ("event_time", "received_at", "position", "schema_version"):
        if type(getattr(event, name)) is not int:
            raise ValueError(f"{name}: требуется int, не bool")
    if event.event_time < 0 or event.received_at < event.event_time:
        raise ValueError("Нарушен договор общей шкалы времени")
    if event.position < 1 or event.schema_version != 1:
        raise ValueError("Недопустимая позиция или версия схемы")
    return event


def parse_event(payload):
    if type(payload) is not dict or set(payload) != {field.name for field in fields(Event)}:
        raise ValueError("Набор полей не соответствует версии 1")
    return validate(Event(**payload))


def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"Повторное имя поля JSON: {key}")
        result[key] = value
    return result


def load_jsonl(text):
    return [
        parse_event(json.loads(line, object_pairs_hook=unique_object))
        for line in text.splitlines() if line.strip()
    ]


def utc_timestamp(value):
    parsed = datetime.fromisoformat(value)
    if parsed.tzinfo is None or parsed.utcoffset() is None:
        raise ValueError("Часовой пояс должен быть указан явно")
    return parsed.astimezone(timezone.utc)


if __name__ == "__main__":
    first = utc_timestamp("2026-11-17T12:00:00+03:00")
    second = utc_timestamp("2026-11-17T09:00:00Z")
    print(first.isoformat(), first == second)

dataclass(frozen=True) описывает запись и запрещает обычное присваивание её полям. Он не проверяет аннотации типов во время создания объекта; это делает validate. parse_event сначала требует точный набор полей, затем создаёт и проверяет событие. Неизвестное поле здесь считается ошибкой версии, а не молча отбрасывается.

load_jsonl читает по одному JSON-объекту на непустую строку. object_pairs_hook получает пары до превращения их в словарь и позволяет отвергнуть повторные имена. Иначе два значения event_id в одном объекте могли бы быть незаметно сведены к одному. Это дополнительное правило нашего формата; возможности декодера описаны в документации json.

Функция utc_timestamp отвергает время без зоны и возвращает aware-объект UTC. Выполнение модуля печатает 2026-11-17T09:00:00+00:00 True.

Парсер устанавливает корректность отдельной записи, но не уникальность event_id, наличие показа для ответа или согласованность каталога. Эти ограничения относятся к набору записей и проверяются отдельно. Для фиксированного числа полей валидация nnn строк требует O(n)O(n)O(n) проверок; чтение текста также зависит от его длины.

Упражнения​

Упражнение · Смена единицы времени#

Старый источник писал Unix-время в секундах, новый пишет в миллисекундах с тем же именем поля. Обе величины проходят проверку «неотрицательное целое». Достаточна ли она? Как сделать преобразование проверяемым?

Разбор

Тип не фиксирует единицу. Нужны версия контракта или однозначно установленная версия источника, единое представление после преобразования и проверка на известных моментах. Деление на 1000 по порогу величины без договора источника — эвристика; она не заменяет определения формата и может ошибиться.

Упражнение · Необязательный доход#

В расширенной схеме есть необязательное поле revenue. Для одного заказа известно revenue=0, для другого значение пока не поступило. Следует ли хранить оба как 0?

Разбор

Нет. Ноль является известным значением, отсутствие — состоянием знания. Нужны допустимый пропуск и правило его интерпретации, а при нескольких причинах отсутствия — отдельный статус. Иначе даже среднее по наблюдаемым значениям и число известных заказов будут посчитаны неверно.
