Источники и единица наблюдения

Данные как результат измерения​

Пусть пользователь открыл рекомендательную ленту. Сервис создал запрос, отобрал кандидатов, сформировал выдачу и отправил её клиенту. Клиент отрисовал часть карточек. Пользователь открыл статью и позже дочитал её. Каждая стадия способна породить отдельную запись. Даже при безошибочном программном коде эти записи не обозначают одно и то же событие.

Определение · Единица наблюдения#

Единица наблюдения — объект, которому соответствует одна строка рассматриваемого набора данных. Для неё задаются правило включения, ключ и смысл измеряемых величин. Единица определяется процедурой построения таблицы; имя файла или столбца само по себе её не определяет.

В таблице доставок строка обозначает полученное сообщение. В каноническом журнале — одно событие после обработки повторов. В таблице показов — один показ одного объекта. В агрегированной матрице — пару пользователя и объекта за указанный период. Переход между этими уровнями требует явного преобразования.

Например, два клика по одной статье являются двумя событиями, но могут превратиться в один бинарный признак взаимодействия. Это допустимая агрегация для определённой задачи. Если назвать агрегат «числом кликов», смысл будет потерян.

Таблица описывает возможные классы источников, а не обязательную схему любой системы. Для каждого поля требуется происхождение. Текст статьи может быть исходным контентом; embedding текста — результатом конкретной модели и версии обработки. Средний рейтинг — агрегатом с периодом расчёта и правилом отбора оценок. Соединять эти величины как одинаково «сырые» признаки нельзя.

Контекст также имеет время доступности. Язык интерфейса при запросе может быть известен до решения. Итоговая длительность чтения становится известна после него. Оба поля описывают один сеанс, но только первое при таком устройстве сбора доступно для исходного решения.

Механизм появления строки​

Введём индикатор OOO: рассматриваемая единица попала в доступные данные при O=1O=1O=1. Пусть XXX обозначает признаки, а YYY — целевую величину в заданной популяции. В данных непосредственно наблюдается распределение

P(X,Y∣O=1),\Prob(X,Y\mid O=1),P(X,Y∣O=1),

если соответствующие XXX и YYY измерены. В общем случае оно не равно P(X,Y)\Prob(X,Y)P(X,Y). Это следует уже из определения условной вероятности: для события BBB при P(O=1)>0\Prob(O=1)>0P(O=1)>0

P(B∣O=1)=P(B,O=1)P(O=1).\Prob(B\mid O=1)=\frac{\Prob(B,O=1)}{\Prob(O=1)}.P(B∣O=1)=P(O=1)P(B,O=1)​.

Равенство с P(B)\Prob(B)P(B) требует дополнительных условий. Если в выгрузку включены только пользователи минимум с двадцатью оценками, распределение активности всех посетителей из неё непосредственно не восстанавливается. Если сохраняются только клики, таблица не содержит знаменателя для вероятности клика на показ.

Здесь не предлагается универсальная поправка на отбор. Сначала нужно описать сам отбор: кого измеряли, какие решения принимала система, что логировалось, какие строки отфильтровали и какие сведения не сохранили. Методы оценки по смещённым логам будут введены после обычных протоколов оценки.

Сквозной пример​

Мы рассматриваем рекомендации статей. impression означает подтверждённую клиентом отрисовку карточки в целевой позиции. Это договор учебного примера; он не утверждает, что человек прочитал карточку. click — открытие по этой карточке, а finish — зарегистрированное достижение принятого в примере критерия дочитывания.

Целевая единица итоговой таблицы — один показ, идентифицируемый impression_id. Метка равна единице, если связанное дочитывание произошло в течение десяти минут после показа. Семантику связи и границы окна мы формализуем в следующих главах.

В исходном журнале 13 доставок, но 11 различных событий и 5 показов. Разница возникла из-за повторных доставок двух дочитываний. Это не оценка распространённости дублей в реальных системах: числа выбраны для проверки алгоритма.

Паспорт источника​

Перед обработкой записываются назначение источника, единица строки, ключ, время и способ измерения, правила отбора, версии, известные пробелы и условия использования. Полезно отдельно отмечать утверждения, подтверждённые документацией, и пока неизвестные свойства. Пустое описание механизма логирования нельзя заменять предположением о полном наблюдении.

Такой подход согласуется с предложением документировать мотивацию, состав, сбор и предполагаемые применения в работе Gebru et al. Datasheets for Datasets. Конкретный паспорт и схема сквозного примера — наша учебная конструкция.

Упражнения​

Упражнение · Три разных числа#

Одно событие клика доставлено три раза. Второй клик того же пользователя по той же статье доставлен один раз. Сколько здесь доставок, событий и различных пар «пользователь — статья»?

Разбор

Четыре доставки, два события и одна пара. Ни одно число не заменяет другое без изменения единицы подсчёта. Для бинарной матрицы взаимодействий достаточно одной пары, для частоты действий нужны два события, для нагрузки на приёмник — четыре доставки.

Упражнение · Недостающий знаменатель#

В файле есть 500 кликов по статье A и 100 по B. Можно ли заключить, что вероятность клика на показ у A выше? Какие дополнительные сведения нужны хотя бы для эмпирического отношения кликов к показам?

Разбор

Нельзя: число показов неизвестно. Нужны сопоставимые показы за тот же период, семантика регистрации, связь кликов с показами и правило подсчёта повторных кликов. Даже после этого отношение описывает зарегистрированный трафик соответствующей политики, а не автоматически эффект замены B на A.
