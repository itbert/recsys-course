Календарь и жизненный цикл

Одна временная линия не объясняет другую​

В рекомендательных данных одновременно меняются трафик, состав пользователей, каталог, политика выдачи и регистрация ответа. График кликов по дням смешивает эти источники изменений. Первый шаг — отдельно показать число экспозиций, ответ и покрытие измерения.

Пусть сутки ddd соответствуют интервалу [dΔ,(d+1)Δ)[d\Delta,(d+1)\Delta)[dΔ,(d+1)Δ), где Δ=86400\Delta=86400Δ=86400 секунд нашей условной шкалы UTC. Определим

Qd={q:dΔ≤tq<(d+1)Δ},Nd=∣Qd∣,Cd=∑q∈Qd1{clickedq}.Q_d=\{q:d\Delta\le t_q<(d+1)\Delta\},\quad N_d=|Q_d|,\quad C_d=\sum_{q\in Q_d}\mathbf1\{\mathrm{clicked}_q\}.Qd​={q:dΔ≤tq​<(d+1)Δ},Nd​=∣Qd​∣,Cd​=q∈Qd​∑​1{clickedq​}.

При Nd>0N_d>0Nd​>0 доля кликов равна Cd/NdC_d/N_dCd​/Nd​. Удвоение CdC_dCd​ может произойти при удвоении NdN_dNd​ без изменения доли. При Nd=0N_d=0Nd​=0 доля не определена; это не день с доказанной нулевой склонностью к клику.

Для дочитывания отдельно сохраняем KdK_dKd​, число известных исходов, и SdS_dSd​, число известных единиц. Пара Kd/NdK_d/N_dKd​/Nd​ и Sd/KdS_d/K_dSd​/Kd​ разделяет покрытие меток и долю среди известных. Изменение любого знаменателя должно оставаться видимым.

В день 12 имеется 143 показа, но только 51 известная метка. Доля единиц среди известных равна 15/51≈29,41%15/51\approx29{,}41\%15/51≈29,41%, покрытие — 51/143≈35,66%51/143\approx35{,}66\%51/143≈35,66%. Замена неизвестных нулями дала бы 15/143≈10,49%15/143\approx10{,}49\%15/143≈10,49%, то есть другую величину. По одному падению последнего отношения нельзя заключить, что поведение пользователей ухудшилось.

Время действия, доставки и выгрузки​

Агрегация по event_time отвечает на вопрос, к какому периоду относится зарегистрированное действие. Агрегация по received_at описывает поступление его подтверждений. В день 19 нашего примера подтверждения запаздывают на три часа. Суточный счётчик здесь может не измениться, поскольку доставки остаются в тех же сутках, но почасовой профиль изменится.

Срез по времени получения и группировка по времени действия совместимы: сначала выбираются доступные доставки, потом они распределяются по времени действий. Исторический отчёт за вчера может доуточняться после поздних поступлений. Нужно сохранять момент экспорта и статус завершённости периода.

Неполные первые или последние сутки нельзя сравнивать с полными как равные интервалы наблюдения. Нормировка на часы допустима, если вопрос именно об интенсивности за наблюдаемые часы; она не восполняет отсутствующие часы с иным поведением. Аналогично локальные календарные сутки и сутки UTC задают разные срезы. Их выбор следует устройству продукта и фиксируется до интерпретации.

Возраст объекта​

Определение · Календарный возраст#

Если статья опубликована в момент bib_ibi​, её возраст при времени t≥bit\ge b_it≥bi​ равен a=t−bia=t-b_ia=t−bi​. Для дневного анализа при появлении на границе суток возраст в днях равен d−bidayd-b_i^{\mathrm{day}}d−biday​. До появления статьи характеристика её показов как доступного объекта не определена.

Первая зарегистрированная экспозиция не обязана совпадать с публикацией. Возраст от первого показа и возраст от появления в каталоге являются разными осями. Мы используем известный день появления из реестра.

Статья a16 доступна с дня 21. Отсутствие её показов до дня 21 обозначается пропуском вне области доступности, а не нулевым спросом. У a19 доступность есть весь период, но число показов равно нулю. Эти случаи различаются даже при одинаковом отсутствии строк в журнале.

При усреднении траекторий нескольких статей для каждого возраста нужно сохранять число объектов с наблюдаемым окном. Старые объекты поддерживают больше возрастных точек, молодые — меньше. Если будущие точки молодых статей заполнить нулями, кривая будет смешивать отсутствие будущего наблюдения с низкой активностью.

Код календарных срезов​

temporal.py — начало модуля
"""Календарные срезы, доступность объекта и календарные недельные когорты."""
from collections import Counter, defaultdict
from dataset import DAY, DAYS
from metrics import rates


def daily(rows):
    groups = defaultdict(list)
    for row in rows:
        groups[row.event_time // DAY].append(row)
    return [{"day": day, **rates(groups[day])} for day in range(DAYS)]


def lifecycle(rows, catalog, item_id):
    counts = Counter(row.event_time // DAY for row in rows if row.item_id == item_id)
    item = catalog[item_id]
    return [{"day": day, "age": day - item["release_day"],
             "impressions": counts[day] if item["release_day"] <= day < item["retire_day"] else None}
            for day in range(DAYS)]


daily сначала группирует строки по времени действия. Затем проходит все 28 суток, включая дни без событий. Это отличает полный временной индекс от списка только встреченных дат.

lifecycle сначала считает показы выбранной статьи. Внутри периода доступности отсутствие строк даёт 0; вне его возвращается None. Время окончания доступности исключено по тому же правилу полуоткрытых интервалов, что и в каталоге части 3. Индекс возраста сохраняется явно, поэтому переход между календарной и возрастной осью проверяем.

Сезонность как гипотеза​

В генераторе день 0 считается условным понедельником; в дни 5 и 6 каждого цикла к активности добавлены показы. Поэтому повторяющаяся недельная структура является свойством конструкции. В реальном журнале похожий рисунок мог бы возникнуть из календарного поведения, рассылок, расписания обновлений или смены состава трафика.

Четыре недели показывают лишь четыре повторения недельного цикла. Они не устанавливают устойчивость на год и не исключают тренд. На этапе EDA полезны срезы по дню недели, часу, платформе и возрасту сущности с сохранением знаменателей. Декомпозиция, автокорреляция и модели временных рядов требуют определения стохастического процесса; они вводятся в следующей части.

Упражнения​

Упражнение · Счётчик и доля#

В понедельник было 100 показов и 20 кликов, во вторник 1000 показов и 100 кликов. Какие величины выросли и уменьшились? Достаточно ли этого, чтобы установить изменение качества рекомендаций?

Разбор

Число кликов выросло в пять раз, число показов — в десять, доля кликов снизилась с 20% до 10%. Это описывает два набора. Для вывода о качестве нужны сопоставимые условия, состав аудитории и корректный протокол; общий календарный срез их не обеспечивает.

Упражнение · Будущий возраст#

Одна статья наблюдалась 30 дней, другая появилась три дня назад. Можно ли при построении средней возрастной траектории записать второй статье нули на возрастах 4–30? Что нужно показывать рядом с каждой возрастной точкой?

Разбор

Нет: эти окна ещё не наблюдались. Нужны пропуски и число статей с достаточным наблюдением для данного возраста. В противном случае снижение средней будет частично создано искусственными нулями, а состав объектов в разных точках останется скрытым.
