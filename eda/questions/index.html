Вопрос, популяция и единица анализа

Сначала определить вопрос​

Фраза «активность выросла» может означать больше показов, больше уникальных посетителей, больше показов на активный аккаунт или большую долю реестра с хотя бы одним показом. Эти величины способны изменяться в разные стороны. Прежде чем строить график, нужно определить объект, период, единицу и допустимое множество наблюдений.

Определение · Описательный объект анализа#

Описательная характеристика относится к явно заданному конечному набору SSS и правилу вычисления T(S)T(S)T(S). Её значение устанавливает свойство этого набора. Для интерпретации как оценки иной популяции дополнительно нужны модель отбора и статистические предпосылки.

Например, N/∣U∣N/|\mathcal U|N/∣U∣ описывает число показов на аккаунт заданного реестра. Если U+={u:nu>0}\mathcal U_+=\{u:n_u>0\}U+​={u:nu​>0}, то N/∣U+∣N/|\mathcal U_+|N/∣U+​∣ описывает число показов на аккаунт, представленный хотя бы одним показом. Исключение нулей меняет знаменатель, даже если события не меняются.

Термин «активный пользователь» также требует измеримого определения. В этой части «активен по показам» означает наличие зарегистрированного показа. Это не устанавливает длительность внимания, посещение всех разделов приложения или наличие клика.

Два усреднения доли кликов​

Для аккаунта uuu с nu>0n_u>0nu​>0 показами и cuc_ucu​ показами с кликом определим ru=cu/nur_u=c_u/n_uru​=cu​/nu​. В нашей таблице clicked уже бинарен на уровне показа, поэтому повторные клики не увеличивают cuc_ucu​.

Теорема · Общая доля как взвешенное среднее#

Пусть N=∑u∈U+nu>0N=\sum_{u\in\mathcal U_+}n_u>0N=∑u∈U+​​nu​>0. Тогда доля показов с кликом равна

r^show=∑ucuN=∑u∈U+nuNru.\widehat r_{\mathrm{show}}=\frac{\sum_u c_u}{N} =\sum_{u\in\mathcal U_+}\frac{n_u}{N}r_u.rshow​=N∑u​cu​​=u∈U+​∑​Nnu​​ru​.

Средняя аккаунтная доля r^user=∣U+∣−1∑uru\widehat r_{\mathrm{user}}=|\mathcal U_+|^{-1}\sum_u r_uruser​=∣U+​∣−1∑u​ru​ использует другие веса и в общем случае имеет другое значение.

Доказательство

Подставим cu=nuruc_u=n_ur_ucu​=nu​ru​ в числитель и вынесем общий знаменатель NNN. Полученные веса nu/Nn_u/Nnu​/N неотрицательны и суммируются в единицу. В аккаунтном среднем вес каждого представленного аккаунта равен 1/∣U+∣1/|\mathcal U_+|1/∣U+​∣ независимо от числа показов. Совпадение этих двух средних не требуется алгеброй.

□

Для двух аккаунтов с результатами 1/101/101/10 и 1/11/11/1 общая доля равна 2/11≈18,18%2/11\approx18{,}18\%2/11≈18,18%, а аккаунтная — 55%55\%55%. Первое число соответствует равномерному выбору показа из таблицы, второе — равномерному выбору представленного аккаунта с последующим использованием его доли. Ни один способ не является универсально правильным: он должен соответствовать вопросу.

У аккаунта без показов индивидуальная доля 0/00/00/0 не определена. Включение такого аккаунта со значением 0 создаёт новый показатель. Его нельзя незаметно назвать средним той же самой доли.

Контракт сквозного набора​

Период наблюдения состоит из 28 полных условных суток UTC, [0,28⋅86400)[0,28\cdot86400)[0,28⋅86400). Единица времени здесь — секунда, в отличие от минутного примера части 3. Одна строка — один канонический показ статьи; повторов доставки в этой таблице уже нет.

В реестре 41 аккаунт; восемь не имеют показов. У 20 статей заданы дни появления и окончания доступности. Две статьи доступны, но не показаны. Некоторые аккаунты начинают наблюдаться позже, а у части генератор прекращает активность после заданного возраста.

clicked обозначает наличие клика. dwell_seconds измеряется для всех показов с кликом и отсутствует для остальных. label обозначает дочитывание в десятиминутном окне. Мы конструируем зрелый снимок: временной срез сделан после завершения окон и предусмотренной доставки ответов. В день 12 для мобильного контекста сведения о дочитывании отсутствуют; observable=False, label=None. Регистрация кликов в примере сохраняется отдельным измерением.

Отметка received_at относится к подтверждению показа. В день 19 она запаздывает на три часа. Это отдельная задержка; она не переопределяет окно дочитывания. У u_burst в день 10 имеются 240 показов одной статьи с секундными интервалами. Этот паттерн служит диагностическим примером и сам по себе не является определением бота.

Генератор и проверка​

dataset.py
"""Детерминированная синтетическая таблица показов; время — секунды."""
from dataclasses import asdict, dataclass

DAY = 86400
DAYS = 28
END = DAYS * DAY


@dataclass(frozen=True)
class Observation:
    impression_id: str
    user_id: str
    item_id: str
    event_time: int
    received_at: int
    platform: str
    position: int
    clicked: bool
    dwell_seconds: int | None
    label: int | None
    observable: bool


def generate():
    users = {f"u{u:02}": (u // 4) * 3 if u < 32 else 0 for u in range(40)}
    users["u_burst"] = 10
    weights = [18, 10, 7, 5, 4, 3, 2, 2, 1, 1, 1, 1, 2, 2, 1, 1, 1, 1, 0, 0]
    catalog = {
        f"a{i:02}": {"release_day": 0 if i < 12 or i >= 18 else 7 if i < 16 else 21,
                    "retire_day": 20 if i == 4 else DAYS}
        for i in range(20)
    }
    rows = []
    for day in range(DAYS):
        pool = [identifier for i, (identifier, item) in enumerate(catalog.items())
                if item["release_day"] <= day < item["retire_day"]
                for _ in range(weights[i])]
        for u in range(32):
            user = f"u{u:02}"
            active_days = 10 if u % 5 == 0 else 17 if u % 7 == 0 else DAYS
            if (day < users[user] or day >= users[user] + active_days
                    or (day - users[user]) % (1 + u % 4)):
                continue
            size = 1 + (11 - u % 12) + (3 if day % 7 in (5, 6) else 0)
            for j in range(size):
                item = pool[(u * 17 + day * 13 + j * 7) % len(pool)]
                time = day * DAY + 7200 + (u * 31 + j * 47) % 60000
                position = j % 5 + 1
                platform = "web" if (u + day) % 3 == 0 else "mobile"
                clicked = (u * 11 + day * 7 + j * 3 + position) % 10 < 6 - position // 2
                finished = clicked and (u + day + j) % 3 != 0
                observable = not (day == 12 and platform == "mobile")
                rows.append(Observation(
                    f"p{len(rows):05}", user, item, time,
                    time + (10800 if day == 19 else (u + j) % 4), platform, position,
                    clicked, 5 + (u * 17 + j * 13 + day * 11) % 240 if clicked else None,
                    int(finished) if observable else None, observable,
                ))
    for j in range(240):
        time = 10 * DAY + 3600 + j
        rows.append(Observation(f"p{len(rows):05}", "u_burst", "a00", time, time,
                                "web", 1, False, None, 0, True))
    rows.sort(key=lambda row: (row.event_time, row.impression_id))
    audit(rows, users, catalog)
    return rows, users, catalog


def audit(rows, users, catalog):
    identifiers = set()
    for row in rows:
        if any(type(value) is not str or not value for value in
               (row.impression_id, row.user_id, row.item_id)):
            raise ValueError("Нужны непустые строковые ID")
        if row.impression_id in identifiers:
            raise ValueError("Повтор ID показа")
        identifiers.add(row.impression_id)
        if row.user_id not in users or row.item_id not in catalog:
            raise ValueError("Неизвестная сущность")
        if type(row.event_time) is not int or type(row.received_at) is not int:
            raise ValueError("Время должно быть целым")
        if type(row.position) is not int or not 1 <= row.position <= 5 or row.platform not in ("web", "mobile"):
            raise ValueError("Некорректный контекст показа")
        day = row.event_time // DAY
        item = catalog[row.item_id]
        if not (users[row.user_id] <= day < DAYS
                and item["release_day"] <= day < item["retire_day"]):
            raise ValueError("Показ вне периода существования сущности")
        if row.received_at < row.event_time or row.received_at > END + 900:
            raise ValueError("Доставка за пределами договора")
        if type(row.clicked) is not bool or type(row.observable) is not bool:
            raise ValueError("Ожидается bool")
        if row.label is not None and (type(row.label) is not int or row.label not in (0, 1)):
            raise ValueError("Некорректная метка")
        if row.observable != (row.label is not None):
            raise ValueError("В этом зрелом снимке неизвестность задаётся пробелом покрытия")
        if row.dwell_seconds is not None and (type(row.dwell_seconds) is not int or row.dwell_seconds < 0):
            raise ValueError("Некорректная длительность")
        if row.clicked != (row.dwell_seconds is not None) or (row.label == 1 and not row.clicked):
            raise ValueError("Нарушено правило сигналов учебного генератора")


if __name__ == "__main__":
    observations, users, catalog = generate()
    print("Показы, аккаунты, статьи:", len(observations), len(users), len(catalog))
    print(asdict(observations[0]))

Observation фиксирует единицу строки. generate создаёт реестры, проходит дни и аккаунты и добавляет показы. Повторение ID в pool задаёт частоту их выбора арифметическим правилом. Здесь нет статистического оценивания или утверждения о вероятности реального поведения: весь набор детерминирован.

Правила появления клика и исхода также заданы непосредственно. Генератор создаёт готовую аналитическую таблицу, а не изображает полноценный исходный журнал. Восстановление такой таблицы из событий было предметом части 3.

audit проверяет уникальность показа, ссылки, периоды существования, время, типы и согласованность пропусков. Свойство «единица дочитывания требует клика» относится только к выбранному генератору. В другом источнике путь к дочитыванию и полнота регистрации кликов могут быть иными.

После запуска получается 2466 строк. На весь реестр приходится примерно 60,15 показа на аккаунт, на 33 аккаунта с показами — примерно 74,73. Разный возраст аккаунтов пока не выровнен. Это две описательные сводки одного периода; возрастные сравнения появятся в главах о времени и когортах.

Упражнения​

Упражнение · Рост без изменения счётчика#

В журнале осталось 1000 показов. В первом отчёте реестр содержит 100 аккаунтов, во втором оставлены только 40 аккаунтов с показами. Сравните средние и укажите, можно ли назвать их различие ростом активности сервиса.

Разбор

Средние равны 10 и 25. Изменился набор усреднения, а не журнал. Разница не подтверждает временной рост: сравниваются показатели с разными знаменателями. Нужны сопоставимые определения и периоды.

Упражнение · Чей вес больше#

У A сто показов и десять кликов, у B десять показов и пять кликов. Рассчитайте обе доли и определите, какой аккаунт сильнее влияет на общую долю показов с кликом.

Разбор

Общая доля равна 15/110≈13,64%15/110\approx13{,}64\%15/110≈13,64%, аккаунтная — (0,1+0,5)/2=30%(0{,}1+0{,}5)/2=30\%(0,1+0,5)/2=30%. В первом случае вес A равен 100/110100/110100/110, вес B — 10/11010/11010/110. Во втором веса равны. Различие вызвано единицей усреднения.
