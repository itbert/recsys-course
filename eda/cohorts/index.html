Когорты и окна наблюдения

Какую группу сравнивает когорта​

Когорта объединяет сущности по общему событию начала и периоду этого события. Началом могут быть регистрация, первый визит, первый показ или первая покупка. Эти события относятся к разным популяциям. Восьми аккаунтов без показов нет в когортах первого показа, хотя они существуют в реестре.

В этой главе используем четыре полные календарные недели w=0,1,2,3w=0,1,2,3w=0,1,2,3. Время анализируется по действиям после формирования полного снимка. Аккаунт считается активным в неделе, если имеет хотя бы один зарегистрированный показ статьи.

Определение · Когорта первого наблюдаемого показа#

Пусть AwA_wAw​ — множество аккаунтов с показом в неделе www, а bu=min⁡{w:u∈Aw}b_u=\min\{w:u\in A_w\}bu​=min{w:u∈Aw​}. Для аккаунтов, имеющих хотя бы один показ, когорта Cb={u:bu=b}C_b=\{u:b_u=b\}Cb​={u:bu​=b}. При наблюдаемой неделе b+ab+ab+a и ∣Cb∣>0|C_b|>0∣Cb​∣>0 определим календарный недельный возврат

Rb,a=∣Cb∩Ab+a∣∣Cb∣.R_{b,a}=\frac{|C_b\cap A_{b+a}|}{|C_b|}.Rb,a​=∣Cb​∣∣Cb​∩Ab+a​∣​.

Возраст aaa здесь означает сдвиг календарных недель относительно недели первого показа, а не точное число суток от первого события.

Аккаунт, впервые показанный в воскресенье, и аккаунт с первым показом в понедельник входят в одну недельную когорту. Их нулевой возраст имеет разную длительность доступного наблюдения внутри недели. Если нужен точный семидневный интервал от первого события, следует определить иной показатель с индивидуальными временными окнами.

Почему нулевая колонка равна единице​

По определению Cb⊆AbC_b\subseteq A_bCb​⊆Ab​, поэтому при непустой когорте Rb,0=1R_{b,0}=1Rb,0​=1. Единица в первой колонке является следствием выбора начала, а не свидетельством отличного удержания. Для когорт регистрации и активности по показам равенство могло бы не выполняться.

Также Rb,aR_{b,a}Rb,a​ не требует активности во все промежуточные недели. Аккаунт может отсутствовать в возрасте 1 и снова появиться в возрасте 2. Непрерывное удержание определялось бы через пересечение Cb∩Ab+1∩…∩Ab+aC_b\cap A_{b+1}\cap\ldots\cap A_{b+a}Cb​∩Ab+1​∩…∩Ab+a​ и давало бы другой числитель.

Возврат к показам не равен возврату к чтению, платежам или любому визиту в приложение. Если человек открывал другой раздел без показов, наша метрика этого не увидит. Изменение инструмента регистрации также способно изменить наблюдаемый возврат без изменения реального поведения.

Правый край таблицы​

Для четырёх недель ячейка (b,a)(b,a)(b,a) наблюдаема только при b+a<4b+a<4b+a<4. Для когорты недели 3 возраст 1 ещё не наступил в доступных данных. Значение в этой ячейке неизвестно и не равно нулю.

Когорта недели 0 содержит 12 аккаунтов; в возрасте 3 зарегистрированы показы восьми, поэтому R0,3=8/12≈66,67%R_{0,3}=8/12\approx66{,}67\%R0,3​=8/12≈66,67%. Когорта недели 3 содержит четыре аккаунта, но её возраст 3 неизвестен. Сравнение 66,67% с искусственным нулём этой когорты создало бы несуществующее ухудшение.

При агрегировании возраста aaa по когортам допустимы только наблюдаемые ячейки. Если вопрос относится к равномерно выбранному аккаунту из доступных когорт, используется

Rapooled=∑b:b+a<4∣Cb∩Ab+a∣∑b:b+a<4∣Cb∣.R_a^{\mathrm{pooled}}= \frac{\sum_{b:b+a<4}|C_b\cap A_{b+a}|} {\sum_{b:b+a<4}|C_b|}.Rapooled​=∑b:b+a<4​∣Cb​∣∑b:b+a<4​∣Cb​∩Ab+a​∣​.

Среднее самих Rb,aR_{b,a}Rb,a​ с равными весами когорт отвечает другому вопросу. Даже корректное объединение меняет состав когорт при росте возраста: дальние возраста представлены более ранними когортами. Поэтому полная кривая не является автоматически траекторией одного неизменного состава пользователей.

Код построения​

temporal.py — функция cohorts
def cohorts(rows, weeks=4):
    active = defaultdict(set)
    first = {}
    for row in rows:
        week = row.event_time // (7 * DAY)
        if not 0 <= week < weeks:
            raise ValueError("Строка вне анализируемых полных недель")
        active[week].add(row.user_id)
        first[row.user_id] = min(first.get(row.user_id, week), week)
    groups = [{user for user, start in first.items() if start == week} for week in range(weeks)]
    return [{"cohort_week": start, "users": len(group), "ages": [
        None if start + age >= weeks else {
            "active": len(group & active[start + age]), "eligible": len(group),
            "rate": len(group & active[start + age]) / len(group) if group else None}
        for age in range(weeks)]} for start, group in enumerate(groups)]

Первый проход строит множества активных аккаунтов для каждой недели и минимальную наблюдаемую неделю аккаунта. min делает результат независимым от порядка строк. Затем создаются когорты и пересечения с активными множествами.

None на уровне ячейки означает отсутствие будущего окна. Для пустой, но календарно доступной когорты знаменатель равен 0, и поле rate также равно None. Эти два случая имеют разную причину, которую структура выхода сохраняет. Значения active и eligible хранятся вместе с долей, чтобы 1/1 не выглядело таким же объёмом свидетельства, как 1000/1000.

Число строк не влияет на принадлежность после появления хотя бы одного показа в неделе: множества исключают повторный подсчёт аккаунта. Один аккаунт с 240 показами увеличивает размер своей когорты на единицу. Временная интенсивность и когортное присутствие — разные характеристики.

Левый край и первое наблюдаемое событие​

Начало выгрузки может обрезать прошлую историю. Тогда первое событие в файле не является первым событием аккаунта за всю его жизнь. Без надёжного реестра или достаточной предыстории когорта должна называться когортой первого наблюдаемого события.

В синтетическом примере правила генератора известны. В реальном анализе нужны определения доступной предыстории, регистрации и начала логирования. Нельзя объявить все аккаунты первой недели новыми только потому, что раньше файл пуст.

Аналогично прекращение показов до конца периода ещё не доказывает окончательный уход. Это отсутствие зарегистрированной активности в конкретном наблюдаемом окне. Для моделей времени до события и цензурирования потребуется дополнительная постановка; текущая таблица описательная.

Упражнение · Вес когорты#

В одном возрасте у первой когорты активны 9 из 10 аккаунтов, у второй 10 из 100. Найдите равновесное среднее двух когорт и объединённую аккаунтную долю.

Разбор

Равновесное среднее равно (0,9+0,1)/2=50%(0{,}9+0{,}1)/2=50\%(0,9+0,1)/2=50%. Объединённая доля — 19/110≈17,27%19/110\approx17{,}27\%19/110≈17,27%. Разные веса соответствуют выбору когорты или аккаунта как единицы усреднения.

Упражнение · Новый в файле#

Файл начинается 1 марта; аккаунт впервые встречается 2 марта. Достаточно ли этого, чтобы включить его в когорту регистрации марта? Как корректно назвать достоверно наблюдаемое событие?

Разбор

Недостаточно: регистрация и прежняя история могут предшествовать файлу. Достоверно известен первый наблюдаемый в этой выгрузке показ 2 марта. Когорта регистрации требует отдельного надёжного времени регистрации и согласованной области аккаунтов.
