Разреженность и поддержка

Три разных количества​

Пусть NNN — число показов, U\mathcal UU — реестр аккаунтов, I\mathcal II — каталог. Один аккаунт может многократно видеть одну статью, поэтому NNN не равно числу различных пар. После свёртки повторных показов определим

E={(u,i):в периоде зарегистрирован хотя бы один показ i аккаунту u}.E=\{(u,i):\text{в периоде зарегистрирован хотя бы один показ }i\text{ аккаунту }u\}.E={(u,i):в периоде зарегистрирован хотя бы один показ i аккаунту u}.

Отдельно определим P⊆EP\subseteq EP⊆E как пары с хотя бы одной наблюдаемой единицей дочитывания. В нашем наборе N=2466N=2466N=2466, ∣E∣=399|E|=399∣E∣=399, ∣P∣=269|P|=269∣P∣=269. Все три числа корректны и относятся к разным объектам.

Пара из E∖PE\setminus PE∖P может содержать только известные нули, неизвестные исходы или их смесь. Поэтому отсутствие наблюдаемой единицы у пары не является общим доказательством отрицательного предпочтения.

Что именно считается плотностью​

Определение · Плотность поддержки#

Для непустых фиксированных реестров определим

ρE=∣E∣∣U∣ ∣I∣,ρP=∣P∣∣U∣ ∣I∣.\rho_E=\frac{|E|}{|\mathcal U|\,|\mathcal I|},\qquad \rho_P=\frac{|P|}{|\mathcal U|\,|\mathcal I|}.ρE​=∣U∣∣I∣∣E∣​,ρP​=∣U∣∣I∣∣P∣​.

Разреженность соответствующей бинарной поддержки — 1−ρ1-\rho1−ρ. Это определения относительно указанного прямоугольника сущностей.

У нас знаменатель равен 41⋅20=82041\cdot20=82041⋅20=820, поэтому ρE≈48,66%\rho_E\approx48{,}66\%ρE​≈48,66%, ρP≈32,80%\rho_P\approx32{,}80\%ρP​≈32,80%. Использование 2466/8202466/8202466/820 дало бы число больше единицы: это среднее число показов на пару, а не плотность бинарной поддержки.

Прямоугольник не утверждает, что все пары были допустимыми рекомендациями во все моменты. Аккаунты и статьи появлялись в разное время, а часть статей перестала быть доступной. Если нужен знаменатель допустимых пар, сначала требуется определить допустимость и временное агрегирование. Плотность по всем ID за месяц и доля доступных пар с экспозицией — разные показатели.

Двудольный граф и степени​

Матрицу поддержки можно рассматривать как граф с двумя непересекающимися типами вершин: аккаунтами и статьями. Ребро соединяет uuu и iii, если (u,i)∈E(u,i)\in E(u,i)∈E. Степень аккаунта dud_udu​ — число различных показанных ему статей, степень статьи did_idi​ — число различных аккаунтов с её показом.

Теорема · Суммы степеней#

Для конечного простого двудольного графа поддержки

∑u∈Udu=∣E∣=∑i∈Idi.\sum_{u\in\mathcal U}d_u=|E| =\sum_{i\in\mathcal I}d_i.u∈U∑​du​=∣E∣=i∈I∑​di​.
Доказательство

Каждое ребро имеет ровно один конец среди аккаунтов и добавляет единицу ровно одному слагаемому первой суммы. Поэтому первая сумма считает каждое ребро один раз. То же рассуждение для конца среди статей даёт второе равенство.

□

Проверка даёт удобный инвариант: если степени посчитаны по различным соседям, обе суммы должны совпасть с числом различных пар. Если вместо степени аккаунта использовано число его показов, получится сумма NNN, которая может быть намного больше.

Аккаунт u_burst имеет 240 показов и степень 1. Большой объём повторных экспозиций не создаёт широкую поддержку для изучения разнообразных предпочтений. Обратно, степень 20 сама по себе не сообщает число повторов и качество ответа.

Построение поддержки​

metrics.py — функция support
def support(rows, predicate=lambda row: True):
    return {(row.user_id, row.item_id) for row in rows if predicate(row)}


Множество Python объединяет одинаковые пары. Без предиката получаем EEE. Вызов support(rows, lambda row: row.label == 1) даёт PPP. Для None сравнение с 1 ложно: это означает лишь отсутствие наблюдаемой единицы при построении PPP, а не преобразование неизвестной метки в ноль.

Ожидаемая стоимость построения множества — O(N)O(N)O(N) при обычном предположении о хеш-таблице, память — O(∣E∣)O(|E|)O(∣E∣). На больших данных та же семантика может быть реализована через SELECT DISTINCT user_id, item_id или разреженную структуру с явным правилом объединения повторов. Связь счётчиков и маски мы уже рассматривали в главе о sparse-данных.

Холодные сущности и границы реестра​

Слово «холодный» зависит от сигнала и момента. Статья без показов, статья с показами без кликов и статья без прошлых положительных действий — три разных режима. Наличие контента может дать информацию о статье даже при нулевой collaborative-поддержке.

Восемь аккаунтов без показов исчезли бы из реестра, построенного только по журналу. Две статьи без показов исчезли бы аналогично. После такого удаления плотность изменилась бы без появления новых связей. Поэтому рядом с плотностью сохраняются размеры полных и наблюдаемых реестров и определение поддержки.

Если каталог получен из текущего снимка, а события — за долгий прошлый период, он способен включать будущие объекты и исключать уже удалённые. Для исторической интерпретации нужно согласовать границы реестра с периодом, используя введённую ранее историю доступности.

Упражнения​

Упражнение · Повторы не создают поддержку#

Десять аккаунтов и пять статей образуют прямоугольник из 50 пар. В журнале сто показов, но только двадцать различных пар. Чему равны плотность показовой поддержки и среднее число показов на пару полного прямоугольника?

Разбор

Плотность равна 20/50=0,420/50=0{,}420/50=0,4, среднее число показов на пару — 100/50=2100/50=2100/50=2. Число 2 не является допустимой плотностью бинарной матрицы. Среднее на уже показанную пару отдельно равно 100/20=5100/20=5100/20=5.

Упражнение · Удалённые нули#

В реестре четыре аккаунта и четыре статьи, наблюдаются четыре разные пары. После удаления двух аккаунтов и двух статей без рёбер осталось то же множество пар. Как изменились плотность и число наблюдений?

Разбор

Плотность выросла с 4/16=25%4/16=25\%4/16=25% до 4/4=100%4/4=100\%4/4=100%. Число пар осталось 4. Изменение плотности вызвано уменьшением области определения; оно не свидетельствует о получении новых наблюдений.
