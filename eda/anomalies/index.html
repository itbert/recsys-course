Аномалии и качество измерения

Подозрительное наблюдение требует объяснения​

Большое число событий может означать активного пользователя, общий аккаунт, автоматизированный трафик, тестовый клиент или дефект логирования. Сам размер счётчика не выбирает одно из этих объяснений. Особенно опасен автоматический порог в данных с выраженной неоднородностью активности.

В разделе NIST о выбросах различаются пометка потенциального выброса, устойчивый анализ и установление его характера. Для логов рекомендаций важно дополнительно проверить семантику событий и источник. Статистический тест на выброс с предпосылкой приблизительной нормальности нельзя автоматически переносить на любой счётчик активности.

Определение · Диагностический флаг#

Диагностический флаг — результат заранее описанного правила, выделяющего наблюдения для проверки. Без дополнительного основания он не является меткой ошибочности данных, бот-активности или недопустимости пользователя.

Несколько признаков одного аккаунта​

Для представленного аккаунта рассмотрим число показов nun_unu​, число разных статей dud_udu​, отношение du/nud_u/n_udu​/nu​ и промежутки между соседними показами в отсортированном времени действия:

Δu,j=tu,(j+1)−tu,(j).\Delta_{u,j}=t_{u,(j+1)}-t_{u,(j)}.Δu,j​=tu,(j+1)​−tu,(j)​.

Малое du/nud_u/n_udu​/nu​ означает сильную повторяемость объектов, но она может быть естественной для некоторых сценариев. Малые промежутки могут указывать на пакетную регистрацию или высокочастотный клиентский процесс; нули также могут возникнуть из-за дискретности временной отметки. Эти признаки интерпретируются вместе с единицами и устройством источника.

В нашем наборе u_burst имеет 240 показов, одну статью и медианный промежуток одну секунду. Учебное правило выделяет аккаунт при одновременном выполнении nu≥200n_u\ge200nu​≥200, медианного промежутка не более двух секунд и du/nu≤0,02d_u/n_u\le0{,}02du​/nu​≤0,02. Пороги выбраны для демонстрации конкретного сконструированного случая; их диагностическая точность на реальных пользователях не измерялась.

Устойчивые шкалы и вырожденные случаи​

Для числового признака иногда используют медиану и медианное абсолютное отклонение

MAD=Q∣x−Qx(0,5)∣(0,5).\mathrm{MAD}=Q_{|x-Q_x(0{,}5)|}(0{,}5).MAD=Q∣x−Qx​(0,5)∣​(0,5).

Это медиана модулей отклонений от выбранной медианы. У набора [1,1,1,10][1,1,1,10][1,1,1,10] MAD равен 0. Деление отклонения на MAD в таком случае не определено. Нулевой масштаб не разрешает объявить все отличающиеся значения ошибками; нужно другое диагностическое правило и понимание дискретности признака.

Порог по IQR, верхнему квантилю или MAD также не устанавливает семантическую причину. Обнаружение необычности относительно среза и доказательство дефекта измерения — разные результаты. Если срезы имеют разные допустимые режимы активности, единый глобальный порог может систематически выделять один нормальный сегмент.

Код диагностического профиля​

diagnostics.py — профили аккаунтов
"""Диагностические признаки и итеративный k-core, без классификации ботов."""
from collections import Counter, defaultdict
from metrics import quantile


def user_profiles(rows):
    groups = defaultdict(list)
    for row in rows:
        groups[row.user_id].append(row)
    result = []
    for user, events in sorted(groups.items()):
        times = sorted(row.event_time for row in events)
        gaps = [right - left for left, right in zip(times, times[1:])]
        unique = len({row.item_id for row in events})
        median_gap = quantile(gaps, .5) if gaps else None
        ratio = unique / len(events)
        flag = len(events) >= 200 and median_gap is not None and median_gap <= 2 and ratio <= .02
        result.append({"user_id": user, "impressions": len(events), "unique_items": unique,
                       "median_gap_seconds": median_gap, "unique_per_impression": ratio,
                       "review_flag": flag})
    return result


Строки группируются по аккаунту. Внутри группы сортируется время; zip(times, times[1:]) образует соседние пары. Для единственного события промежутков нет, и медиана сохраняется как None. Множество статей отделяет разнообразие от общего числа показов.

review_flag сохраняется в выходе, но ни одна строка не удаляется. Это позволяет сначала просмотреть профиль, выяснить причину и лишь затем выбрать действие. Сортировка времён даёт суммарную стоимость не хуже O(Nlog⁡N)O(N\log N)O(NlogN) для всех групп, остальные проходы линейны по объёму данных.

Временные характеристики считаются по event_time. Для диагностики транспорта отдельно рассматривается received_at-event_time. Подмена одной оси другой могла бы превратить пачку поздних доставок в ложный всплеск пользовательской активности.

Анализ чувствительности к исключению​

Если временно убрать u_burst, останется 2226 показов и прежние 1088 показов с кликом. Описательная доля вырастет с 1088/2466≈44,12%1088/2466\approx44{,}12\%1088/2466≈44,12% до 1088/2226≈48,88%1088/2226\approx48{,}88\%1088/2226≈48,88%.

Это чувствительность результата к составу таблицы. Модель при таком расчёте не улучшалась. Исключение может быть оправдано после установленного нарушения источника; высокий новый показатель сам по себе не является основанием для удаления. В отчёте сохраняются оба варианта, правило выделения и доля исключённых единиц.

Обрезка больших значений до порога, иногда называемая винзоризацией, также меняет характеристику. Среднее после обрезки описывает преобразованные значения. Его нельзя без пояснения подставить вместо среднего исходного времени или исходного числа действий.

Упражнения​

Упражнение · Порог не равен диагнозу#

Аккаунт имеет тысячу показов в сутки. Назовите два объяснения, совместимых с корректным человеческим использованием или устройством измерения, и два направления проверки перед объявлением его ботом.

Разбор

Совместимы, например, общий аккаунт и автоматическая регистрация множества карточек интерфейсом при человеческом просмотре. Проверяются семантика показа и производитель, точность времени, сессии, запросы и независимые записи. Одного счётчика недостаточно, чтобы выбрать причину или оценить вероятность бот-активности.

Упражнение · Одинаковый час получения#

Сотня событий имеет времена действия, равномерно распределённые по суткам, но доставлена за одну минуту после восстановления связи. Что покажут два графика и какой из них описывает доставку?

Разбор

График по времени действия распределит зарегистрированные действия по суткам; по времени получения покажет минутный всплеск. Второй описывает доставку. При восстановлении исторического знания эти события становятся доступны только после получения, несмотря на более ранние действия.
