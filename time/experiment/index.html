Воспроизводимый прогноз и границы модели

Фиксируем вопрос до расчёта​

Есть 168 значений синтетического вещественного индекса из первой главы. После получения дней 0–139 нужно одновременно спрогнозировать дни 140–167. Настройки методов и момент отсечения фиксированы; значения последних 28 дней используются только для вычисления ошибок.

Это один учебный временной срез. Он проверяет реализацию и смысл прогноза. Рекомендательные выборки с пользователями, объектами, доступными кандидатами, задержками и выбором модели потребуют более полного протокола следующей части.

Индекс имеет недельную синусоидальную компоненту и линейный тренд по построению. Поэтому гипотеза гармонической регрессии здесь особенно близка к механизму генератора. Её преимущество в этом примере не устанавливает универсального порядка методов на пользовательских данных.

Модели и доступная информация​

Сравниваются последнее значение, drift, сезонный baseline, гармоническая регрессия, AR(7), частный ARIMA(1,1,0), SES, Holt и аддитивный Holt–Winters. Период равен 7. Для сглаживания используются заранее заданные α=0,3\alpha=0{,}3α=0,3, β∗=0,1\beta^*=0{,}1β∗=0,1, γ=0,2\gamma=0{,}2γ=0,2, незатухающий тренд там, где он присутствует.

Параметры регрессии и AR оцениваются только по 140 прошлым значениям. Будущие синус и косинус вычисляются по известному календарному индексу. Истинные будущие остатки и средняя компонента, сохранённые генератором для проверки, в модели не передаются.

Условные ошибки MA-части в общей рекурсии были введены отдельно; эксперимент не объявляется сравнением всех порядков ARIMA или полноценной процедурой максимального правдоподобия ETS. Он использует конкретные реализации с явной инициализацией.

Ошибки на горизонте​

Для H=28H=28H=28 и eh=y139+h−y^139+h∣139e_h=y_{139+h}-\widehat y_{139+h\mid139}eh​=y139+h​−y​139+h∣139​ рассчитываем

MAE=1H∑h=1H∣eh∣,RMSE=1H∑h=1Heh2.\mathrm{MAE}=\frac1H\sum_{h=1}^H|e_h|,\qquad \mathrm{RMSE}=\sqrt{\frac1H\sum_{h=1}^He_h^2}.MAE=H1​h=1∑H​∣eh​∣,RMSE=H1​h=1∑H​eh2​​.

Обе величины имеют единицу целевого индекса. RMSE сильнее увеличивается при больших ошибках. Среднее по горизонтам является характеристикой именно этого набора горизонтов; более дальние прогнозы не превращаются в независимые повторения одного эксперимента.

Подгонять настройки после просмотра этого же теста и продолжать называть его независимой итоговой проверкой было бы изменением протокола.

Полный сборщик​

experiment.py
"""Один фиксированный учебный прогноз: origin=140, horizon=28, без настройки по тесту."""
import hashlib
import json
from pathlib import Path
import platform
import numpy as np
from autoregression import ar_forecast, arima_p10, baseline, fit_ar, is_stable
from dependence import sample_acf
from events import hawkes_log_likelihood
from series import generate, harmonic_fit, vector
from smoothing import holt, holt_winters, ses


def run(values=None, origin=140):
    values = vector(generate()["index"] if values is None else values)
    if type(origin) is not int or not 15 <= origin < len(values):
        raise ValueError("Нужен допустимый момент отсечения")
    train, target = values[:origin], values[origin:]
    horizon = len(target)
    ar = fit_ar(train, 7)
    harmonic = harmonic_fit(train)
    future = np.arange(origin, len(values))
    future_design = np.column_stack([np.ones(horizon), future,
                                     np.sin(2*np.pi*future/7), np.cos(2*np.pi*future/7)])
    forecasts = {
        "last": baseline(train, horizon), "drift": baseline(train, horizon, "drift"),
        "seasonal": baseline(train, horizon, "seasonal"),
        "harmonic": future_design@harmonic["coefficients"],
        "ar7": ar_forecast(ar, train, horizon), "arima110": arima_p10(train, horizon, 1),
        "ses": ses(train, horizon), "holt": holt(train, horizon),
        "holt_winters": holt_winters(train, horizon),
    }
    scores = {}
    for name, forecast in forecasts.items():
        error = target-forecast
        scores[name] = {"mae": float(np.mean(np.abs(error))), "rmse": float(np.sqrt(np.mean(error**2)))}
    source_files = ("series.py", "dependence.py", "autoregression.py", "smoothing.py",
                    "state_space.py", "events.py", "experiment.py")
    return {
        "manifest": {"synthetic": True, "target": "real-valued activity index, not event count",
                     "python": platform.python_version(), "numpy": np.__version__,
                     "seed": 20261117, "n": len(values), "origin": origin, "horizon": horizon,
                     "data_sha256": hashlib.sha256(values.astype("<f8").tobytes()).hexdigest(),
                     "source_sha256": {name: hashlib.sha256(Path(__file__).with_name(name).read_bytes()).hexdigest()
                                       for name in source_files}},
        "scores": scores, "forecasts": {name: forecast.tolist() for name, forecast in forecasts.items()},
        "ar7": {"intercept": ar["intercept"], "phi": ar["phi"].tolist(), "stable": is_stable(ar["phi"]),
                "training_residual_acf": sample_acf(ar["residuals"], 7)},
        "hawkes_example": hawkes_log_likelihood([1, 2, 2.5, 4], 6),
    }


if __name__ == "__main__":
    report = run()
    Path(__file__).with_name("report.json").write_text(json.dumps(report, ensure_ascii=False, indent=2, allow_nan=False)+"\n")
    print(json.dumps(report["scores"], ensure_ascii=False, indent=2))

Для повторения сохраните последовательно приведённые блоки в семь файлов: series.py, dependence.py, autoregression.py, smoothing.py, state_space.py, events.py и этот experiment.py. Все они лежат в одной папке. Установленные NumPy 2.5.5 и Python 3.13.3 соответствуют проверенному окружению; исходные массивы генерируются без скачивания данных. python3 experiment.py сохраняет report.json.

Массив разбивается один раз до оценивания. В прогнозных функциях остаётся только train. Регрессионные будущие признаки зависят от номера дня, а не от будущего ответа. Словарь scores вычисляется после построения всех прогнозов.

Хеш фиксирует байты целевого ряда в явном формате little-endian float64. Дополнительно сохраняются версии, seed, отсечение, горизонт и байты семи модулей. Для повторения всей среды используются локальные pins и lock из математической части. Хеш идентифицирует артефакт, а не доказывает правильность модели.

Что проверено независимо​

Временные границы и фильтры проверены ручными последовательностями. Формула дисперсии среднего сопоставлена с прямой ковариационной матрицей. Нелинейная зависимость белого шума проверена точным перебором конечных исходов. AR и интегрированный прогноз сопоставлены с динамикой в рациональных дробях; сезонное продолжение — с точной линией и гармоникой.

Фильтр Калмана сопоставлен с условным распределением полного гауссовского вектора, интеграл Hawkes — с квадратурой SciPy. Рекурсия физического затухания проверена прямой суммой вкладов, переходы — композицией интервалов. Интерфейсные модели сравниваются с Python на сетке параметров.

Отдельная проверка меняет все будущие значения, оставляя прошлые неизменными. Прогнозы сохраняются, ошибки меняются. Это подтверждает отсутствие такого прямого пути будущих ответов в данном коде; проверка не заменяет анализ остальных источников утечки в реальном эксперименте.

Границы вывода​

Белые по ACF остатки не доказывают независимости. Устойчивые AR-коэффициенты не доказывают сохранения режима. Хорошая ошибка агрегированного временного ряда не устанавливает качество индивидуального ранжирования. Кластеризация событий не является сама по себе причинным эффектом предыдущего действия.

Для реального применения нужно определить целевой объект, доступную историю, механизм измерения, варианты изменения режима и процедуру проверки. Связь с решениями рекомендательной системы будет строиться на этих условиях, а не на переносе удачной синтетической метрики.

Упражнения​

Упражнение · Будущий трафик как признак#

Модель прогноза кликов использует фактическое число показов завтрашнего дня, а результат описан как прогноз из сегодняшнего момента. Когда такая постановка допустима и что требуется изменить в обычном прогнозе?

Разбор

Она допустима как условный расчёт при заранее действительно известном плане экспозиции либо как явно заданный сценарий. Если число показов неизвестно, нужен его доступный прогноз или совместная модель неопределённости. Подстановка реализовавшегося будущего значения создаёт другое информационное условие.

Упражнение · Победа на одном участке#

Метод A имеет меньшую RMSE, чем B, на одном 28-дневном участке. Какие сведения нужны, чтобы перейти от этого описательного факта к обоснованному сравнению методов для целевой задачи?

Разбор

Нужны целевая популяция рядов и периодов, правило выбора параметров, допустимая история, повторные временные срезы или другой обоснованный дизайн, анализ зависимости ошибок и неопределённости. Один участок поддерживает только утверждение о вычисленных ошибках конкретных процедур на нём.
