User-kNN для неявных сигналов

От соседей к кандидатам​

Для пользователя uuu есть история PuP_uPu​ и набор обучающих профилей PvP_vPv​. Фиксируем неотрицательное сходство, выбираем не более LLL обучающих соседей с положительными весами и исключаем сам профиль uuu. Бинарный скоринг вычисляет

s(u,i)=∑v∈NL(u)w(u,v) 1{i∈Pv}.s(u,i)=\sum_{v\in N_L(u)} w(u,v)\,\mathbf1\{i\in P_v\}.s(u,i)=v∈NL​(u)∑​w(u,v)1{i∈Pv​}.

После накопления ограничиваем кандидатов разрешённой областью и исключаем ранее потреблённое, когда это входит в контракт. Веса реализованного правила — косинус (обычный или со взвешенными координатами) с поправкой по общим объектам.

Один набор соседей используется для всех целей. Если поделить все scores одного пользователя на ∑v∈NL(u)w(u,v)\sum_{v\in N_L(u)}w(u,v)∑v∈NL​(u)​w(u,v), общий порядок сохранится при положительном знаменателе. Если делить отдельно на сумму голосов за сам объект, любой объект с положительными голосами получит 1. Такая нормировка бессмысленна для бинарной суммы единиц.

Ручной проход​

У пользователя U история {a,b}\{a,b\}{a,b}. У V профиль {a,b,x}\{a,b,x\}{a,b,x}, у W — {b,y,z}\{b,y,z\}{b,y,z}, у Z — {c,x}\{c,x\}{c,x}. При обычном косинусе веса V и W равны 2/62/\sqrt62/6​ и 1/61/\sqrt61/6​, а Z не участвует. При L=2L=2L=2 объект x получает 2/62/\sqrt62/6​, y и z получают 1/61/\sqrt61/6​. Если x недоступен, лучшим допустимым будет y или z по ключу равенств. Аналогия с ближайшими соседями в ML полезна, но обучающей единицей здесь является профиль, а прогноз строится для множества новых объектов.

Лемма · Каких соседей достаточно рассмотреть#

При неотрицательных координатных весах и отборе только строго положительных косинусов достаточно рассмотреть объединение posting lists объектов из истории запроса.

Доказательство

Вне этого объединения множество общих координат пусто, поэтому скалярное произведение равно нулю. Внутри объединения накопление по объектам даёт ту же сумму скалярного произведения, что прямой обход полных векторов. Заранее сохранённые нормы и одинаковое правило сортировки дают тот же top-LLL.

□
users.py
"""User-kNN для бинарных профилей и перевёрнутого индекса."""
from collections import Counter, defaultdict
import math


def fit_users(profiles, inverse_frequency=False):
    postings = defaultdict(list)
    for user, items in sorted(profiles.items()):
        for item in sorted(items):
            postings[item].append(user)
    # Вес в скалярном произведении. Координата имеет масштаб sqrt(weight).
    weights = {
        i: (1 + math.log((1 + len(profiles)) / (1 + len(users)))
            if inverse_frequency else 1.0)
        for i, users in postings.items()
    }
    norms = {u: math.sqrt(math.fsum(weights[i] for i in items))
             for u, items in profiles.items()}
    return profiles, dict(postings), weights, norms


def neighbors(history, index, n_neighbors, shrink=4.0, exclude_user=None):
    if n_neighbors < 1 or not math.isfinite(shrink) or shrink < 0:
        raise ValueError("Проверьте число соседей и shrinkage")
    _, postings, weights, norms = index
    dots = defaultdict(float)
    common = Counter()
    items = sorted(set(history) & postings.keys())
    query_norm = math.sqrt(math.fsum(weights[i] for i in items))
    for i in items:
        for u in postings[i]:
            if u != exclude_user:
                dots[u] += weights[i]
                common[u] += 1
    # Если пересечений нет, dots пуст и деления на ноль нет.
    scores = [(u, dot / (query_norm * norms[u]) * common[u] / (common[u] + shrink))
              for u, dot in dots.items()]
    return sorted(scores, key=lambda pair: (-pair[1], pair[0]))[:n_neighbors]


def user_scores(history, index, n_neighbors, shrink=4.0, exclude_user=None):
    profiles, _, _, _ = index
    result = defaultdict(float)
    for user, weight in neighbors(history, index, n_neighbors, shrink, exclude_user):
        for item in sorted(profiles[user]):
            result[item] += weight
    return dict(result)

fit_users строит таблицу «объект → пользователи» и сохраняет норму каждого профиля. neighbors накапливает числители только по пересечению с индексированной областью. Объект, отсутствующий в словаре индекса, не попадает и в норму запроса. Для понижения веса популярных координат используется вариант inverse user frequency. Обоснование весов приведено в главе о поправках.

Границы способа​

У нового пользователя без истории сумма пуста. Длинный профиль повышает число затронутых posting lists и может ухудшить специфичность соседства. Две модели с одинаковым top-LLL, но разными весами могут дать разные рекомендации из-за суммирования голосов. Совпадения с одними и теми же известными объектами сигнализируют поведение в этом наборе данных. Для оценки на другой аудитории требуется собственный отложенный срез.

При прогнозе явного рейтинга часто выбирают top-LLL отдельно среди пользователей, оценивших именно цель. Это позволяет опереться на лучший доступный сигнал для данной пары. Такую модель нельзя воспроизвести, один раз усекши общий список соседей. В главе о рейтингах используются два отдельные способа построения окрестности.

Упражнение · Изменился L

В примере U увеличим LLL с 1 до 2. Что произойдёт со scores x и y без нормировки?

Разбор

У x останется 2/62/\sqrt62/6​ от V. y получит 1/61/\sqrt61/6​ от W. Если пригодных кандидатов у одного соседа мало, второй может увеличить покрытие выдачи.

Упражнение · Вне словаря

Запрос содержит a и неизвестный в обучении b. Как в этом коде повлияет b на вычисление косинуса? Можно ли принять другое правило?

Разбор

b не входит в пространство координат индекса и не влияет на норму. Можно расширить пространство фиксированным весом новых координат, тогда b увеличит норму запроса и уменьшит все оценки для данного пользователя. Сравнивать направленность эффекта надо при явно выбранном пространстве.
