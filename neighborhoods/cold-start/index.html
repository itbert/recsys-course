Холодный старт и резервная выдача

Когда исчезает сигнал​

Новый пользовательПустая историяГлобальная или контекстная популярность
Пользователь с короткой историейМало общих координатСглаживание, более широкий источник кандидатов

Исчерпаны кандидаты графаTop-LLL и фильтрация удалили дугиРезерв из допустимого каталога и измерение его вклада

Термин cold start всегда привязываем к моменту обучения. Объект может быть новым пользователю, хотя глобальная история по нему богата. Объект без событий в одном регионе может иметь данные в другом. При оценке определяем отдельно «пустой пользовательский профиль в срезе», «нулевая поддержка объекта в срезе» и «пустой результат после фильтрации».

Резерв влияет на измерение системы​

В нашем правиле сначала ставятся допустимые объекты с положительным сигналом, затем недостающие позиции заполняются глобальной популярностью. При равном сигнале популярность также служит вторичным ключом. Это удобно для воспроизводимости и сравнения методов. При пустом профиле все соседские правила выдают те же списки, что popularity. Поэтому NDCG на холодном пользовательском срезе совпадает у всех этих алгоритмов. В контекстном fallback могли бы использовать тип запроса, язык и регион при наличии достаточной прошлой статистики. Слишком узкая группа требует возврата к более широкой.

У общего score разных методов могут быть несопоставимые масштабы. Если задача смешивает источники, фиксируют нормировку, модель калибровки или порядок их применения. Например, смешивать по s=γsneighbors+(1−γ)spopulars=\gamma s_{\rm neighbors}+(1-\gamma)s_{\rm popular}s=γsneighbors​+(1−γ)spopular​ имеет смысл после определения масштабов. Резерв по приоритету источника задаёт лексикографическое правило и не требует трактовать частоту и сходство как одну вероятность.

Для нового объекта граф не создаёт положительного сигнала. Если заполнение по популярности всегда исчерпывается известными объектами, новый объект может встретиться в каталоге и ни разу не появиться в выдаче. Знание тематических атрибутов даёт ещё один источник. Контролируемое исследование новых объектов требует правил назначения и логирования вероятностей. Дальнейшие части рассмотрят контент и бандитов.

Диагностика​

Рядом с общей NDCG полезно сообщать качество по длине исторического профиля, долю запросов с пустым кандидатом, долю позиций fallback, покрытие новых объектов и частоту недопустимых результатов. Публикуйте число запросов в каждом срезе. Измерение только на пользователях, для которых алгоритм уже нашёл много соседей, завышает применимость метода при сравнении со всей аудиторией.

Упражнение · Фильтр всей области

Запрос допускает A, B и C. У пользователя в истории A, протокол запрещает повторы. Граф вернул только A, глобальный порядок A, C, B. Какова выдача при K=3K=3K=3?

Разбор

После фильтра граф пуст. Резерв заполняет C и B. Третья позиция остаётся пустой, так как осталось только два уникальных допустимых объекта. Увеличение глубины не устраняет ограничения.

Упражнение · Выбор правильного среза

Новый объект получил ноль показов соседской модели. Почему из этого нельзя сделать вывод о низкой релевантности?

Разбор

В графе у объекта нет наблюдаемых связей, и популярность не вывела его в top-KKK. Ноль характеризует решение системы. О релевантности нужны допустимые наблюдения, независимая разметка или эксперимент.
