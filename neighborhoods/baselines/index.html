Случайная выдача, популярность и свежесть

Случайный список и глобальная частота​

Равномерно выбираем без возвращения KKK объектов из допустимой области размера NNN при K≤NK\le NK≤N. Каждый входит с вероятностью K/NK/NK/N. Для R>0R>0R>0 позитивов ожидаемая Recall@K равна K/NK/NK/N, поскольку ожидаемое число попаданий равно RK/NRK/NRK/N. При разных NqN_qNq​ сначала вычисляется эта величина на каждом запросе, затем применяется выбранное усреднение. На конечном прогоне результат случайного baseline зависит от seed.

Для популярности вводим ci=∑e∈HT1{ie=i}c_i=\sum_{e\in\mathcal H_T}\mathbf1\{i_e=i\}ci​=∑e∈HT​​1{ie​=i}. Если цель — вероятность успеха, при наличии зрелых показов можно оценить p^i=si/ni\hat p_i=s_i/n_ip^​i​=si​/ni​, где nin_ini​ — число показов, sis_isi​ — число единиц. Например, два исхода из двух показов дают оценку 1, а 40 из 100 дают 0,4. Счётчики успехов и доли упорядочивают эти объекты противоположно. В практической модели с малыми выборками можно использовать

p~i=si+αp0ni+α,α>0.\widetilde p_i=\frac{s_i+\alpha p_0}{n_i+\alpha}, \qquad \alpha>0.p​i​=ni​+αsi​+αp0​​,α>0.

Это взвешенное среднее доли и общей частоты p0p_0p0​, вычисленной в прошлом. Для ni=0n_i=0ni​=0 оно равно p0p_0p0​. При биномиальной модели и 0<p0<10<p_0<10<p0​<1 выражение также является апостериорным средним beta-приора с параметрами αp0\alpha p_0αp0​ и α(1−p0)\alpha(1-p_0)α(1−p0​). Показанные исходы относятся к исторической политике. Разная экспозиция и положение объектов могут менять оценённую долю.

Экспоненциальное затухание​

Используем положительный период полураспада hhh и вес 2−(T−te)/h2^{-(T-t_e)/h}2−(T−te​)/h.

Ci(T)=∑e∈HT: ie=i2−(T−te)/h.C_i(T)=\sum_{e\in\mathcal H_T:\,i_e=i} 2^{-(T-t_e)/h}.Ci​(T)=e∈HT​:ie​=i∑​2−(T−te​)/h.

Слагаемое в возрасте hhh вносит половину веса только что произошедшего события. Возраст изменяется по времени действия, а включение в статистику по доступности. Запоздалое событие при появлении получает вес по своему фактическому возрасту. Для просмотра с неполным логом более свежая популярность может быть занижена из-за недоставленных событий, поэтому последние интервалы проверяют на полноту.

Лемма · Обновление без пересчёта всей истории#

Для T′>TT'>TT′>T при добавлении событий без исправлений старых записей Ci(T′)=2−(T′−T)/hCi(T)+∑e∈HT′∖HT:ie=i2−(T′−te)/hC_i(T')=2^{-(T'-T)/h}C_i(T)+\sum_{e\in\mathcal H_{T'}\setminus\mathcal H_T:i_e=i}2^{-(T'-t_e)/h}Ci​(T′)=2−(T′−T)/hCi​(T)+∑e∈HT′​∖HT​:ie​=i​2−(T′−te​)/h.

Доказательство

Вклад любого старого события умножается на один и тот же множитель, поскольку T′−te=(T′−T)+(T−te)T'-t_e=(T'-T)+(T-t_e)T′−te​=(T′−T)+(T−te​). Добавленные записи учитываются по их временам действия. При отсутствии добавлений этот множитель сохраняет весь порядок популярности.

□

В отличие от жёсткого окна, веса уменьшаются непрерывно по возрасту. Жёсткое окно можно предпочесть, если точно определяется момент устаревания сигнала. Оба варианта выбираются на прошлых блоках проверки. Последний глобальный подсчёт на всём датасете создал бы утечку даже без признаков пользователя.

baselines.py
"""Базовые модели и общий контракт выдачи."""
from collections import Counter, defaultdict
from dataclasses import dataclass
import math
import random


@dataclass(frozen=True)
class Event:
    user: int
    item: int
    t: int
    available: int


def snapshot(events, cutoff):
    return [e for e in events if e.t < cutoff and e.available <= cutoff]


def popularity(events):
    return Counter(e.item for e in events)


def decayed_popularity(events, time, half_life):
    if not math.isfinite(half_life) or half_life <= 0:
        raise ValueError("Требуется положительный конечный период полураспада")
    result = defaultdict(float)
    for e in snapshot(events, time):
        result[e.item] += math.exp2(-(time - e.t) / half_life)
    return dict(result)


def smoothed_rates(counts, prior, strength):
    """counts[item] = (положительные исходы, завершённые показы)."""
    if not 0 <= prior <= 1 or not math.isfinite(strength) or strength <= 0:
        raise ValueError("Проверьте параметры сглаживания")
    result = {}
    for item, (successes, total) in counts.items():
        if not 0 <= successes <= total:
            raise ValueError("Проверьте число исходов и показов")
        result[item] = (successes + strength * prior) / (total + strength)
    return result


def random_list(candidates, k, rng):
    pool = sorted(set(candidates))
    if k < 0:
        raise ValueError("K должно быть неотрицательным")
    return rng.sample(pool, min(k, len(pool)))


def recommend(candidates, evidence, fallback, k):
    """Сначала кандидаты с положительным сигналом, затем резерв по популярности."""
    if k < 0:
        raise ValueError("K должно быть неотрицательным")

    def key(item):
        score = evidence.get(item, 0)
        count = fallback.get(item, 0)
        if not math.isfinite(score) or not math.isfinite(count):
            raise ValueError("Требуются конечные scores")
        return (-max(score, 0), -count, item)

    return sorted(set(candidates), key=key)[:k]

snapshot фильтрует действия и доставки, popularity получает уже допустимые записи, а decayed_popularity дополнительно применяет тот же срез. recommend сортирует по положительному соседскому score, затем по числу событий и ID. Для популярности и затухания подаём соответствующие глобальные scores. Для production достаточно один раз отсортировать глобальный список при обновлении и пропускать запрещённые объекты в запросе. Подсчёт на EEE событиях требует O(E)O(E)O(E) обновлений счётчиков.
