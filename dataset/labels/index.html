Метки, задержка и созревание когорты

Ответ после решения​

Положительная метка определяется правилом, а не названием действия. Для показа iii в запросе qqq фиксируем конечный горизонт HHH и явную атрибуцию:

Yqi(H)=1{∃e:parent⁡(e)=(q,i), ke=finish, tq≤te<tq+H}.Y_{qi}^{(H)}=\mathbf1\{\exists e:\operatorname{parent}(e)=(q,i),\ k_e=\text{finish},\ t_q\le t_e<t_q+H\}.Yqi(H)​=1{∃e:parent(e)=(q,i), ke​=finish, tq​≤te​<tq​+H}.

Завершение ровно в tq+Ht_q+Htq​+H не входит. Цель «завершил за шесть минут» отличается от «когда-либо завершит». Увеличение горизонта меняет задачу, а не только уменьшает число пропусков.

Пусть ccc — момент снимка для меток. Уже доставленная единица может быть известна до конца окна. Отсутствие доставленной единицы до созревания не является нулём.

Теорема · Достаточная граница готовности#

Предположим полную регистрацию всех релевантных исходов наблюдаемой строки и гарантированную задержку 0≤ae−te≤L0\le a_e-t_e\le L0≤ae​−te​≤L. При c≥tq+H+Lc\ge t_q+H+Lc≥tq​+H+L все исходы из полуоткрытого окна уже доступны. Поэтому отсутствие подходящего исхода позволяет поставить Yqi(H)=0Y_{qi}^{(H)}=0Yqi(H)​=0.

Доказательство

Для исхода внутри окна te<tq+Ht_e<t_q+Hte​<tq​+H, следовательно ae≤te+L<tq+H+L≤ca_e\le t_e+L<t_q+H+L\le cae​≤te​+L<tq​+H+L≤c. Все подходящие исходы доставлены. Полнота регистрации исключает невидимые релевантные события. Граница достаточна; конкретная единица может быть известна раньше.

□

Максимальная задержка наблюдавшихся событий не доказывает глобальную границу LLL и полноту. В реальном источнике это отдельные допущения, договорённости или проверяемые гарантии. При их отсутствии нужно сохранять неопределённость либо строить модель задержки с новыми предпосылками.

Единица уже известна, строка ещё не включается​

В label ниже возвращаются отдельно y, mature, observable и ready_at. Ранний положительный исход даёт y=1, но mature может оставаться ложным. Сборщик обучающей когорты требует зрелости для всех строк независимо от класса.

Если взять все уже известные единицы и только зрелые нули, свежие строки будут отобраны по исходу. При простейшей модели с исходной вероятностью единицы ppp и вероятностью её раннего обнаружения rrr среди свежих строк сохраняются только единицы. Даже если старые строки представлены полностью, добавление такой свежей группы меняет смесь классов. Это не устраняется словом «метки известны».

Наша консервативная альтернатива — целая зрелая когорта. Она уменьшает свежесть данных, зато правило включения не использует раннее наступление исхода. Удаление строк с неполным наблюдением также ограничивает популяцию: результат относится к наблюдаемой части, а не обязательно переносится на исключённых пользователей.

Генератор, каталог и метки​

journal.py
"""Новый синтетический журнал; время в минутах, не продолжение реальных логов."""
import hashlib
import json

HORIZON = 6
MAX_DELAY = 3


def digest(value):
    payload = json.dumps(value, ensure_ascii=False, sort_keys=True,
                         separators=(",", ":"), allow_nan=False).encode()
    return hashlib.sha256(payload).hexdigest()


def contains(start, end, t):
    return start <= t and (end is None or t < end)


def version_at(versions, item, t):
    matches = [v for v in versions if v["item"] == item
               and contains(v["valid_from"], v["valid_to"], t)
               and contains(v["known_from"], v["known_to"], t)]
    if len(matches) > 1:
        raise ValueError("Неоднозначный каталог")
    return matches[0] if matches else None


def candidates(versions, request):
    t = request["t"]
    answer = []
    for item in sorted({v["item"] for v in versions}):
        version = version_at(versions, item, t)
        if version and version["region"] in ("all", request["region"]):
            answer.append(item)
    return answer


def fixture():
    versions = []
    for j, item in enumerate("ABCDEFGH"):
        start = {"C": 30, "D": 60, "F": 100, "G": 150}.get(item, 0)
        versions.append(dict(item=item, revision="v1", topic=j % 3,
                             valid_from=start, valid_to=140 if item == "E" else None,
                             known_from=start, known_to=40 if item == "A" else None,
                             region="north" if item == "H" else "all"))
    versions.append(dict(item="A", revision="v2", topic=2, valid_from=0,
                         valid_to=None, known_from=40, known_to=None, region="all"))
    requests, impressions, actions = [], [], []
    for k in range(96):
        t = 10 + 2 * k
        request = dict(id=f"r{k:03}", user=f"u{(5*k+k//7) % 6}", t=t,
                       received=t, region="north" if k % 2 == 0 else "south")
        requests.append(request)
        pool = candidates(versions, request)
        shown = [pool[k % len(pool)], pool[(k+1) % len(pool)]]
        for slot, item in enumerate(shown):
            imp = dict(id=f"{request['id']}:{slot}", request=request["id"],
                       user=request["user"], item=item, t=t, received=t,
                       observable=k % 19 != 0, slot=slot)
            impressions.append(imp)
            # Положительный исход внутри [t,t+6); иногда — только на правой границе.
            offset = 1 + k % 5 if (k+slot) % 3 == 0 else 6
            if (k+slot) % 3 == 0 or (k+slot) % 11 == 0:
                actions.append(dict(id=f"a{k:03}:{slot}", impression=imp["id"],
                                    user=imp["user"], item=item, t=t+offset,
                                    received=t+offset+(k+slot) % 4, kind="finish"))
    return dict(versions=versions, requests=requests, impressions=impressions,
                actions=actions)


def validate(data):
    for table in ("requests", "impressions", "actions"):
        rows = data[table]
        if len({r["id"] for r in rows}) != len(rows):
            raise ValueError("Повторный ID")
        if any(type(r["t"]) is not int or type(r["received"]) is not int
               or r["received"] < r["t"] for r in rows):
            raise ValueError("Некорректное время")
    requests = {r["id"]: r for r in data["requests"]}
    impressions = {r["id"]: r for r in data["impressions"]}
    for imp in impressions.values():
        request = requests[imp["request"]]
        if (imp["t"], imp["user"]) != (request["t"], request["user"]):
            raise ValueError("Показ не соответствует запросу")
        if imp["item"] not in candidates(data["versions"], request):
            raise ValueError("Показ вне доступного каталога")
    for action in data["actions"]:
        imp = impressions[action["impression"]]
        if (action["user"], action["item"]) != (imp["user"], imp["item"]):
            raise ValueError("Неверная атрибуция")
        if action["t"] < imp["t"] or action["received"]-action["t"] > MAX_DELAY:
            raise ValueError("Нарушена граница доставки или времени исхода")


def label(imp, actions, cutoff, horizon=HORIZON, delay=MAX_DELAY):
    if horizon <= 0 or delay < 0:
        raise ValueError("Неверное окно")
    if imp["received"] > cutoff:
        raise ValueError("Показ ещё не доставлен")
    end = imp["t"] + horizon
    positive = any(a["impression"] == imp["id"] and a["kind"] == "finish"
                   and imp["t"] <= a["t"] < end and a["received"] <= cutoff
                   for a in actions)
    mature = cutoff >= end + delay
    y = 1 if positive else (0 if mature and imp["observable"] else None)
    return dict(y=y, mature=mature, ready_at=end+delay,
                observable=imp["observable"])

fixture создаёт запросы, доступные объекты и показанные пары. Каждое событие имеет устойчивую ссылку на показ. Некоторые завершения намеренно поставлены точно на правую границу: они существуют в истории, но не превращают метку этого показа в единицу. validate проверяет ссылки, уникальность и заявленную задержку в видимых данных. Проверка данных не заменяет внешнюю гарантию, что потерянных событий нет.

label видит только исходы с received <= cutoff. В производственной цепочке до этой функции нужны канонизация повторных доставок и контроль схемы, разобранные в части 3. Новый генератор уже выдаёт канонические ID; повтор отклоняется валидатором, а не считается новым действием.

Модель задержки — другой путь​

Chapelle, 2014 рассматривает обучение при задержанных конверсиях через совместное моделирование вероятности исхода и задержки. Это более содержательное решение, чем автоматическое превращение свежих пропусков в нули, но оно требует допущений о задержке. Здесь модель не реализуется: цель главы — строгая конечная метка и проверяемая зрелость. Развёрнутая delayed-feedback модель появится при изучении задач CTR/CVR.

Упражнение · Снимок до границы

Показ в 10, H=6H=6H=6, L=3L=3L=3. В 18 уже получено завершение с event time 15. Каковы y и mature? Что если завершения нет?

Разбор

При завершении y=1, но mature=False: достаточная граница равна 19. Без завершения y=None. По принятому когортному правилу ни одна из двух строк пока не включается в обучение.

Упражнение · Одинаковая зрелость, разное наблюдение

Два показа достаточно стары; у первого гарантирована полная регистрация, у второго часть событий потеряна. Единиц не видно. Можно ли обоим поставить 0?

Разбор

Только первому. Старость окна не восстанавливает потерянные данные. У второго остаётся неизвестный исход. В нашем эксперименте он исключается с фиксацией сокращённой популяции.
