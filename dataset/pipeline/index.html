Воспроизводимый сборщик обучающих данных

От контракта к исполняемой таблице​

Теперь можно собрать единый pipeline. Сначала задаём единицу и цель, проверяем канонический журнал, затем восстанавливаем историю каждого запроса. Метки рассчитываются на своём снимке, когорты — на своих временных границах. Только после этого выполняются fit преобразований и модели, прогнозы и оценка на полностью созревшей проверке.

Сохраняемый результат​

В новом журнале 96 запросов, 192 показа, 76 завершений и девять версий каталога. При итоговом обучении в 160 восемь уже произошедших показов ещё не зрелы. Среди полностью наблюдаемых и зрелых строк остаётся 134 обучающих показа, из них 44 положительных. Проверочная когорта [160,190)[160,190)[160,190) содержит 28 наблюдаемых строк, из них 10 положительных.

Baseline использует сглаженную обучающую частоту исхода по объекту, strength 2 и prior из train. Отрицательная выборка применяется отдельно как демонстрация экономии таблицы: модель этого эксперимента обучается на полном train, а не на сокращённом. Поэтому в результатах нет скрытой смены весов цели. Качество тоже считается на полном наборе наблюдаемых проверочных показов.

Полный сборщик​

experiment.py
"""Manifest + диагностические fold; последний временной блок — отдельный итоговый."""
import hashlib
import json
from pathlib import Path
import platform
from journal import fixture, validate, digest, candidates, label
from features import history, sql_windows
from protocol import fold
from sampling import retain_rows, sample_items


def run(data=None):
    data = fixture() if data is None else data
    validate(data)
    # Проверка другим движком всех окон, включая пустые.
    expected = [(r["id"], len(h := history(data["actions"], r)),
                 max((a["t"] for a in h), default=None)) for r in data["requests"]]
    assert sql_windows(data) == sorted(expected)
    folds = [fold(data, origin) for origin in (80, 120, 160)]
    summary = []
    for result in folds:
        sampled = retain_rows(result["train"], .25)
        summary.append(dict(origin=result["origin"], score_cutoff=result["score_cutoff"],
                            n_train=len(result["train"]), n_test=len(result["test"]),
                            positives_train=sum(r["y"] for r in result["train"]),
                            positives_test=sum(r["y"] for r in result["test"]),
                            sampled_train=len(sampled), cold_rows=result["cold_rows"],
                            brier=result["brier"], scaler=result["scaler"]))
    request = data["requests"][50]
    pool = candidates(data["versions"], request)
    target = data["impressions"][100]
    draws = sample_items(pool, target["item"], [1]*len(pool), 5)
    # Итоговый score считается на полном наборе показов, не на sampled_train.
    source_files = ("journal.py", "features.py", "sampling.py", "protocol.py", "experiment.py")
    root = Path(__file__).parent
    return dict(manifest=dict(python=platform.python_version(), data_sha256=digest(data),
                             source_sha256={name: hashlib.sha256((root/name).read_bytes()).hexdigest()
                                            for name in source_files},
                             unit="logged impression", time_unit="minute", horizon=6,
                             max_delivery_delay=3, feature_window=24, negative_keep=.25,
                             seed=17, validation_origins=[80,120], final_origin=160),
                counts={key:len(data[key]) for key in data}, folds=summary,
                sampling_example=dict(request=request, pool=pool, excluded=target["item"],
                                      draws=draws),
                pending_at_160=sum(not label(i,data["actions"],160)["mature"]
                                   for i in data["impressions"] if i["t"] < 160))


if __name__ == "__main__":
    result = run()
    Path(__file__).with_name("report.json").write_text(
        json.dumps(result, ensure_ascii=False, indent=2)+"\n")
    print(json.dumps(result, ensure_ascii=False, indent=2))

Для повторения сохраните в одной папке пять опубликованных модулей: journal.py, features.py, sampling.py, protocol.py, experiment.py. Проверено на Python 3.13.3; основная цепочка не требует сторонних пакетов и скачивания данных. Команда python3 experiment.py создаёт report.json рядом со скриптом. SQLite поставляется с Python; его версия относится к конкретной сборке runtime.

run сначала валидирует связи, каталог и задержки, затем сверяет все оконные счётчики с SQLite. fold получает разные снимки для обучения и оценки. Только после построения допустимых таблиц вычисляются статистики модели и потери. Время генерации исходов не служит разрешением подать их в прошлый fit.

Manifest и аудит строки​

Manifest хранит единицу, минуты как шкалу, горизонт 6, гарантию доставки 3, окно истории 24, вероятность отбора нулей 0,25, seed 17, моменты разработки и финала, версию Python, SHA-256 сериализованного журнала и пяти модулей. JSON сериализуется с сортировкой ключей и явными разделителями; NaN запрещены. Хеш кода будет отличаться после содержательного изменения файла, даже если на этом журнале итоговые числа совпали.

Для аудита конкретной строки дополнительно нужны: ID запроса и показа, время решения, использованная версия каталога, происхождение каждого raw-признака, границы целевого окна, снимок метки, статус наблюдения, принадлежность блоку и вероятность технического отбора. В промышленной системе эти связи лучше хранить как lineage или воспроизводимую ссылку на снимок; несколько агрегатных чисел не заменяют их.

Что проверено независимо​

Пройдены 35 проверок Python: ссылки и дубли, каталог и регион, границы исходов, задержки и пропуски, SQL-окна и сессии, неизменность прошлого при добавлении будущего, готовность train, целостность запросов между блоками, нормализация точными дробями, temporal target encoding, полный перебор взвешенной потери, формула Байеса и поддержка отрицательной выборки. Отдельно проверяются модель интерактивных демонстраций и код, доступный читателю в готовом HTML.

Эти проверки покрывают заявленный пример и определённые классы ошибок. Они не доказывают полноту реального логирования, перенос на другую популяцию или отсутствие всех возможных дефектов. При переходе к большим данным сначала сохраняют семантику эталонного сборщика, затем проверяют оптимизированную реализацию на тех же случаях.

Упражнение · Новая партия данных

После добавления более позднего месяца какие артефакты должны измениться, а какие должны остаться прежними для уже зафиксированного прошлого запроса?

Разбор

Изменится хеш полного входа и могут измениться новые train-когорты, словари и модели будущих отсечений. Raw-признаки старого запроса должны сохраниться, если доступная в его момент информация не изменилась. Повтор старого fit на том же историческом снимке тоже должен сохранить обученное состояние; использование более поздних меток изменило бы протокол.

Упражнение · Сокращённый тест

Для ускорения исследователь оставил только известные единицы и 20 случайных непоказанных объектов на запрос. Можно ли назвать полученную оценку качеством на исходной полной таблице показов?

Разбор

Нет. Изменены единицы, область сравнения и смысл отрицательного примера; непоказанные объекты не имеют наблюдаемого бинарного исхода. Даже при известных вероятностях отбора нельзя автоматически перенести поправку аддитивной суммы на нелинейную ranking-метрику. В части 7 эти различия будут сформулированы для конкретных метрик.

Переход к оценке​

Мы получили временно определённые таблицы, допустимые признаки, зрелые метки и воспроизводимые блоки.
