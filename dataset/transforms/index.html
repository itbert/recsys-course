Обучаемые преобразования и кодирование цели

Fit относится ко всему pipeline​

После правильного временного разбиения можно снова открыть путь в будущее через нормализацию, словарь ID, отбор признаков, заполнение пропусков, PCA или embeddings. Каждое преобразование с оценённым состоянием является частью обучения. Для блока с отсечением TTT его состояние строится на разрешённом train и затем применяется к проверке без повторного fit.

Для числового признака xxx используем

μT=1n∑j∈DTxj,sT2=1n∑j∈DT(xj−μT)2,z=x−μTsT.\mu_T=\frac1n\sum_{j\in D_T}x_j,\qquad s_T^2=\frac1n\sum_{j\in D_T}(x_j-\mu_T)^2,\qquad z=\frac{x-\mu_T}{s_T}.μT​=n1​j∈DT​∑​xj​,sT2​=n1​j∈DT​∑​(xj​−μT​)2,z=sT​x−μT​​.

Это масштабирование с делением на nnn, а не несмещённая оценка дисперсии с n−1n-1n−1. Если все значения одинаковы, код берёт scale 1, чтобы преобразование оставалось определено. Для train 0,1,30,1,30,1,3 получаем μ=4/3\mu=4/3μ=4/3, s2=14/9s^2=14/9s2=14/9. Добавление тестового значения 100 к fit изменило бы оба числа.

Словарь и неизвестные значения​

vocabulary создаёт отсортированный словарь только обучающих объектов, индексы начинаются с 1. Для неизвестного ID зарезервирован 0. Числовой индекс не означает величину или близость объекта; модель должна интерпретировать его как категорию.

Нужно отличать неизвестный ID от пропуска, если их смысл различается. Статический классификатор тем, утверждённый до эксперимента, может быть известен заранее. Словарь по всем будущим взаимодействиям — другой источник, сообщающий о будущих сущностях. Для трансдуктивной задачи доступность такого словаря может быть частью контракта, но её нужно заявить явно.

Наличие объектов в train-словаре не определяет их доступность в новом запросе: это было отдельным условием предыдущих глав. В финальном блоке примера есть пять строк с объектами, отсутствующими в train, и они не удаляются. Baseline использует глобальный prior как fallback.

Кодирование цели​

Для объекта iii сглаженная средняя метка может быть записана как

TE⁡i=si+αp0ni+α,α>0,\operatorname{TE}_i=\frac{s_i+\alpha p_0}{n_i+\alpha},\qquad\alpha>0,TEi​=ni​+αsi​+αp0​​,α>0,

где sis_isi​ — сумма известных меток, nin_ini​ — число разрешённых строк, p0p_0p0​ — prior. Это определение сглаживания; для интерпретации как байесовского posterior нужны отдельные модельные предпосылки.

Если единственная строка категории имеет метку 1, несглаженная средняя равна 1 и раскрывает собственный ответ. При случайных уникальных категориях это может дать идеальное обучение без способности предсказывать новые строки.

Теорема · Собственный ответ в среднем категории#

Для фиксированного nin_ini​, prior p0p_0p0​ и остальных меток увеличение собственной бинарной метки строки с 0 до 1 меняет её in-sample кодировку на 1/(ni+α)1/(n_i+\alpha)1/(ni​+α). При α=0\alpha=0α=0 и единственной строке кодировка равна самой метке.

Доказательство

В числителе sis_isi​ увеличивается на 1, знаменатель остаётся тем же. Разность отношений равна 1/(ni+α)1/(n_i+\alpha)1/(ni​+α). При ni=1n_i=1ni​=1, α=0\alpha=0α=0 сумма содержит только собственный ответ.

□

Сглаживание уменьшает, но не исключает прямой доступ к собственной метке. Out-of-fold кодирование оценивает статистику без строк текущего fold. Для будущего сценария случайные folds могут всё ещё включать будущие метки; нужен временной вариант.

В temporal_target_encoding для строки в ttt используются только предыдущие строки с ready_at <= t. Prior фиксирован заранее, по умолчанию 0,5. Если prior тоже оценивается, он должен быть построен на разрешённой информации этого же шага. Исключение собственной строки без фильтра по готовности чужих меток не решает задержку исходов.

Полный модуль протокола​

protocol.py
"""Отбор зрелых когорт, неизменяемое преобразование и простой frozen baseline."""
import math
from journal import label
from features import feature_row


def table(data, start, end, cutoff):
    if start >= end:
        raise ValueError("Пустой интервал запросов")
    requests = {r["id"]: r for r in data["requests"]}
    rows = []
    for imp in data["impressions"]:
        if not start <= imp["t"] < end or imp["received"] > cutoff:
            continue
        target = label(imp, data["actions"], cutoff)
        if not target["mature"] or not target["observable"]:
            continue
        request = requests[imp["request"]]
        rows.append(dict(id=imp["id"], request=imp["request"], user=imp["user"],
                         item=imp["item"], t=imp["t"], **target,
                         **feature_row(data, request, imp["item"])))
    return rows


def fit_scaler(rows, name="user_finishes"):
    if not rows:
        raise ValueError("Пустое обучение")
    values = [r[name] for r in rows]
    mean = math.fsum(values)/len(values)
    variance = math.fsum((x-mean)**2 for x in values)/len(values)
    return dict(name=name, mean=mean, scale=math.sqrt(variance) or 1.0)


def transform(row, state):
    return (row[state["name"]]-state["mean"])/state["scale"]


def vocabulary(rows):
    return {item: i+1 for i, item in enumerate(sorted({r["item"] for r in rows}))}


def temporal_target_encoding(rows, query, strength=2, prior=.5):
    if strength <= 0 or not 0 <= prior <= 1:
        raise ValueError("Неверное сглаживание")
    # Уже вычисленные зрелые метки допустимы лишь после их ready_at.
    past = [r for r in rows if r["item"] == query["item"]
            and r["t"] < query["t"] and r["ready_at"] <= query["t"]]
    return (sum(r["y"] for r in past)+strength*prior)/(len(past)+strength)


def fit_item_rate(rows, strength=2):
    if not rows or strength <= 0:
        raise ValueError("Нужно непустое обучение и положительное сглаживание")
    prior = sum(r["y"] for r in rows)/len(rows)
    stats = {}
    for r in rows:
        n, s = stats.get(r["item"], (0, 0))
        stats[r["item"]] = (n+1, s+r["y"])
    return dict(prior=prior, strength=strength, stats=stats)


def predict_rate(model, item):
    n, s = model["stats"].get(item, (0, 0))
    return (s+model["strength"]*model["prior"])/(n+model["strength"])


def brier(rows, model):
    if not rows:
        raise ValueError("Пустая проверка")
    return math.fsum((r["y"]-predict_rate(model, r["item"]))**2 for r in rows)/len(rows)


def fold(data, origin, width=30, lookback=None, score_cutoff=None):
    if width <= 0 or (lookback is not None and lookback <= 0):
        raise ValueError("Неверная длительность")
    if score_cutoff is None:
        score_cutoff = origin+width+9
    train = table(data, 0 if lookback is None else origin-lookback, origin, origin)
    test = table(data, origin, origin+width, score_cutoff)
    expected = [i for i in data["impressions"] if origin <= i["t"] < origin+width
                and i["observable"]]
    if len(test) != len(expected):
        raise ValueError("Проверочная когорта ещё не полностью наблюдается")
    model = fit_item_rate(train)
    scaler = fit_scaler(train)
    vocab = vocabulary(train)
    return dict(origin=origin, score_cutoff=score_cutoff, train=train, test=test,
                model=model, scaler=scaler, vocabulary=vocab,
                brier=brier(test, model),
                cold_rows=sum(r["item"] not in vocab for r in test))

table сначала отбирает временную когорту и полное зрелое наблюдение, затем получает исходные признаки для времени каждого запроса. fold строит train на снимке обучения и проверку на более позднем снимке; отказывается считать неполную тестовую когорту. fit_scaler и vocabulary используют только train.

fit_item_rate — намеренно простой baseline: сглаженная доля положительных исходов по объекту с обучающим prior. Он нужен для проверки всего пути данных, а не как сильная рекомендательная модель. Для нового объекта возвращается prior. В прогнозе используются только ID объекта и уже обученные статистики; остальные raw-признаки сохраняются и проверяются, но не включены в эту учебную модель.

brier вычисляет среднюю квадратичную ошибку вероятности n−1∑(y−p^)2n^{-1}\sum(y-\widehat p)^2n−1∑(y−p​)2. Это уже знакомая квадратичная потеря для бинарной цели. Полный анализ вероятностных метрик и калибровки последует в части 7.

Где заканчивается ответственность Pipeline​

Официальная документация scikit-learn рекомендует обучать преобразования на train и использовать Pipeline для согласованного fit/transform. Pipeline не проверит сам, что сырые признаки были доступны в момент решения, что каталог исторический и что метки созрели: эти условия возникают до передачи массивов в estimator.

Обученные представления объектов, графовая структура и текстовые embeddings подчиняются той же логике происхождения. Если их обучение использовало будущие взаимодействия, замораживание файла embeddings после этого не возвращает временную корректность. Для внешней предобученной модели фиксируют версию, доступные источники и допустимость использования в выбранном сценарии.

Упражнение · Готовность target encoding

Есть две строки A: первая в 0 с ready_at=9, меткой 1; вторая в 8 с ready_at=17, меткой 0. При α=2\alpha=2α=2, p0=1/2p_0=1/2p0​=1/2 найдите кодировку для запроса в 8, 9 и 17.

Разбор

В 8 ни одна метка не готова, кодировка 1/21/21/2. В 9 доступна первая: (1+1)/(1+2)=2/3(1+1)/(1+2)=2/3(1+1)/(1+2)=2/3. В 17 доступны обе: (1+1)/(2+2)=1/2(1+1)/(2+2)=1/2(1+1)/(2+2)=1/2. Раннее существование строки в 8 не означает готовности её нулевого исхода.

Упражнение · Словарь из будущего

У модели есть отдельный индекс для объекта, который впервые появится через неделю, потому что словарь построили по всей таблице. Достаточно ли не использовать его будущие метки, чтобы назвать pipeline историческим?

Разбор

Нет без дополнительного контракта. Само знание будущего ID и способ подготовки представления уже происходят из будущего источника. Нужно либо строить train-словарь и fallback, либо явно определить задачу с заранее известным каталогом и обосновать эту доступность.
