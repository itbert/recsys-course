Сессии и доступный префикс

Сессия — правило группировки​

Близкие действия часто объединяют в сессии. Это полезный способ задать последовательность, но границы зависят от наблюдаемого журнала и выбранного порога. Таймаут не доказывает, что пользователь закончил задачу; отсутствие событий может быть вызвано неполной регистрацией или работой на другом устройстве.

Определение · Сессии по разрыву#

Для одного аккаунта упорядочим времена запросов t1≤⋯≤tnt_1\le\cdots\le t_nt1​≤⋯≤tn​. При пороге Δ≥0\Delta\ge0Δ≥0 положим b1=1b_1=1b1​=1 и bj=1{tj−tj−1>Δ}b_j=\mathbf1\{t_j-t_{j-1}>\Delta\}bj​=1{tj​−tj−1​>Δ} для j>1j>1j>1. Номер сессии sj=∑k=1jbks_j=\sum_{k=1}^j b_ksj​=∑k=1j​bk​. Равенство разрыва порогу продолжает сессию.

Для времён 0,10,22,35,400,10,22,35,400,10,22,35,40 при Δ=12\Delta=12Δ=12 номера равны 1,1,1,2,21,1,1,2,21,1,1,2,2. Разрыв 22−10=1222-10=1222−10=12 ещё допустим; 35−22=1335-22=1335−22=13 открывает новую группу. Общее время сессии может существенно превышать Δ\DeltaΔ: ограничены соседние промежутки, а не расстояние от первого события.

Что известно в текущем запросе​

В момент запроса в 10 можно использовать начало 0, возраст 10 и число уже полученных запросов 2, включая текущий. Длина всей первой сессии 3 станет известна только позднее; время её конца тоже недоступно. Признак «до конца сессии осталось 12 минут» является использованием будущего ответа о поведении.

Лемма · Добавление будущего к упорядоченному префиксу#

Если новые записи имеют времена строго позже всех записей префикса и не меняют уже известные записи, номера сессий существующего префикса по правилу разрыва сохраняются. Итоговая длина последней сессии может увеличиться.

Доказательство

Для каждой старой записи её предшественник и соседний разрыв остаются прежними. Поэтому сохраняются все bjb_jbj​ и их префиксные суммы. Новая запись может продолжить последнюю сессию, увеличив её итоговый размер.

□

Условие существенно. Поздняя доставка события с временем 11 между 0 и 22 может объединить ранее разделённые группы при пороге 12. Ретроспективная sessionization по окончательному журналу тогда отличается от доступной онлайн-картины. Для признаков нужно реконструировать именно доступный префикс или хранить выдававшееся состояние.

SQL по известному снимку​

Следующий запрос выполняется над таблицей r(id,user,t), предварительно отфильтрованной по доступности. Два этапа нужны потому, что нельзя непосредственно вложить одну оконную функцию в другую на том же уровне SELECT.

WITH gaps AS (
  SELECT *, LAG(t) OVER (
    PARTITION BY user ORDER BY t,id
  ) AS prev
  FROM r
), flags AS (
  SELECT *, CASE WHEN prev IS NULL OR t-prev>12
                 THEN 1 ELSE 0 END AS b
  FROM gaps
)
SELECT id,user,
  SUM(b) OVER (
    PARTITION BY user ORDER BY t,id
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS session_number
FROM flags;

PARTITION BY отделяет аккаунты; LAG получает предшественника; сумма создаёт номер. id задаёт воспроизводимое разрешение совпавших времён, но не доказывает реальный порядок решений. В сквозном журнале времена запросов различны. В реальном потоке нужен зарегистрированный порядок или консервативное правило для совпадений.

Прямая Python-реализация session_ids будет приведена вместе с признаками. Она сортирует NNN запросов за O(Nlog⁡N)O(N\log N)O(NlogN), затем делает линейный проход; память O(N)O(N)O(N) с сохранением результата. Повторный расчёт для каждого запроса намеренно прост, но не масштабируется как потоковое обновление.

Порог и постановка​

Порог задают из прикладного смысла, наблюдаемых разрывов и проверяемой гипотезы, а не из универсальной константы. Варьирование порога меняет распределение длин, долю одиночных сессий и состав обучающих переходов. Сравнение порогов по итоговому тесту превращает этот тест в этап разработки.

Сессия может быть единицей grouping при разбиении, единицей sequence-модели или просто источником признаков. Эти роли необходимо назвать отдельно. Если модель предназначена для продолжения текущей сессии, наличие её прошлого в истории допустимо; если проверяется обобщение на новые независимые сессии, протокол должен исключить их пересечение.

Упражнение · Граничный разрыв

При временах 0,12,240,12,240,12,24 и Δ=12\Delta=12Δ=12 сколько сессий? Как изменится ответ при правиле разрыва ≥Δ\ge\Delta≥Δ?

Разбор

В принятом правиле одна сессия. При ≥\ge≥ получатся три. Неуказанное равенство меняет даже детерминированный результат; его нужно фиксировать в коде и тестах.

Упражнение · Поздний мост

В момент 30 известны запросы 0 и 22. В 31 доставили запрос с event time 11. При Δ=12\Delta=12Δ=12 как различаются известная в 30 и поздняя реконструкция?

Разбор

Без 11 разрыв 22 создаёт две сессии. С записью 11 оба разрыва равны 11, получается одна. Нельзя подставлять позднюю группировку в прошлый онлайн-признак без явного изменения задачи.
