Новые пользователи, каталог и serving факторов

Пользовательские факторы при замороженных объектах​

Пусть обучение завершено, QQQ и объектные смещения опубликованы. Если новый пользователь уже оценил несколько объектов, можно решить его регуляризованную локальную систему как в ALS. Это fold-in: не трогаем остальные строки и столбцы. Для WALS с первыми неявными событиями используем ту же опубликованную матрицу Q⊤QQ^\top QQ⊤Q и поправки к ней. Размер блока — число факторов. Можно вычислять его при обновлении профиля, а затем кэшировать до следующего события.

При пустой истории и симметричном нулевом приоре решение пользовательского блока нулевое. Для рейтинга остаётся μ+ci\mu+c_iμ+ci​, для WALS все базовые произведения равны нулю. У BPR в нашей лаборатории используется общий резерв популярности для холодного пользователя. На уровне продукта можно опереться на контент, контекст или опрос интересов. Для нового объекта вектор может прийти из отдельной контентной модели после проверки, что его пространство согласовано с пользовательскими факторами.

Из скалярного произведения в список​

При фиксированном пользователе точный поиск оценивает pu⊤qi+cip_u^\top q_i+c_ipu⊤​qi​+ci​ по всему допустимому каталогу. Слагаемые μ+bu\mu+b_uμ+bu​ одинаковы для объекта и сокращаются в ранжировании. Если поиск реализуется как максимизация скалярного произведения, объектные смещения можно хранить в дополнительной координате.

Лемма · Дополнительная координата для смещения#

Для p~u=(pu,1)\widetilde p_u=(p_u,1)p​u​=(pu​,1) и q~i=(qi,ci)\widetilde q_i=(q_i,c_i)q​i​=(qi​,ci​) произведение p~u⊤q~i=pu⊤qi+ci\widetilde p_u^\top\widetilde q_i=p_u^\top q_i+c_ip​u⊤​q​i​=pu⊤​qi​+ci​. Top-KKK по этим значениям совпадает с рейтингом, если используется то же правило разрешения равенств.

Доказательство

Последняя координата даёт 1⋅ci1\cdot c_i1⋅ci​. Остальные совпадают с исходным произведением. Добавление пользовательской константы не меняет порядок.

□

Косинусная нормировка векторов меняет правило, потому что делит score на разные нормы объекта. Подмена целевого типа расстояния в индексе способна изменить кандидатов до ranking. Приближённые индексы изучим в части 14. В лаборатории используется полный точный проход по допустимым ID и резерв для известных с нулевой поддержкой или новых ID.

Версия пространства и контракт данных​

Факторы двух запусков могут кодировать одинаковые прогнозы в повернутых координатах. Поэтому нельзя без проверки соединять PPP одной версии и QQQ другой. При публикации согласуют реестр ID, обе матрицы, смещения, предобработку истории и индекс. Обновление с частичной загрузкой версии может дать корректные по форме массивы и ошибочные рекомендации.

Офлайн-срез содержит одни и те же ограничения каталога для всех моделей. Сравнивают доли попаданий в cold-сегменты и измеряют, сколько новых объектов действительно получило слоты. Нулевой фактор нового объекта плохо сочетается с общим числовым ранжированием: ноль может оказаться выше отрицательных scores известных объектов. В обучающем примере сначала идут известные пары с факторным score, затем допустимые объекты из резерва. Выбранное правило видно в коде и его влияние измеряется отдельно.

Упражнение · Старые и новые факторы

Один запуск сохранил p=1,q=2p=1,q=2p=1,q=2, другой эквивалентный запуск сохранил p=−1,q=−2p=-1,q=-2p=−1,q=−2. Что получится, если оставить первый фактор пользователя и взять второй фактор объекта?

Разбор

Любая согласованная версия даёт 2. Смешивание версий даёт −2. Даже совершенно одинаковое качество изолированных версий не гарантирует совместимость их факторов.

Упражнение · Скалярный поиск и косинус

Пользователь имеет вектор (1,0)(1,0)(1,0). У A вектор (3,4)(3,4)(3,4), у B вектор (2,0)(2,0)(2,0). Кто выше по произведению и кто выше по косинусу?

Разбор

Произведение равно 3 для A и 2 для B. Косинус равен 3/53/53/5 для A и 1 для B. Выбор метрики поиска определяет победителя.
