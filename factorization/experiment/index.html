Воспроизводимое сравнение факторизаций

Как устроен опыт​

Синтетический генератор задаёт пользователям и объектам векторы размерности 3. У рейтинга скрытая основа равна 3 плюс два смещения и скалярное произведение, умноженное на коэффициент. Добавляется гауссовский шум. Ранние неявные события выбираются с весом, зависящим от той же скрытой геометрии и объектной популярности. Эти параметры знает только генератор. Обучаемые модели получают события, рейтинги или ID кандидатов.

Срез T=100T=100T=100 отбрасывает записи, которые произошли или стали доступны после нужной границы. Истории SVD++ сложены из ранних неявных событий, доступных ещё до первых обучающих рейтингов. На явной задаче 2128 обучающих оценок от 112 пользователей, 560 тестовых оценок после TTT. Тестовые пары отсутствуют в рейтинговом обучении. Каждая строка теста получает один и тот же вес. Поправка из главы о времени проверяется отдельным ручным примером и тестами.

RMSE базовой модели около 0,654. Две реализации факторизации достигают около 0,294–0,296, SVD++ — 0,281. Генератор включает низкоранговое взаимодействие и общую причину для событий и рейтингов. Поэтому этот опыт показывает, как правильная форма носителя сигнала помогает прогнозу. Он не измеряет эффективность модели на наблюдениях реальной шкалы оценок.

Неявная задача​

Из 2016 доступных событий строим обучающие профили. В тесте 136 запросов, в том числе 24 без истории. В 44 объектах каталога четыре холодных, появившихся в TTT. Область исключает ранее увиденные объекты. Отложенные степени 2 и 1 назначаются двум объектам из одной и той же допустимой области для всех методов, остальные получают 0 по контракту генератора.

BPR даёт NDCG@5 около 0,189 против 0,137 у item-kNN. У холодных пользователей четыре правила совпадают по выбранному fallback. Ни один холодный объект не попадает в пять позиций. Результат указывает на ограничение общего serving-протокола, а не на измеренное отсутствие интереса к этим объектам. Все гиперпараметры заданы в коде до расчёта. Сравнение не подбирает их по итоговой когорте.

BPR сохраняет среднюю логистическую потерю на тройках, рассчитанную в моменты отдельных шагов. Это диагностическая онлайн-величина обучения. Она не обязана убывать при новой выборке и не сравнивается численно с полной функцией WALS.

Маленький байесовский пример​

У пары без оценки условно на фиксированных гиперпараметрах эмпирическое среднее латентного произведения равно 0.388, стандартное отклонение 1.070. Квантили одной учебной цепочки относятся к скрытому score. Для нового рейтинга к реализации score ещё прибавляются базовые смещения и шум наблюдения. Результат позволяет увидеть разницу между одним точечным прогнозом и набором реализаций.

Запустить самостоятельно​

experiment.py
"""Временное сравнение на двух синтетических задачах с общей геометрией."""
from collections import defaultdict
import hashlib
import json
import math
from pathlib import Path
import platform

import numpy as np

import associations
import baselines
import prediction
import ranking as ranking_metrics_module
import ratings as ratings_baseline_module
from associations import item_graph, item_scores, profiles
from baselines import Event, popularity, recommend, snapshot
from explicit import fit_als, fit_sgd
from implicit import event_counts, fit_wals
from pairwise import fit_bpr
from prediction import rating_errors
from probability import gibbs_predictions
from ranking import ranking_metrics
from ratings import baseline, fit_biases

USERS, WARM_USERS = 136, 112
ITEMS, OLD_ITEMS = 44, 40
ORIGIN, K, SEED = 100, 5, 9026
SGD = dict(factors=4, epochs=35, step=.025, regularization=.6, seed=9)
ALS = dict(factors=4, sweeps=18, regularization=.6, seed=9)
WALS = dict(factors=6, sweeps=14, alpha=8, regularization=1, seed=12)
BPR = dict(factors=6, epochs=16, updates=3000, step=.035, regularization=.025, seed=18)
GIBBS = dict(factors=2, burn=200, draws=800, noise_precision=4, prior_precision=1, seed=11)


def fixture():
    rng = np.random.default_rng(SEED)
    user = rng.normal(size=(USERS, 3))
    item = rng.normal(size=(ITEMS, 3))
    affinity = user @ item.T / math.sqrt(3)
    observed_popularity = rng.normal(0, .35, ITEMS)
    user_bias = rng.normal(0, .4, USERS)
    item_bias = rng.normal(0, .3, ITEMS)
    events = []
    for u in range(WARM_USERS):
        probabilities = np.exp(affinity[u, :OLD_ITEMS] + observed_popularity[:OLD_ITEMS])
        probabilities /= probabilities.sum()
        choices = rng.choice(OLD_ITEMS, size=18, p=probabilities)
        for day, i in enumerate(choices, 30):
            events.append(Event(u, int(i), day, day + 2))
    events += [Event(0, 0, 62, 102), Event(0, 40, 101, 102)]
    histories = profiles(snapshot(events, ORIGIN))

    rows, rating_test = [], []
    for u in range(WARM_USERS):
        choices = rng.permutation(OLD_ITEMS)[:24]
        for pos, i in enumerate(choices):
            r = 3 + user_bias[u] + item_bias[i] + .6 * affinity[u, i] + rng.normal(0, .22)
            t = 72 + pos if pos < 19 else 101 + pos
            rows.append((u, int(i), t, t + 1, float(r)))
    for u, i, t, available, r in rows:
        if t >= ORIGIN and available <= 130:
            rating_test.append((u, i, r))
    rating_train = [(u, i, r) for u, i, t, a, r in rows if t < ORIGIN and a <= ORIGIN]

    requests = []
    for u in range(USERS):
        candidates = [i for i in range(ITEMS) if i not in histories.get(u, ())]
        # Новые объекты доступны с ORIGIN, раньше их в каталоге не было.
        probabilities = np.exp(affinity[u, candidates] + observed_popularity[candidates])
        probabilities /= probabilities.sum()
        chosen = rng.choice(candidates, size=2, replace=False, p=probabilities)
        grades = {i: int(i == chosen[0]) * 2 + int(i == chosen[1]) for i in candidates}
        requests.append((u, ORIGIN + 1, candidates, grades))
    return events, rows, rating_train, rating_test, requests


def rank_factor_scores(candidates, scores, popular):
    def key(i):
        if i in scores:
            return 0, -scores[i], -popular[i], i
        return 1, 0, -popular[i], i

    return sorted(candidates, key=key)[:K]


def evaluate_ranking(events, requests):
    observed = snapshot(events, ORIGIN)
    history = profiles(observed)
    popular = popularity(observed)
    graph = item_graph(history.values(), limit=20, min_count=2, shrink=4)
    counts = event_counts(observed)
    p, q, wals_losses = fit_wals(counts, USERS, OLD_ITEMS, **WALS)
    x, y, b, bpr_losses = fit_bpr(history, range(OLD_ITEMS), USERS, OLD_ITEMS, **BPR)

    results = defaultdict(list)
    for u, _, candidates, grades in requests:
        seen = history.get(u, ())
        eligible_warm = [i for i in candidates if i in popular]
        wals = {i: float(p[u] @ q[i]) for i in eligible_warm} if seen else {}
        bpr = {i: float(b[i] + x[u] @ y[i]) for i in eligible_warm} if seen else {}
        orders = {
            "popularity": recommend(candidates, popular, popular, K),
            "item_knn": recommend(candidates, item_scores(seen, graph), popular, K),
            "wals": rank_factor_scores(candidates, wals, popular),
            "bpr": rank_factor_scores(candidates, bpr, popular),
        }
        for name, order in orders.items():
            m = ranking_metrics(order, grades, K)
            results[name].append((bool(seen), m["ndcg"], m["recall"], sum(i >= OLD_ITEMS for i in order)))

    ranking = {}
    for name, values in results.items():
        ranking[name] = {
            "ndcg": math.fsum(v for _, v, _, _ in values) / len(values),
            "recall": math.fsum(r for _, _, r, _ in values) / len(values),
            "warm_ndcg": math.fsum(v for warm, v, _, _ in values if warm) / WARM_USERS,
            "cold_ndcg": math.fsum(v for warm, v, _, _ in values if not warm) / (USERS-WARM_USERS),
            "cold_slots": sum(n for _, _, _, n in values),
        }
    return ranking, wals_losses, bpr_losses


def evaluate_ratings(train, test, history):
    base = fit_biases({(u, i): r for u, i, r in train}, regularization=.6)
    sgd, sgd_losses = fit_sgd(train, USERS, ITEMS, **SGD)
    als, als_losses = fit_als(train, USERS, ITEMS, **ALS)
    svdpp, svdpp_losses = fit_sgd(train, USERS, ITEMS, histories=history, **SGD)
    models = {"bias": lambda u, i: baseline(base, u, i), "sgd": sgd.predict,
              "als": als.predict, "svdpp": svdpp.predict}
    results = {name: rating_errors([(r, predict(u, i)) for u, i, r in test])
               for name, predict in models.items()}
    return results, {"sgd": sgd_losses, "als": als_losses, "svdpp": svdpp_losses}


def bayesian_example():
    centered = [(0, 0, 1.), (0, 1, -.5), (1, 0, .8), (1, 1, -.6), (1, 2, 1.1)]
    samples = gibbs_predictions(centered, 2, 3, [(0, 2)], **GIBBS)[:, 0]
    return {"mean": float(samples.mean()), "std": float(samples.std(ddof=1)),
            "quantiles": np.quantile(samples, [.05, .95]).tolist()}


def run():
    events, rows, train, test, requests = fixture()
    observed = snapshot(events, ORIGIN)
    ranking, wals_losses, bpr_losses = evaluate_ranking(events, requests)
    ratings, rating_losses = evaluate_ratings(train, test, profiles(observed))
    sources = ("explicit.py", "probability.py", "implicit.py", "pairwise.py", "temporal.py", "experiment.py")
    root = Path(__file__).parent
    data = [[[e.user, e.item, e.t, e.available] for e in events], rows, requests]
    dependencies = [associations, baselines, prediction, ranking_metrics_module, ratings_baseline_module]
    return {
        "manifest": {
            "python": platform.python_version(), "numpy": np.__version__, "seed": SEED,
            "cutoff": ORIGIN, "rating_score_cutoff": 130, "k": K,
            "parameters": {"sgd_and_svdpp": SGD, "als": ALS, "wals": WALS, "bpr": BPR, "gibbs": GIBBS},
            "source_sha256": {name: hashlib.sha256((root / name).read_bytes()).hexdigest()
                              for name in sources},
            "dependency_sha256": {module.__name__: hashlib.sha256(Path(module.__file__).read_bytes()).hexdigest()
                                  for module in dependencies},
            "data_sha256": hashlib.sha256(json.dumps(data, sort_keys=True).encode()).hexdigest(),
        },
        "sizes": {"observed_events": len(observed), "warm_users": WARM_USERS, "cold_users": USERS-WARM_USERS,
                  "items": ITEMS, "ratings_train": len(train), "ratings_test": len(test)},
        "ranking": ranking, "ratings": ratings, "bayesian": bayesian_example(),
        "curves": {"wals": wals_losses, "bpr_online": bpr_losses, **rating_losses},
    }


if __name__ == "__main__":
    report = run()
    Path(__file__).with_name("report.json").write_text(
        json.dumps(report, ensure_ascii=False, indent=2, allow_nan=False) + "\n"
    )
    print(json.dumps({k: report[k] for k in ("sizes", "ratings", "ranking", "bayesian")}, indent=2))

Сохраните шесть файлов из части 9 рядом. Для повторения нужны также baselines.py, associations.py и ratings.py из части 8, prediction.py и ranking.py из части 7. При запуске из репозитория эти каталоги можно добавить в PYTHONPATH. В Python 3.13.3 с NumPy 2.5.5 команда python3 experiment.py сохраняет report.json с параметрами, метриками, кривыми и хешами. Возможны небольшие численные отличия между реализациями BLAS.

Упражнение · Разные победители

Если WALS выиграл бы по Recall@5, а BPR по NDCG@5, какое объяснение совместимо с определениями?

Разбор

WALS мог чаще находить хотя бы часть позитивов в пяти позициях, а BPR помещать наиболее релевантный позитив выше. Recall учитывает попадания, NDCG учитывает степень и позицию. Для выбора метрики нужно заранее определить цель.

Упражнение · Сравнение холодных объектов

В каталоге определены новые ID, но все стратегии ставят их ниже известных. Как проверить, может ли дополнительный источник улучшить рекомендации этих объектов?

Разбор

Зафиксировать доступность, срез и связанные метки. Добавить источник кандидатов, например контентное сходство, при известном лимите выдачи. Сравнить доли слотов, качество на холодных объектах и общие метрики с прежним резервом. Для вывода об эффекте на реальную аудиторию нужен онлайн-дизайн с допустимой экспозицией.

В части 10 будем учить линейные связи между объектами, сравнивать их с эвристической совместной встречаемостью и выводить закрытое решение EASE.
