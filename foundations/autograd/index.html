Autograd и проверка градиентов

Автоматическое дифференцирование вычисляет производные выполненной композиции операций. Оно не проверяет, что эта композиция соответствует целевой функции задачи. Поэтому сначала нужен формальный критерий, затем его реализация и независимые способы проверки.

Цепное правило и вычислительный граф​

В предыдущей главе зависимость имела вид w↦Xw↦ℓ↦F\vect{w}\mapsto\mat{X}\vect{w}\mapsto\ell\mapsto Fw↦Xw↦ℓ↦F. Обратный проход последовательно применяет цепное правило, начиная со скалярной потери. Для отображения z=Xw\vect{z}=\mat{X}\vect{w}z=Xw вклад обратного прохода равен XT(∂F/∂z)\mat{X}^{\mathsf T}(\partial F/\partial\vect{z})XT(∂F/∂z).

PyTorch autograd строит граф операций для тензоров, участвующих в дифференцировании. requires_grad=True включает вычисление производных относительно параметра. Для скалярного результата .backward() накапливает производные в .grad соответствующих leaf-тензоров.

Для нескалярного результата необходимо указать входной вектор обратного прохода; в текущей задаче потеря уже сведена к скаляру через среднее и штраф. Формы данных остаются (4, 2), (4,), (2,), как в ручном выводе.

Одна функция в двух реализациях​

В PyTorch используется binary_cross_entropy_with_logits с усреднением по элементам и добавлением λ∥w∥22/2\lambda\norm{\vect w}_2^2/2λ∥w∥22​/2. Это та же функция, что в NumPy. Использовать одновременно этот критерий и предварительную сигмоиду было бы другой композицией: функция ожидает логиты.

Все тензоры примера находятся на CPU и имеют float64. torch.tensor создаёт отдельный тензор из NumPy-данных. torch.nn.Parameter обозначает обучаемый параметр; экземпляр оптимизатора получает именно его. Смена устройства и типа должна быть согласована между входом и параметрами, а не оставлена неявной.

autograd_demo.py
"""Сверка ручного градиента, конечных разностей и PyTorch на CPU."""
import numpy as np
import torch
import torch.nn.functional as functional
from optimization import loss_and_gradient, problem, train


def torch_loss(weights, features, targets, l2=0.2):
    logits = features @ weights
    return functional.binary_cross_entropy_with_logits(logits, targets) + l2 / 2 * (weights @ weights)


def finite_difference(weights, features, targets, epsilon=1e-6):
    result = np.zeros_like(weights)
    for index in range(len(weights)):
        direction = np.zeros_like(weights)
        direction[index] = epsilon
        above = loss_and_gradient(weights + direction, features, targets)[0]
        below = loss_and_gradient(weights - direction, features, targets)[0]
        result[index] = (above - below) / (2 * epsilon)
    return result


def train_torch(features, targets, steps=200, rate=0.2):
    x = torch.tensor(features, dtype=torch.float64)
    y = torch.tensor(targets, dtype=torch.float64)
    weights = torch.nn.Parameter(torch.zeros(features.shape[1], dtype=torch.float64))
    optimizer = torch.optim.SGD([weights], lr=rate)
    for _ in range(steps):
        optimizer.zero_grad(set_to_none=True)
        loss = torch_loss(weights, x, y)
        loss.backward()
        optimizer.step()
    return weights.detach().cpu().numpy().copy()


if __name__ == "__main__":
    torch.set_num_threads(1)
    features, targets = problem()
    point = np.array([0.2, -0.4], dtype=np.float64)
    weights = torch.tensor(point, dtype=torch.float64, requires_grad=True)
    x = torch.tensor(features, dtype=torch.float64)
    y = torch.tensor(targets, dtype=torch.float64)
    torch_loss(weights, x, y).backward()
    manual = loss_and_gradient(point, features, targets)[1]
    print("manual:", np.round(manual, 6))
    print("finite difference:", np.round(finite_difference(point, features, targets), 6))
    print("autograd:", np.round(weights.grad.numpy(), 6))
    print("gradcheck:", torch.autograd.gradcheck(lambda w: torch_loss(w, x, y), (weights,)))
    numpy_weights, _ = train(features, targets)
    torch_weights = train_torch(features, targets)
    print("training agrees:", np.allclose(numpy_weights, torch_weights, atol=1e-10, rtol=1e-10))

Перед запуском требуются numerics.py и optimization.py, сохранённые из предыдущих глав в ту же папку. Внутри torch_loss отсутствует ручной градиент: производная получается по графу операций PyTorch.

Конечные разности​

Для координатного вектора ej\vect e_jej​ центральная разность определяется как

gjFD(w)=F(w+εej)−F(w−εej)2ε.g_j^{\mathrm{FD}}(\vect w)= \frac{F(\vect w+\varepsilon\vect e_j)-F(\vect w-\varepsilon\vect e_j)}{2\varepsilon}.gjFD​(w)=2εF(w+εej​)−F(w−εej​)​.

При достаточно гладкой функции с ограниченной третьей производной вдоль рассматриваемой координаты ошибка усечения имеет порядок O(ε2)O(\varepsilon^2)O(ε2). Это следует из разложения Тейлора двух значений и сокращения чётных членов. В машинной арифметике добавляется ошибка округления, усиливаемая делением на малое ε\varepsilonε. Поэтому уменьшение шага до минимально возможного не гарантирует более точную проверку.

Здесь используется ε=10−6\varepsilon=10^{-6}ε=10−6 и float64. В точке (0,2,−0,4)T(0{,}2,-0{,}4)^{\mathsf T}(0,2,−0,4)T три способа дают после округления градиент

(0,087494−0,700584).\begin{pmatrix}0{,}087494\\-0{,}700584\end{pmatrix}.(0,087494−0,700584​).

torch.autograd.gradcheck выполняет дополнительное численное сопоставление с autograd; его назначение описано в справке пакета. Совпадение в одной точке недостаточно для доказательства корректности всей программы. Проверяются несколько точек, формы, знаки и крайние случаи; аналитический вывод остаётся самостоятельной проверкой.

Накопление градиентов​

На каждом шаге обучения код выполняет четыре разных действия:

  1. optimizer.zero_grad(set_to_none=True) сбрасывает прошлые градиенты.
  2. Вычисляется новая скалярная потеря и новый граф.
  3. loss.backward() вычисляет и накапливает текущие производные.
  4. optimizer.step() изменяет параметры по правилу SGD.

Без первого действия производные разных проходов могут суммироваться. Например, для f(w)=w2f(w)=w^2f(w)=w2 при w=2w=2w=2 первый обратный проход даёт 4. Повторное вычисление новой функции и новый .backward() без очистки дают накопленное значение 8. Такое накопление иногда задаётся намеренно, но оно должно соответствовать нормировке общей потери.

Повторный обратный проход через тот же граф и построение нового графа — разные операции. Сохранённые промежуточные значения обычно освобождаются после обратного прохода; возможность повторного использования требует явных решений о хранении графа и памяти.

Отделение результата и режим оценки​

detach() исключает дальнейшее участие результата в текущем графе. .cpu() переносит его в память CPU при необходимости; .numpy() преобразует поддерживаемый CPU-тензор в массив, который может разделять с ним память. Завершающий .copy() в примере создаёт независимый буфер результата.

no_grad() управляет записью графа, а model.eval() изменяет поведение некоторых модулей, например dropout и batch normalization. Эти действия не заменяют друг друга. В данном примере таких модулей нет, поэтому различие не влияет на вычисленные числа, но становится существенным для последующих нейронных моделей.

Сопоставление обучения​

Обе реализации используют нулевую инициализацию, одинаковые 200 шагов, шаг 0,2, коэффициент 0,2 и усреднение потерь. На проверенной конфигурации конечные параметры совпадают в допусках atol=rtol=1e-10.

В точном полном спуске траектория определяется функцией и шагом. При сравнении реализаций сначала выравниваются эти условия, а затем проверяется численное согласие. Сравнение разных reduction, штрафов или правил очистки градиентов не является проверкой одного алгоритма.

Упражнения​

Упражнение · Потеря связи с параметром#

Что изменится, если перед вычислением потери заменить weights на weights.detach()? Может ли autograd восстановить намерение обучать исходный параметр?

Разбор

Связь вычисляемой потери с исходным параметром будет разорвана. Если других входов, требующих градиент, нет, обратный проход для такой потери завершится ошибкой. Намерение не восстанавливается автоматически: дифференцируется фактический граф.

Упражнение · Масштаб накопления#

Два одинаковых полных батча обработаны без обновления параметров и без очистки градиента между проходами. Что нужно учесть, если целью было среднее по объединённому набору, а каждый проход уже усреднил свой батч одинакового размера?

Решение

Сумма двух средних даёт градиент, вдвое больший градиента среднего по объединённому набору. Каждый вклад можно умножить на 1/2 либо нормировать итоговую сумму. При неравных размерах батчей веса должны учитывать их размеры.
