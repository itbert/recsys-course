Разреженные данные и маски наблюдений

Рекомендательная таблица взаимодействий часто содержит малую долю всех пар «пользователь — объект». Разреженное хранение сокращает затраты, но не определяет смысл отсутствующих записей. Числовой ноль и отсутствие наблюдения относятся к разным уровням модели данных.

Значение и маска​

Пусть R∈Rnu×ni\mat{R}\in\R^{n_u\times n_i}R∈Rnu​×ni​ содержит значения выбранного агрегата. Отдельно зададим маску M∈{0,1}nu×ni\mat{M}\in\{0,1\}^{n_u\times n_i}M∈{0,1}nu​×ni​: Mui=1M_{ui}=1Mui​=1 означает наличие наблюдения по принятому правилу.

Например, Rui=0,Mui=1R_{ui}=0, M_{ui}=1Rui​=0,Mui​=1 может означать зарегистрированный показ без целевого действия. Сочетание Rui=0,Mui=0R_{ui}=0, M_{ui}=0Rui​=0,Mui​=0 используется как техническое заполнение неизвестного значения. Одна числовая матрица не различает эти случаи.

Для квадратичной ошибки по наблюдаемым парам при ∣Ω∣>0|\Omega|>0∣Ω∣>0 можно записать

L=1∣Ω∣∑(u,i)∈Ω(R^ui−Rui)2,Ω={(u,i):Mui=1}.\mathcal L=\frac1{|\Omega|}\sum_{(u,i)\in\Omega}(\widehat R_{ui}-R_{ui})^2, \qquad \Omega=\{(u,i):M_{ui}=1\}.L=∣Ω∣1​(u,i)∈Ω∑​(Rui​−Rui​)2,Ω={(u,i):Mui​=1}.

Замена Ω\OmegaΩ всеми парами задаёт другую функцию, в которой технические нули становятся целевыми значениями. Реализация не должна делать эту замену неявно.

COO: координаты и значения​

Формат COO хранит тройки «строка, столбец, значение». Он удобен для сборки из событий. Несколько событий могут иметь одинаковые координаты. В используемом SciPy sparse при переводе COO в CSR повторные координаты суммируются. Это правило библиотеки; его соответствие задаче необходимо установить отдельно.

Для числа событий сложение естественно. Для последнего рейтинга, максимальной оценки или булева признака оно может быть неверным. Выбор агрегата относится к построению данных, а не к универсальному свойству пользовательского предпочтения.

В примере координата (0,1)(0,1)(0,1) записана дважды со значениями 1 и 2; после суммирования получается 3. Координата (1,2)(1,2)(1,2) явно наблюдалась со значением 0. Маска фиксирует три уникальные координаты независимо от сумм значений.

CSR: доступ к строкам​

CSR хранит массив значений data, индексы столбцов indices и границы строк indptr. Данные строки uuu лежат между indptr[u] и indptr[u+1]. Формат удобен для прохода по объектам пользователя и умножения на плотный вектор.

Если zzz — число сохранённых записей, оценка объёма этих массивов равна

zbv+zbi+(nu+1)bi,z b_v+z b_i+(n_u+1)b_i,zbv​+zbi​+(nu​+1)bi​,

где bvb_vbv​ и bib_ibi​ — размеры значения и индекса в байтах. При nu=106n_u=10^6nu​=106, ni=105n_i=10^5ni​=105, z=108z=10^8z=108, bv=bi=4b_v=b_i=4bv​=bi​=4 получается около 0,8040{,}8040,804 GB вместо 400400400 GB плотных значений. Это расчёт только основных массивов одного представления; маска, временные буферы, копии и метаданные требуют дополнительной памяти. Возможность использовать четырёхбайтовые индексы проверяется по диапазону задачи.

Умножение CSR на плотный вектор требует прохода по сохранённым элементам и строкам, то есть O(z+nu)O(z+n_u)O(z+nu​) операций при обычной модели доступа к памяти. Результат при этом может быть плотным. Экономия хранения не гарантирует разреженности всех последующих результатов.

Явные нули​

.nnz означает число сохранённых записей, а не обязательно число ненулевых числовых значений. Явный ноль занимает место. eliminate_zeros() удаляет такие записи из выбранного sparse-массива, не сохраняя в нём сведения о том, что нулевая величина ранее наблюдалась.

Полный пример​

sparse_arrays.py
"""Разреженное хранение значений и независимая маска наблюдений."""
import numpy as np
from scipy.sparse import coo_array


def build_example():
    rows = np.array([0, 0, 1, 2])
    columns = np.array([1, 1, 2, 0])
    values = np.array([1.0, 2.0, 0.0, 1.0])
    shape = (3, 4)
    matrix = coo_array((values, (rows, columns)), shape=shape).tocsr()
    observed = coo_array(
        (np.ones(len(rows), dtype=np.int64), (rows, columns)), shape=shape
    ).tocsr()
    observed.data[:] = 1
    return matrix, observed


def main():
    matrix, observed = build_example()
    print("values:\n", matrix.toarray())
    print("observed:\n", observed.toarray())
    print("stored entries:", matrix.nnz)
    print("nonzero values:", matrix.count_nonzero())
    print("product:", matrix @ np.array([1.0, 2.0, 3.0, 4.0]))
    compact = matrix.copy()
    compact.eliminate_zeros()
    print("after eliminate_zeros:", compact.nnz)
    print("observed entries:", observed.nnz)


if __name__ == "__main__":
    main()

Массивы rows, columns, values задают четыре исходные записи. shape=(3, 4) фиксируется явно, включая строки и столбцы без событий. После .tocsr() остаются три сохранённые координаты. Число численно ненулевых значений — два.

Маска строится по наличию исходной координаты. После объединения повторов observed.data[:] = 1 переводит счётчики присутствия в индикаторы. Использование matrix != 0 потеряло бы наблюдаемый ноль и могло бы потерять взаимно сократившиеся значения.

Умножение на (1,2,3,4)T(1,2,3,4)^{\mathsf T}(1,2,3,4)T даёт (6,0,1)T(6,0,1)^{\mathsf T}(6,0,1)T. После удаления явных нулей compact.nnz равно 2, а observed.nnz остаётся 3: численная компактность и сведения о наблюдениях хранятся независимо.

toarray() используется только для печати маленького примера. Для большого каталога такое преобразование может уничтожить экономию памяти. Кроме того, sparse-форматы имеют собственные ограничения на индексацию и изменение структуры; перенос плотного алгоритма требует проверки операций.

Упражнения​

Упражнение · Отмена значений#

В COO записаны два значения 1 и −1 по одной координате. Каково агрегированное значение? Можно ли по нему определить, была ли координата наблюдена?

Решение

После суммирования значение равно нулю. Оно не различает наблюдённую пару и отсутствующую запись. Маска или исходная таблица событий должны хранить информацию о наличии наблюдения отдельно.

Упражнение · Знаменатель функции потерь#

В таблице 100 пар, наблюдалось 5; сумма квадратов ошибок на них равна 10. Чему равна средняя ошибка по наблюдениям? Эквивалентно ли деление этой суммы на 100 исходной функции?

Решение

Средняя ошибка по наблюдениям равна 2. Деление на 100 даёт 0,1 и меняет масштаб критерия. Если добавлен не пересчитанный штраф, изменяется и его относительный вес. При включении ошибок по техническим нулям меняется также сам числитель.
