Воспроизводимость и проверка эксперимента

Воспроизводимый эксперимент задаётся не только формулой и seed. Его определяют данные, преобразования, критерий, инициализация, алгоритм, версии программ и вычислительная среда. Кроме повторяемости вычислений необходимо проверять корректность постановки и протокола.

Что фиксирует seed​

Псевдослучайный генератор имеет состояние. При заданной реализации его выход определяется исходным состоянием и последовательностью вызовов. Если вставить дополнительный случайный вызов в общий поток, последующие значения могут измениться, несмотря на тот же начальный seed.

В примерах используются отдельные np.random.default_rng для данных и инициализации. Тогда изменение числа вызовов инициализации не должно менять построенные данные. Для параллельных экспериментов требуется также явно организовать независимые потоки; простое копирование состояния разным работникам создаёт одинаковые последовательности.

Раздельность состояний здесь означает отсутствие влияния вызовов одного генератора на состояние другого. Это программное свойство не является доказательством статистической независимости произвольных последовательностей, полученных из различных seed.

Соглашения генераторов и границы совместимости описаны в NumPy Generator и политике совместимости. Один seed без версии, алгоритма и порядка вызовов недостаточен для универсального обещания тождественных чисел.

Журнал запуска​

reproducibility.py
"""Раздельные состояния генераторов данных и инициализации; журнал запуска."""
import hashlib
import json
import platform
import numpy as np
from numerics import sigmoid
from optimization import loss_and_gradient


def experiment(data_seed=11, initialization_seed=23):
    data_rng = np.random.default_rng(data_seed)
    initialization_rng = np.random.default_rng(initialization_seed)
    features = data_rng.normal(size=(64, 2))
    targets = data_rng.binomial(1, sigmoid(features @ np.array([1.0, -1.0]))).astype(np.float64)
    weights = initialization_rng.normal(scale=0.1, size=2)
    digest = hashlib.sha256()
    for array in (features, targets):
        digest.update(str((array.shape, array.dtype.str)).encode())
        digest.update(array.tobytes())
    for _ in range(100):
        _, gradient = loss_and_gradient(weights, features, targets)
        weights -= 0.2 * gradient
    return {
        "python": platform.python_version(),
        "numpy": np.__version__,
        "data_seed": data_seed,
        "initialization_seed": initialization_seed,
        "data_hash": digest.hexdigest(),
        "steps": 100,
        "rate": 0.2,
        "l2": 0.2,
        "loss": loss_and_gradient(weights, features, targets)[0],
        "weights": weights.tolist(),
    }


if __name__ == "__main__":
    print(json.dumps(experiment(), ensure_ascii=False, indent=2))

Нужны файлы numerics.py и optimization.py. Генерируются 64 строки с двумя признаками; метки Бернулли получаются по заданной синтетической логистической модели. Это управляемый эксперимент, а не утверждение о реальных пользовательских откликах.

Два генератора получают отдельные seed. Начальные веса ненулевые и случайные; далее выполняются 100 полных градиентных шагов с тем же штрафом, что в предыдущих главах. Выход — JSON с версиями Python и NumPy, параметрами, хешем данных и итогом обучения.

Хеш включает форму, тип и байты двух массивов. Он фиксирует используемое представление; это не каноническое сравнение математически одинаковых данных в разных типах или порядке байтов. Изменение seed инициализации сохраняет хеш данных; изменение seed данных в проверяемом примере меняет его. Два повторных вызова с одинаковыми условиями дают одинаковый журнал в данной среде.

Версии и устройство вычислений​

Для всех примеров этой части зафиксированы прямые версии NumPy, SciPy, PyTorch и Matplotlib; полное состояние локального окружения дополнительно сохранено через pip freeze. Прямой список не фиксирует автоматически все транзитивные зависимости и системные библиотеки.

При переносе записываются ОС, архитектура, устройство, точность и параметры численных библиотек. В PyTorch установка seed, выбор детерминированных алгоритмов и настройка аппаратных библиотек — разные меры. Официальная заметка о воспроизводимости описывает их границы; повторение между разными версиями и платформами не гарантируется одной настройкой.

torch.set_num_threads(1) в проверяемом примере ограничивает число CPU-потоков конкретного процесса. Оно не доказывает побитовую воспроизводимость произвольной модели на всех устройствах. Все программы заканчивают работу; SQLite-соединение закрывается явно, графики сохраняются и закрываются без GUI, серверы для выполнения кода не требуются.

Допуски и независимые проверки​

Для чисел с плавающей точкой используется условие вида

∣a−b∣≤atol+rtol ∣b∣,|a-b|\le\mathrm{atol}+\mathrm{rtol}\,|b|,∣a−b∣≤atol+rtol∣b∣,

где bbb — выбранное опорное значение. Абсолютный допуск существенен около нуля, относительный — при изменении масштаба. Допуск выбирается по типу, алгоритму и цели проверки, а не расширяется до прохождения ошибочного результата.

В этой части сопоставляются разные основания расчёта: аналитическая производная, конечные разности и autograd; точные дроби и десятичная арифметика; явная матрица и sparse-операция. Такие проверки обнаруживают разные классы ошибок. Тест, который повторяет ту же формулу с теми же индексами, может повторить и исходную ошибку.

Для неединственных представлений проверяется инвариант. Например, в SVD можно сравнивать восстановленную матрицу и сингулярные значения, а не требовать совпадения знаков всех векторов. Для sparse-счётчиков сравниваются значения, маска и правило объединения повторов.

Вычислительная и статистическая корректность​

Повторение одного результата подтверждает лишь повторение данной процедуры. Детерминированная программа может использовать будущее, некорректный негативный sampling или неправильную целевую метку.

В обычном протоколе обучающая часть используется для подбора параметров, валидационная — для выбора вариантов процедуры, тестовая — для итоговой оценки после фиксации выбора. Рекомендательные временные разбиения и оценка по логам вводят дополнительные условия, которые будут разбираться в частях о данных и метриках.

Несколько seed позволяют изучить вариативность из-за указанного источника случайности. Они не создают независимых пользователей и не исправляют невалидное разбиение. Аналогично уменьшение обучающей потери не доказывает улучшение пользовательской ценности.

Проверочный список результата​

Перед интерпретацией эксперимента должны быть определены:

  • единица наблюдения, способ получения меток и состояние данных на момент решения;
  • формула критерия, нормировка, штрафы и алгоритм обновления;
  • формы, типы и устройства входов и параметров;
  • случайные потоки, версии, условия повторения и численные допуски;
  • протокол оценки и границы утверждений, которые поддерживают результаты.

Это описание экспериментального объекта, а не набор доказательств качества само по себе. Конкретные проверки следуют из конкретной постановки.

Упражнения​

Упражнение · Раздельные состояния генераторов#

В исходном коде измените только initialization_seed. Какие поля журнала должны остаться прежними по построению? Доказывает ли совпадение окончательных весов отсутствие влияния инициализации на промежуточную траекторию?

Разбор

Данные, их хеш, seed данных, версии и параметры алгоритма сохраняются. Инициализация и путь могут измениться. Совпадение конечных точек не доказывает совпадения траекторий: разные начальные состояния могут сходиться к одному минимуму.

Упражнение · Повторяемая ошибка#

Программа с фиксированным seed каждый раз показывает одинаковую метрику. В признаки включено число взаимодействий за месяц после тестового запроса. Какой вывод поддерживает повторение и какой — нет?

Разбор

Поддерживается повторяемость данной вычислительной процедуры. Корректность оценки прошлого решения не поддерживается: признаки содержат недоступные в тот момент сведения. Исправление требует изменения протокола данных, а не нового seed.
